## TL;DR

* **ping** quickly checks reachability and latency (RTT); `-c N` limits probes.
* **traceroute / tracert** reveal each hop via TTL; `*` means no ICMP reply.
* **tcpdump -r / tshark -r** read pcaps to verify flows: `arp` for L2 resolve, `bootp&#124;&#124;dhcp` for DORA, `icmp` for ping/traceroute.

## Gotchas — Networking Essentials (SAL1)

* **IPv6 fragmentation happens only at the sender.**
  Routers do **not** fragment IPv6 packets. The sender discovers the usable path MTU via **Path MTU Discovery (PMTUD)** driven by **`ICMPv6 Type 2 (Packet Too Big)`** and then fragments (or lowers MSS/MTU) itself. If you see drops only for large payloads, suspect PMTUD.

* **Don’t block essential ICMPv6.**
  Filtering `ICMPv6` (especially **Type 2: Packet Too Big**) causes **PMTUD collapse**—small packets work, large ones “black-hole.” Allow at least: Destination Unreachable, Packet Too Big, Time Exceeded, and Echo (Req/Reply).

* **Enable TCP MSS clamping on VPNs/tunnels.**
  Encapsulation (IPsec, GRE, WireGuard, PPPoE) reduces effective MTU. Without **MSS clamping** on the tunnel/edge, large TCP segments get dropped when PMTUD is blocked or slow, leading to stalls. Clamp MSS to MTU−overhead (e.g., common values: 1452, 1412, 1360—depends on your tunnel).

* **MTU mismatch symptoms = “small works, big breaks.”**
  Web loads hang mid-page, SSH feels fine, pings succeed but file transfers stall. Test with `ping -s <size>` (Linux) and adjust MTU/MSS or fix ICMPv6 filtering.

* **Traceroute variations can mislead.**
  Different OSes use UDP/ICMP/TCP probes. Some hops drop or rate-limit ICMP, showing `* * *` even though forwarding continues. Read the full path, not a single missing hop.

* **DHCP is L2-broadcast; it won’t cross routers unaided.**
  If clients on another subnet don’t get leases, you likely need a **DHCP relay/agent (ip helper)** on the gateway.

* **Private RFC1918 addresses are not Internet-routable.**
  Reaching the Internet from them requires **NAT** (or a proxy). NAT state exhaustion (≈65k ports per public IP) can throttle many concurrent flows.

* **IPv4 vs IPv6 TTL/Hop-Limit.**
  IPv4 uses **TTL**; IPv6 uses **Hop-Limit**. Low values or overzealous decrements create false “short paths” or premature expirations in traces.

* **DHCP** configures IP/mask, gateway, DNS automatically via **DORA**; clients begin from `0.0.0.0` to `255.255.255.255`. Example `tshark` shows lease of `192.168.66.133`. Q\&A: steps **4**; Discover dest **255.255.255.255**; source **0.0.0.0**. &#x20;
* **ARP** maps IP→MAC on local Ethernet/Wi-Fi; Request is broadcast to **ff\:ff\:ff\:ff\:ff\:ff**; Reply returns target MAC. Shown with `tshark` and `tcpdump`. Q\&A: destination MAC = **ff\:ff\:ff\:ff\:ff\:ff**. &#x20;
* **ICMP** diagnostics: `ping -c 4` reports min/avg/max/mdev; `traceroute` reveals hops via TTL and ICMP **Time Exceeded**; some hops don’t reply (`*`). Q\&A: echo (ping) request bytes **40**; field that must hit zero for traceroute = **TTL**.  &#x20;
* **Routing** terms: **OSPF**, **EIGRP** (Cisco proprietary), **BGP**, **RIP**. Q\&A: Cisco proprietary = **EIGRP**. &#x20;
* **NAT**: many private hosts share one public IP; router keeps (inside IP\:port)↔(outside IP\:port) mappings. Example shows public IP **212.3.4.5**; approximate concurrent TCP connections per public IP ≈ **65k**. &#x20;
