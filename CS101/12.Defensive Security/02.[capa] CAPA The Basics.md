# 41. SAL1 Note — CAPA: The Basics (Cheat Sheet)
tags: [defensive, malware-analysis, static-analysis, capa, mitre-attack, maec, mbc, namespaces]

> For authorized lab/CTF environments only.

---

## TL;DR
- **CAPA** identifies **capabilities** of binaries (PE/ELF/.NET/shellcode) via **rule-based static analysis**, mapping results to **MITRE ATT&CK, MAEC, and MBC** so you quickly grasp what a sample can do (e.g., HTTP comms, file I/O, persistence). :contentReference[oaicite:0]{index=0}  
- Core usage: `capa <file>`; add **`-v` / `-vv`** for detail, **`-j`** to JSON, then review with **CAPA Web Explorer** for fast triage. :contentReference[oaicite:1]{index=1}  
- Results are grouped by **Namespaces** (e.g., `anti-analysis/…`, `communication/http`, `host-interaction/file-system`). Think “what + where in behavior space.” :contentReference[oaicite:2]{index=2}

## Quick Start (Windows lab path from the room)
#powershell
# Go to the prepared folder
cd C:\Users\Administrator\Desktop\capa

# Basic run (static analysis)
capa.exe .\cryptbot.bin

# Help / parameters
capa -h

# Verbose / very verbose
capa.exe .\cryptbot.bin -v
capa.exe .\cryptbot.bin -vv

# JSON (machine-readable) + very verbose → file
capa.exe -j -vv .\cryptbot.bin > cryptbot_vv.json

# If using pre-generated outputs in the room
Get-Content .\cryptbot.txt
Get-Content .\cryptbot_vv.txt
````



---

## Reading the Output (What to look for)

* **General info**: hashes, OS, format, arch, analysis type, path. First sanity check. 
* **ATT&CK table**: maps tactics/techniques/sub-techniques (e.g., `Defense Evasion :: Obfuscated Files or Information [T1027]`). Use to align with detection/use-cases. 
* **MAEC**: high-level malware category (e.g., **launcher**, **downloader**)—quick behavior summary. 
* **MBC**: objectives/behaviors/methods (e.g., `DATA :: Encode Data :: Base64 [C0026.001]`). Great for analyst notes and hunting ideas. 
* **Capabilities + Namespaces**: granular findings (e.g., `reference Base64 string → data-manipulation/encoding/base64`, `schedule task via schtasks → persistence/scheduled-tasks`). 

---

## Practical Analyst Flow

1. **Run**: `capa.exe <sample> [-v|-vv]` to scope behaviors quickly.
2. **Export**: `-j` for JSON → load into **CAPA Web Explorer** (online or offline HTML) for filters/search. 
3. **Pivot**: From findings to ATT&CK/MBC → build detection/hardening items (e.g., PowerShell usage, scheduled tasks). 
4. **Report**: Summarize capabilities + mapped IDs; attach hashes and notable rules hit.

---

## CAPA Web Explorer (faster triage)

* Open **capa Web Explorer**, click **“Upload from local”**, select `cryptbot_vv.json`.
* Use the **Global Search Box** to filter capabilities, strings, IDs (e.g., search `vmware`, `schtasks`).

## Common Findings (Examples to recognize)

| Finding (Capability)                                         | Namespace                                     | What it implies                                     |
| ------------------------------------------------------------ | --------------------------------------------- | --------------------------------------------------- |
| `reference anti-VM strings`                                  | `anti-analysis/anti-vm/vm-detection`          | Sandbox/VM checks → likely **evasion**.             |
| `encode data using XOR` / `reference Base64 string`          | `data-manipulation/encoding/xor` / `…/base64` | **Encoding/obfuscation** of config or comms.        |
| `check HTTP status code`, `reference HTTP User-Agent string` | `communication/http/client`                   | **HTTP C2** or web activity.                        |
| `schedule task via schtasks`                                 | `persistence/scheduled-tasks`                 | **Persistence** mechanism on Windows.               |
| `create/read/write/delete file`                              | `host-interaction/file-system/*`              | File system interaction → staging, logs, payloads.  |

## Handy One-Liners (Windows)

```powershell
# Quick triage (console, human-readable)
capa.exe .\sample.bin -v

# Deep dive with structured output (for Explorer/JSON tools)
capa.exe -j -vv .\sample.bin > sample_vv.json

# Grep-like filtering in PowerShell (e.g., search ATT&CK IDs)
Select-String -Path .\cryptbot.txt -Pattern "T1497|T1027|C0026"
```

## Gotchas

* **Static ≠ full truth**: CAPA is static; some behaviors only appear dynamically (runtime-only code paths, decrypted strings). Pair with sandboxing when allowed. 
* **Verbose is slow**: `-vv` is powerful but time-consuming on constrained VMs; prefer pre-generated files or JSON+Explorer for navigation. 
* **Rule context matters**: A capability hit can be low-signal without corroboration (e.g., single string match). Validate across multiple hits and related namespaces. 
* **Namespace ≠ family**: Namespaces describe behavior domains, not attribution. Don’t over-interpret them as family IDs.
