# FlareVM Arsenal of Tools — Investigator’s Cheat Sheet

## TL;DR

* FlareVM is a Windows VM stacked with RE/DFIR tooling (Procmon, Process Explorer, HxD, CFF Explorer, PEStudio, FLOSS, Wireshark, etc.). Use it to do **static triage** (PEStudio, CFF Explorer, FLOSS/HxD) and **dynamic observation** (Process Explorer/Procmon/Wireshark) without touching the Internet. 
* Fast path:

  1. **PEStudio** → hashes, entropy, imports/blacklist, manifest.
  2. **CFF Explorer/HxD** → PE headers, MD5, DOS e_magic (“MZ”), suspicious bytes.
  3. **Run sample** (if permitted) → **Process Explorer** (parent/child, TCP/IP), **Procmon** (filtered I/O/registry), **Wireshark** (C2 hints).
  4. **FLOSS** → quick string harvest/deobfuscation (for non-.NET; .NET deobfuscation not covered). 

---

## Quick Map of Tools (what to use when)

* **PEStudio** – static triage (hashes, entropy, imports/blacklist, manifest). 
* **CFF Explorer** – PE structure, hash computation, DOS/NT headers. 
* **HxD** – raw bytes/headers; confirm magic (e.g., `4D 5A`). 
* **Process Explorer** – process tree, parent/child, **TCP/IP tab** for live connections. 
* **Procmon** – filter by process name to capture file/registry/network I/O sequences. 
* **Wireshark** – confirm protocol/targets (e.g., TLSv1.2 sessions). 
* **FLOSS** – extract static/stack/tight strings (note: limited for .NET). 

---

## Core Workflow (10–15 min)

1. **Static triage (no execution)**

   * **PEStudio** → Open sample → note `SHA256/MD5`, **entropy**, **imports** (use **Blacklist** view), **manifest**/requestedExecutionLevel.
   * **CFF Explorer** → Confirm **MD5**, DOS header **e_magic = 5A4D (“MZ”)**, file timestamps/sections.
   * **HxD** → sanity-check magic bytes and suspicious blobs. 
2. **Run & watch (if allowed in the lab)**

   * Launch sample → **Process Explorer**: confirm **parent/child**; open **Properties → TCP/IP** to see C2 host:port (e.g., `47.120.46.210:81`). 
   * **Procmon**: set filter `Process Name` **contains** `<part-of-name>` → Include → Apply; review filesystem/registry ops. 
   * **Wireshark**: capture and filter (e.g., `tcp.port == 81`, `tls`), confirm encrypted sessions. 
3. **Strings & hints**

   * **FLOSS** (PowerShell) to dump strings, configs, APIs (e.g., `RijndaelManaged`, `CreateDecryptor`, `CipherMode`).

## Common Tasks + Commands

### 1) Launch tools quickly (PowerShell)

```powershell
# Open folder with samples used in the room
Set-Location "C:\Users\Administrator\Desktop\Sample"

# Launch core tools
Start-Process "C:\Program Files\PEStudio\pestudio.exe"
Start-Process "C:\Program Files\Wireshark\Wireshark.exe"
Start-Process "C:\Program Files\Process Explorer\procexp.exe"
Start-Process "C:\Program Files\Process Monitor\Procmon.exe"
Start-Process "C:\Program Files\CFF Explorer\CFF Explorer.exe"
Start-Process "C:\Program Files\HxD\HxD.exe"
```

(Adjust paths if your image differs.) 

### 2) PEStudio — Static triage

* **What to look at:** `Hashes`, `Entropy` (e.g., ~7.999 indicates packing), `Imports` → **Blacklist** (crypto, process creation), `Manifest` → `requestedExecutionLevel = requireAdministrator`.
* **Why:** quickly score risk, detect obfuscation/packing, and privilege asks. 

### 3) CFF Explorer — PE details & hashes

* **Steps:** Open file → view **DOS Header** → `e_magic = 5A4D` → check **File MD5/SHA1** and sections.
* **Use cases:** confirm executable type, verify MD5 (e.g., of `possible_medusa.txt`), inspect timestamps. 

### 4) HxD — Verify magic & bytes

* **Steps:** Open file → verify first bytes `4D 5A` (“MZ”), scan for ASCII IOCs.
* **Why:** quick binary sanity check; identify embedded data. 

### 5) Process Explorer — Parent/child + TCP/IP

* **Steps:** Run sample → in Process Explorer, find process → **Properties → TCP/IP** → read **Remote Address** and **Remote Port** (e.g., `47.120.46.210:81`).
* **Why:** confirm live C2 endpoints, parent/child chain (often `explorer.exe` → `<sample>.exe`). 

### 6) Procmon — Focus on your process

* **Steps:** Open Procmon → **Filter (Ctrl+L)** → `Process Name` **contains** `<part>` → **Include → Add → Apply**.
* **Why:** shrink noise; see file/registry operations tied to the sample. 

### 7) Wireshark — Network evidence

* **Filters to try:**

  * `tls` (encrypted flows), `tcp.port == 81` (match Process Explorer finding), `ip.addr == x.x.x.x`.
* **Why:** cross-validate Process Explorer/Procmon findings at packet level. 

### 8) FLOSS — Strings & config harvest

```powershell
# From the Sample folder
.\FLOSS.exe .\cobaltstrike.exe            # prints to console
.\FLOSS.exe .\windows.exe > windows.txt   # save output to file
```

* **Notes:** Great for native binaries; for .NET samples, FLOSS warns that language-specific deobfuscation isn’t supported in this workflow.

## Investigation Playbooks (micro-recipes)

### A) “Is this packed/encrypted?”

1. **PEStudio** → Entropy near 8.0? Many suspicious imports?
2. **CFF Explorer/HxD** → Headers look minimal/altered?
3. **FLOSS** → Few/no strings decoded?
   → Treat as obfuscated; prepare for deeper sandboxing or specialized unpacking. 

### B) “Is there active C2?”

1. Run sample → **Process Explorer → TCP/IP**: read remote IP/port.
2. **Procmon** filter confirms network/registry behavior.
3. **Wireshark** filter `ip.addr == <remote>` or `tcp.port == <port>` confirms sessions (often TLSv1.2). 

### C) “What crypto/features does it use?”

* **PEStudio → Imports → Blacklist**: look for `RijndaelManaged`, `CipherMode`, `CreateDecryptor`, `CryptoStream`.
* **FLOSS** to surface related strings.

## Gotchas (read before you click)

* **FLOSS & .NET:** the module notes that .NET-specific string deobfuscation is **not** performed in this flow; don’t over-interpret thin results on managed binaries. Use .NET-aware tooling if needed. 
* **High entropy ≠ malware**: Packed/compressed legit apps also show high entropy; correlate with imports/behavior. 
* **Parent/child misreads:** If you start from a script/archiver, parent may be `explorer.exe`, a script host, or an office app. Always validate with **both** Process Explorer and Procmon. 
* **Encrypted traffic:** TLS in Wireshark doesn’t prove malice; confirm endpoints (IP/port), timing, and cross-tool evidence. 
* **Isolated VM only:** The lab includes malicious samples and no Internet. Keep analysis inside the VM.
