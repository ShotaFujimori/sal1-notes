# SAL1/windows\_powershell.md

tags: \[powershell, windows]

## TL;DR

* **Object‑oriented shell** — every cmdlet returns rich .NET objects instead of plain text, so you can manipulate properties & methods directly.
* **Verb‑Noun naming** keeps intent obvious (`Get-Content`, `Set-Location`, `Remove-Item`) and is easy to remember.
* **Discover fast** with `Get-Command` (enumerate) and `Get-Help -Examples` (see usage) for any task.
* **Pipelines pass objects**, so filtering (`Where-Object`), sorting (`Sort-Object`) and selecting (`Select-Object`) stay reliable—no fragile text‑parsing needed.
* **`Invoke-Command`** runs scripts or inline blocks on remote hosts, enabling one‑to‑many automation and red/blue‑team ops.
* Core triage cmdlets—`Get-Process`, `Get-Service`, `Get-NetTCPConnection`, `Get-FileHash`—give live visibility for incident response.

## Gotchas

* Default **Execution Policy** blocks unsigned scripts—set to *RemoteSigned* (or bypass per run) only when you understand the risk.
* Remote cmdlets need **WinRM/PSRemoting** enabled and network‑reachable ports (5985/5986).
* Paths with spaces require quotes: `Get-Content "C:\Program Files\log.txt"`.
* `Remove-Item -Recurse -Force` is unforgiving—double‑check the path before execution.
* Without `-Recurse`, `Get-ChildItem` won’t dive into sub‑folders; add it or use `-Depth` on PS 7+.
