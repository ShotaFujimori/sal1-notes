# 32. SAL1 — Defensive Security: SOC Fundamentals (Cheat Sheet)
tags: [defense, soc, siem, edr, incident-response, logging, monitoring, 5Ws]

> Use these commands only in authorized lab/enterprise environments.  
> This cheat sheet distills the “SOC Fundamentals” room: why SOC exists, the 3 pillars (People, Process, Technology), what SOC detects & how it responds, and a mini playbook for L1 analysts. :contentReference[oaicite:0]{index=0}

---

## TL;DR
- **SOC = Security Operations Center**: 24×7 team that **detects** and **responds** to threats across the org. Core aim: maintain **Detection & Response**. :contentReference[oaicite:1]{index=1}  
- **3 pillars**: **People** (roles & responsibilities), **Process** (alert triage → reporting → IR/forensics), **Technology** (SIEM, EDR, firewall, and more). :contentReference[oaicite:2]{index=2}  
- **Process backbone**: triage every alert with **5Ws** (What/When/Where/Who/Why), escalate with evidence, and assist IR. :contentReference[oaicite:3]{index=3}  
- **Technology** centralizes telemetry and automates detection/response (SIEM for correlation/alerts; EDR for endpoint visibility/containment; firewalls for network control). :contentReference[oaicite:4]{index=4}

## SOC at a Glance
**Detect**: vulnerabilities, unauthorized activity, policy violations, intrusions.  
**Respond**: minimize impact, support IR, root-cause analysis. :contentReference[oaicite:5]{index=5}

## People — Roles & “What They Do”
- **SOC Analyst L1** – First responder, **alert triage** & initial reporting. :contentReference[oaicite:6]{index=6}  
- **SOC Analyst L2** – Deepen investigations, correlate multiple data sources. :contentReference[oaicite:7]{index=7}  
- **SOC Analyst L3/Threat Hunter** – Proactive hunts, support **IR** (contain/eradicate/recover). :contentReference[oaicite:8]{index=8}  
- **Security Engineer** – Deploy & maintain security tooling (SIEM/EDR/etc.). :contentReference[oaicite:9]{index=9}  
- **Detection Engineer** – Build detection rules/logic. :contentReference[oaicite:10]{index=10}  
- **SOC Manager** – Process & stakeholder comms (CISO updates). :contentReference[oaicite:11]{index=11}

## Process — L1 Triage with the 5Ws
**Goal:** Decide severity & next actions fast; collect proof for escalation. :contentReference[oaicite:12]{index=12}

### Quick triage commands (copy/paste)
**Linux (auth & processes)**
```bash
# Failed logins / lateral movement hints
sudo grep -i "failed password" /var/log/auth.log | tail -n 50
last -i | head

# Suspicious processes / sockets
ps aux --sort=-%mem | head
sudo ss -tuna | sed -n '1,15p'

# New binaries recently written to exec paths
sudo find /usr/bin /usr/local/bin -type f -mmin -60 -exec ls -l {} \;
````

**Windows (PowerShell)**

```powershell
# Failed logons (4625) in last hour
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4625; StartTime=(Get-Date).AddHours(-1)} | Select TimeCreated,Message | ft -Auto

# Network sockets & owning processes
netstat -ano | findstr LISTEN
Get-Process | Sort-Object CPU -Descending | Select -First 10
```

**Network (pcap quick look)**

```bash
# Fast scan of noisy indicators (port scans, auth protocols)
sudo tcpdump -nni any "tcp[tcpflags] & (syn) != 0 or port 445 or port 3389" -c 200
```

**When ready, escalate**

* Summarize **5Ws**, attach logs/screenshots/pcaps, and **open ticket** to L2/IR.

## Detection Playbook Starters (what to look for)

### 1) Unauthorized Activity (Account Takeover)

* **Clues**: impossible travel, unusual User-Agent, odd hours. 
  **SIEM-ish query ideas (generic SPL/KQL style)**

```txt
# Failed → Success burst for one user
index=auth action IN ("failure","success")
| eval hour=strftime(_time,"%H")
| stats count by user,action,src_ip,hour
```

### 2) Policy Violations

* **Clues**: exfil via cloud drives, cleartext secrets, shadow IT apps. 
  **Endpoint grep (Linux)**

```bash
sudo grep -RniE 'api[_-]?key|secret|passwd|token' /home/* 2>/dev/null | head
```

### 3) Intrusions/Malware

* **Clues**: exploit traces in web logs; suspicious child processes. 
  **Web access error bursts**

```bash
sudo awk '$9 ~ /50[0-9]/ {print}' /var/log/nginx/access.log | tail -n 100
```

### 4) Vulnerability Exposure

* **Clues**: unpatched Windows fleet, old libs/frameworks. 
  **Linux kernel/package age snapshot**

```bash
uname -a
dpkg -l | awk '/^ii/ && ($3 ~ /-0|ubuntu|debian/){print $2,$3}' | head
```

## Response — First Moves

* **Contain**: isolate endpoint (EDR network containment), kill process, block IOC on firewall. 
* **Eradicate/Recover**: remove persistence, patch, restore from known-good, monitor closely. 
* **Report**: document actions, timeline, evidence; handoff to IR/forensics as needed. 

---

## Technology — Tools You’ll Touch

* **SIEM**: centralizes logs, correlation, alerting; now often with **UEBA** & threat intel. *Detect-only; response via other tools.* 
* **EDR**: endpoint telemetry + remote actions (quarantine/kill/hunt). 
* **Firewall**: north–south filtering; detect/block suspicious network flows. 
* **Others**: AV/EPP, IDS/IPS, XDR, SOAR, etc. (choose per risk & resources). 

### Quick tech commands

```bash
# Linux firewall snapshot
sudo iptables -S | sed -n '1,40p'
sudo ufw status verbose

# EDR-like triage (open-source endpoint tools vary by environment)
sudo lsof -i -nP | head
```

## Mini Lab Checklist (L1 Workflow)

1. **Open alert** → run **5Ws** triage; grab host/user/time/IPs.
2. **Validate** with host logs & quick net checks (snippets above).
3. **Decide severity** → **escalate** to L2/IR with artifacts.
4. **Assist containment** (EDR isolate, FW block), then monitor.
5. **Close alert** with findings & lessons learned (flag if provided).

## Gotchas (and Fast Fixes)

| Symptom                                  | Likely Cause                              | Quick Fix                                                                    |
| ---------------------------------------- | ----------------------------------------- | ---------------------------------------------------------------------------- |
| Alert fatigue / too many false positives | Noisy rules, missing allowlisting         | Tune detections, add context (asset/user risk), suppress known-good patterns |
| Can’t decide severity quickly            | Missing 5Ws data                          | Use the triage template; ask for logs from **both** client & server sides    |
| Gaps in visibility                       | Unenrolled endpoints, missing log sources | Verify SIEM/EDR coverage; backfill high-value assets first                   |
| “No incident found” after escalation     | Evidence insufficient                     | Always attach logs, timestamps, hostnames, and your preliminary reasoning    |
| IR stalled                               | Roles unclear / no runbook                | Define RACI, keep IR playbooks handy (contain/eradicate/recover steps)       |
| Over-reliance on tools                   | Automation ≠ analysis                     | People & process remain critical for context & prioritization                |
