## What is an “Incident” (fast refresher)
- Security solutions ingest **events** as logs and raise an **alert** on suspected harm. Analysts triage to weed out **false positives** vs **true positives**; confirmed (true) alerts become **incidents**. :contentReference[oaicite:6]{index=6} :contentReference[oaicite:7]{index=7} :contentReference[oaicite:8]{index=8}

## SANS PICERL — 6 Phases (with quick actions)
1) **Preparation** — teams, plans, tooling, training.  
   *Do:* phishing awareness, IR plan ready. :contentReference[oaicite:9]{index=9} :contentReference[oaicite:10]{index=10}

2) **Identification** — monitor for anomalies; confirm incident.  
   *Do:* validate unusual data exfil / phishing-led compromise. :contentReference[oaicite:11]{index=11} :contentReference[oaicite:12]{index=12}

3) **Containment** — **minimize impact** (isolate host, disable accounts).  
   *Do:* pull network cable/EDR isolate. :contentReference[oaicite:13]{index=13} :contentReference[oaicite:14]{index=14}

4) **Eradication** — remove the threat (malware cleanup, persistence removal).  
   *Do:* full malware scan, IOC purge. :contentReference[oaicite:15]{index=15}

5) **Recovery** — rebuild/restore, test, and return to service. :contentReference[oaicite:16]{index=16}

6) **Lessons Learned** — post-incident review, gaps → improvements. :contentReference[oaicite:17]{index=17} :contentReference[oaicite:18]{index=18}

**NIST mapping:** similar flow, condensed to 4 phases; includes **Post-Incident Activity**. :contentReference[oaicite:19]{index=19}

## L1 Analyst Playbook — Triage Snippets

### Host quick checks (Linux)
```bash
# Recent auth failures / logons
sudo grep -i "failed password" /var/log/auth.log | tail -n 50
last -i | head

# Processes & sockets
ps aux --sort=-%mem | head
sudo ss -tuna | head
````

### Host quick checks (Windows PowerShell)

```powershell
# Failed logons (4625) last hour
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4625; StartTime=(Get-Date).AddHours(-1)} |
  Select TimeCreated, Message | ft -Auto

# Listening sockets & heavy processes
netstat -ano | findstr LISTEN
Get-Process | Sort-Object CPU -Descending | Select -First 10
```

### Network pulse (pcap triage)

```bash
# SYNs + common admin ports
sudo tcpdump -nni any "tcp[tcpflags] & (syn) != 0 or port 445 or port 3389" -c 200
```

### Containment & follow-ups

* **Isolate** host (EDR network containment), **disable** compromised accounts, then **eradicate → recover**.   
* **Document** 5Ws, evidence, timeline; feed back into **Lessons Learned**.

## Incident Types (recognize the shape)

* **Malware infection**, **security breach**, **data leak**, **insider**, **DoS**—impact varies by org; don’t assume severity without context.

## Playbooks vs Runbooks (Use Both)

* **Playbook**: scenario-level guide (e.g., phishing).
  Example steps: notify, analyze headers/body, analyze attachments, check opens, isolate hosts, block sender. 
* **Runbook**: the granular, step-by-step execution for a specific tool/task.

## Gotchas (and Fast Fixes)

| Pitfall                    | Why it hurts               | Fix                                                               |
| -------------------------- | -------------------------- | ----------------------------------------------------------------- |
| Skipping **Preparation**   | Chaos during incidents     | Maintain IR plan, roles, comms, tooling readiness.                |
| Not **isolating** promptly | Lateral movement & spread  | Contain immediately (network isolate, disable creds).             |
| Cleaning before scoping    | Evidence loss, reinfection | Identify, **contain**, then eradicate; capture artifacts first.   |
| No **lessons learned**     | Repeat incidents           | Run a PIR; update playbooks/detections.                           |
| Tool over-reliance         | Missed context             | Combine SIEM/EDR alerts with analyst validation.                  |
