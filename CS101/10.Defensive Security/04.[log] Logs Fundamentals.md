## TL;DR
Logs are the **digital footprints** of activity; they’re essential for detection, investigation, troubleshooting, performance, and compliance. Focus on the **right log type** (Security vs. System vs. Application vs. Network vs. Access) and use fast text tools (`grep`, `less`, `tail`) or Windows Event Viewer filters (e.g., **Event ID 4624** for successful logins). :contentReference[oaicite:0]{index=0} :contentReference[oaicite:1]{index=1} :contentReference[oaicite:2]{index=2}

## Why Logs Matter (Use Cases)
- **Security monitoring** (spot anomalies)  
- **Incident investigation/forensics** (reconstruct actions)  
- **Troubleshooting** (find errors)  
- **Performance monitoring**  
- **Audit & compliance** (activity trail)

## Log Types & What to Look For
- **System Logs** – startup/shutdown, drivers, hardware errors.  
- **Security Logs** – authN/authZ, policy & account changes, abnormal activity.  
- **Application Logs** – app events, changes, updates, errors.  
- **Audit Logs** – data access, system changes, user activity, policy enforcement.  
- **Network Logs** – inbound/outbound traffic, firewall/connection events.  
- **Access Logs** – web, DB, app, API access patterns.

## Windows Event Logs (GUI Workflow)
1. Open **Event Viewer** → *Windows Logs* (Application, Security, System…). :contentReference[oaicite:11]{index=11}  
2. Use **Filter Current Log…** and search by **Event ID**. :contentReference[oaicite:12]{index=12}

**High-value Event IDs**
- `4624` Successful logon  
- `4625` Failed logon  
- `4634` Logoff  
- `4720/4722/4724/4725/4726` Account create/enable/reset/disable/delete

## Web Server Access Logs (CLI Workflow)
Sample file location (THM AttackBox): `/root/Rooms/logs/access.log`. :contentReference[oaicite:14]{index=14}

### Quick Parsers
```bash
# Grep by IP / verb / path
grep "192.168.1.1" access.log
grep "GET /contact" access.log | tail -n 1      # last GET /contact
grep "POST" access.log | grep "172.16.0.1" | tail -n 1
````

  

```bash
# Page through large logs
less access.log                # Space=next page, b=back, /pattern, n/N to hop
```

 

```bash
# Typical questions -> patterns
# Who accessed /contact last?
grep "GET /contact" access.log | tail -n 1

# When was the last POST by 172.16.0.1 and to which URL?
grep "POST" access.log | grep "172.16.0.1" | tail -n 1
```

## Fast Investigation Flow (Example)

1. **Define the question** (e.g., “last successful login yesterday 18:00–21:00”).
2. **Pick the log type** (Windows **Security** for auth). 
3. **Filter** (Event Viewer → **4624**, time range). 
4. **Pivot** (e.g., correlate with **Network** or **Access** logs if needed). 

---

## Gotchas

* **Noise overload**: reading logs raw is inefficient—**filter by IDs/time/keywords**. 
* **Missing context**: a single line rarely tells the story—correlate across **multiple log types**. 
* **Browser blocks** when downloading sample logs (IP/UA flagged)—choose **“Keep file”**. 
* **Time ordering assumptions**: `tail -n 1` assumes newest at bottom—verify log ordering. 
* **Over-reliance on memory**: don’t memorize all Event IDs—**know the key ones** and filter.

## Mini-Lab Prompts (Practice)

* “Find the IP that last hit `/contact`” → `grep "GET /contact" access.log | tail -n 1` 
* “Last `POST` by `172.16.0.1` + URL” → `grep "POST" access.log | grep "172.16.0.1" | tail -n 1` 
* “List all 5xx responses” → `grep 'HTTP/1.1" 5' access.log` (extend with `cut`, `awk` as needed). (Derived from the same parsing approach in the room.)
