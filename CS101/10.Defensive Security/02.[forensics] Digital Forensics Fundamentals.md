## Methodology (NIST 4 Phases)
**1) Collection** — identify all relevant devices and collect without tampering; document items. :contentReference[oaicite:10]{index=10}  
**2) Examination** — filter large datasets to the subset you need (by time/user/artifact). :contentReference[oaicite:11]{index=11}  
**3) Analysis** — correlate artifacts to reconstruct activities chronologically. :contentReference[oaicite:12]{index=12}  
**4) Reporting** — write findings/methodology, add executive summary & recommendations. :contentReference[oaicite:13]{index=13}

**Typical commands (collection integrity)**
```bash
# Create a raw image (Linux) – read source, write to image, record hashes
sudo dd if=/dev/sdX of=/evidence/disk.img bs=4M status=progress conv=sync,noerror
sha256sum /evidence/disk.img > /evidence/disk.img.sha256

# Mount image read-only for browsing
sudo mount -o ro,loop,show_sys_files,streams_interface=windows /evidence/disk.img /mnt/evidence
````

## Evidence Acquisition Essentials

* **Authorization** — obtain prior approval or risk inadmissibility. 
* **Chain of Custody** — maintain a detailed handoff/audit trail for each item. 
* **Write Blockers** — prevent unintended writes while imaging storage. 

**Quick commands**

```bash
# Verify device is read-only (Linux)
lsblk -o NAME,RO,RM,SIZE,TYPE,MOUNTPOINT

# Hash before & after imaging (integrity check)
md5sum /dev/sdX
md5sum /evidence/disk.img
```

## Windows Forensics — Imaging & Tools

* **Disk image**: non-volatile data (files, browsing history, etc.). **Memory image**: volatile state (processes, sockets)—**capture first**. 
* **Tooling highlights:** **FTK Imager** (acquire/analyze disk), **Autopsy** (full image analysis), **DumpIt** (acquire RAM), **Volatility** (analyze RAM).  

**Acquisition & analysis commands**

```powershell
# (Windows RAM) Run DumpIt (GUI/CLI) to create a memory dump on Windows
# Then transfer dump to your analysis workstation.

# (Linux RAM) Use LiME (if allowed) – not covered in the room but common:

vol -f memdump.raw windows.netconnections
vol -f memdump.raw windows.malfind
```

## Analyst Field Notes (Handy One-Liners)

```bash
# List recent files (by mtime) under user profiles
find /mnt/evidence/Users -type f -printf '%TY-%Tm-%Td %TH:%TM %p\n' | sort -r | head

# Grep for likely secrets/keywords
grep -RInE 'password|apikey|token|secret' /mnt/evidence 2>/dev/null | head

# Carve strings from a suspicious binary
strings -an -t x suspicious.bin | head
```

## Gotchas (and Fast Fixes)

| Pitfall                             | Why it hurts                                       | Fast fix                                                                  |
| ----------------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------- |
| Imaging **without** a write blocker | Timestamps & data may change on evidence media     | Use a **hardware/software write blocker** and verify RO mode.             |
| No **chain of custody**             | Evidence may be challenged in court                | Maintain a complete custody log (who/when/where).                         |
| Acquire **disk** before **memory**  | Volatile artifacts are lost on reboot/power events | Prioritize **memory image first**, then disk.                             |
| Over-collect, under-examine         | Noise hides relevant artifacts                     | Use **Examination** to filter by time/user/source before Analysis.        |
| Weak reporting                      | Stakeholders can’t act                             | Follow the **Reporting** phase with methods, findings, and exec summary.  |
