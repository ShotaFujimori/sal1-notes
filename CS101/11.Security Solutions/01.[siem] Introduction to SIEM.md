
# 36. SAL1 — Security Solutions: Introduction to SIEM (Cheat Sheet)
tags: [siem, soc, logs, parsing, normalization, correlation, alerting, dashboards]

## TL;DR
- **SIEM = Security Information and Event Management**: centralizes logs, **parses/normalizes**, **correlates** events, and **alerts in near-real time** so analysts can detect and investigate threats efficiently. :contentReference[oaicite:0]{index=0}  
- Solves scattered logs, volume, inconsistent formats, and missing context by **collect→normalize→correlate→alert→investigate**. :contentReference[oaicite:1]{index=1}

---

## Core Concepts (Why SIEM)
- **Problems without SIEM**: too many sources, no centralization, limited context, manual analysis limits, format mismatch. :contentReference[oaicite:2]{index=2}  
- **What SIEM does**: centralized collection, parsing/normalization, cross-source correlation, real-time alerting, dashboards/reporting. :contentReference[oaicite:3]{index=3}

## Log Sources & Quick Commands

### Windows (Event Viewer basics)
- Open **Event Viewer** → Windows Logs (Application/Security/System) → **Filter Current Log…** by **Event ID**. :contentReference[oaicite:4]{index=4}  
- Useful IDs: **4624** (logon success), **4625** (logon failure), **4634** (logoff), **4720/4722/4724/4725/4726** (account ops). :contentReference[oaicite:5]{index=5}

**PowerShell snippets**
```powershell
# Failed logons (4625) in last hour
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4625; StartTime=(Get-Date).AddHours(-1)} |
  Select TimeCreated, Id, Message | ft -Auto

# Recent process starts (4688) — common for rule building
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4688; StartTime=(Get-Date).AddHours(-1)} |
  Select TimeCreated, Id, Message | more
````

### Linux (common log paths)

* `/var/log/auth.log` or `/var/log/secure` (auth), `/var/log/cron` (cron), `/var/log/kern` (kernel), **HTTP**: `/var/log/httpd` or `/var/log/apache`. 

**CLI snippets**

```bash
# Last 50 failed SSH attempts
grep -i "failed" /var/log/auth.log | tail -n 50

# Recent cron messages
tail -n 50 /var/log/cron

# Quick web access triage (Apache/HTTPD)
grep "GET /" /var/log/httpd/access.log | tail -n 10
```

### Web servers (access logs)

* Monitor requests/responses for attack patterns; default Apache/HTTPD paths above.

## Ingestion Methods (to SIEM)

* **Agent/Forwarder** on endpoints (e.g., Splunk Forwarder).
* **Syslog** from servers/network gear.
* **Manual upload** for offline analysis.
* **Port-forwarding/listener** on SIEM to receive logs. 

**Examples (conceptual)**

```bash
# Syslog (rsyslog) example: send auth logs to SIEM
# /etc/rsyslog.d/60-siem.conf
auth,authpriv.*  @siem.company.lan:514
```

## Alerting & Rule Creation

**How rules trigger**

* Logical conditions on normalized fields (e.g., failed logins, process starts, USB insertion, outbound data volume). 

**Windows use-cases**

* **Event Log cleared** → **Event ID 104** ⇒ trigger “Event Log Cleared”. 
* **Suspicious command** (e.g., `whoami`) → **Event ID 4688** with `NewProcessName` contains `whoami`. 

**Generic SIEM query idea (pseudocode)**

```txt
# Multiple Failed Logins in 10s
source=WinEventLog:Security Id=4625
| bucket _time span=10s
| stats count by user, src_ip, _time
| where count >= 5
```

## Analyst Workflow (L1)

1. **Triage** alert in dashboards (top failed logins, health, rules triggered). 
2. **Pivot** into correlated events (host + network + auth).
3. Decide **True/False Positive**; **tune** noisy rules if FP; **escalate** & contain if TP. 

---

## Dashboards & Reporting

* Typical widgets: **Alert highlights, failed login list, events ingested, rules triggered, top domains**; customize per org.

## Gotchas (and Fast Fixes)

| Pitfall                            | Why it hurts                     | Fix                                                        |
| ---------------------------------- | -------------------------------- | ---------------------------------------------------------- |
| Analyzing **isolated logs**        | Misses cross-source patterns     | Use SIEM **correlation** views and timeline.               |
| **Format mismatch** across sources | Slows analysis                   | Rely on SIEM **parsing/normalization** fields.             |
| **Volume overload**                | Humans miss signals              | Let SIEM alert, then **filter/aggregate** by fields/time.  |
| Over-tuned or under-tuned rules    | FPs waste time; FNs miss attacks | Iteratively **tune** rules after investigations.           |
| Forgetting key IDs                 | Slows triage                     | Memorize core IDs: **4624/4625/4634/4688/104**.            |

## Copy-Paste Mini-Playbook

**Windows (investigate a logon burst)**

```powershell
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4625; StartTime=(Get-Date).AddMinutes(-15)} |
  Group-Object {$_.Properties[5].Value} | Sort-Object Count -Descending | Select -First 5
```

**Linux (quick auth + web triage)**

```bash
grep -i "failed" /var/log/auth.log | tail -n 100
awk '{print $1,$2,$3,$7,$9}' /var/log/httpd/access.log | tail -n 50
```

**Rule sketch (pseudo)**

```txt
IF source=WinEventLog AND EventID=4688 AND NewProcessName CONTAINS "whoami"
THEN ALERT "WHOAMI command execution detected"
```
