# IDS Fundamentals

## Overview
Intrusion Detection System (IDS) is a security tool that monitors network or system activity to detect and alert on suspicious or malicious behavior.

## Key Differences: IDS vs IPS

| Feature | IDS | IPS |
|---------|-----|-----|
| **Detection** | Detects threats | Detects and blocks threats |
| **Response** | Alerts only | Active blocking/prevention |
| **Deployment** | Passive monitoring | In-line deployment |
| **Performance Impact** | Minimal | May cause latency |
| **False Positives** | Less critical | More disruptive |

## IDS Types

### 1. Network IDS (NIDS)
- Monitors entire network traffic
- Analyzes packets crossing network boundaries
- Deployed at network edge or core
- Examples: Snort, Suricata, Zeek

### 2. Host IDS (HIDS)
- Monitors system and application activity on individual hosts
- Tracks file system changes, process execution, user behavior
- Installed as agent on each monitored system
- Examples: OSSEC, Wazuh, Falco

### 3. Hybrid Approach
- Combines NIDS and HIDS
- Provides comprehensive coverage
- Reduces blind spots

## Detection Methods

### Signature-Based Detection
**How it works:**
- Compares traffic against database of known attack signatures
- Pattern matching against threat indicators
- Fast and accurate for known threats

**Pros:**
- Low false positive rate
- Good performance
- Easy to understand alerts

**Cons:**
- Misses zero-day exploits
- Requires frequent signature updates
- Cannot detect unknown threats

### Anomaly-Based Detection
**How it works:**
- Establishes baseline of normal behavior
- Flags deviations from baseline
- Uses statistical analysis or machine learning

**Pros:**
- Detects unknown/zero-day attacks
- Adapts to new threats
- Better for insider threats

**Cons:**
- High false positive rates
- Requires long baseline period
- Resource intensive
- Harder to understand alerts

### Protocol-Based Detection
- Monitors for protocol violations
- Detects misuse of HTTP, DNS, etc.
- Combination of signature and anomaly

## Example IDS Rules

### Snort/Suricata Signature Format
```
alert tcp any any -> any 80 (msg:"HTTP SQL Injection"; 
  content:"GET"; http_method; 
  content:"union select"; http_uri; 
  case_sensitive; 
  sid:1000001; rev:1;)

alert tcp any any -> any 445 (msg:"SMB Exploit Attempt"; 
  content:"|ff|SMB"; offset:0; 
  content:"|5c 5c"; 
  sid:1000002; rev:1;)

alert dns any any -> any 53 (msg:"Suspicious DNS Query"; 
  dns_query; content:"bitly"; 
  sid:1000003; rev:1;)
```

### OSSEC Rule Example
```
<rule id="100001" level="5">
  <if_sid>4688</if_sid>
  <pattern>^powershell.exe</pattern>
  <description>PowerShell execution detected</description>
</rule>
```

## IDS Deployment Steps

### Phase 1: Planning
1. Define monitoring scope (which networks/systems)
2. Identify critical assets
3. Determine detection methods
4. Plan resource allocation

### Phase 2: Installation
1. Deploy IDS sensors on network segments
2. Configure HIDS agents on critical servers
3. Set up central management console
4. Configure logging/storage backend

### Phase 3: Configuration
1. Upload/enable detection signatures
2. Whitelist legitimate traffic patterns
3. Configure alerting rules
4. Set notification channels (email, syslog, etc.)

### Phase 4: Testing
1. Perform baseline testing
2. Validate signature detection with test traffic
3. Ensure proper logging and alerting
4. Document false positives

### Phase 5: Tuning & Optimization
1. Reduce false positives
2. Fine-tune thresholds
3. Optimize performance
4. Regular signature updates

## Tuning & Optimization

### Reducing False Positives
```
# Whitelist legitimate traffic
- Internal vulnerability scanners
- Legitimate admin tools
- Normal backup processes
- Expected security testing
```

### Performance Optimization
1. **Load balancing**: Distribute IDS across multiple sensors
2. **Sampling**: Monitor subset of traffic (use carefully)
3. **Rule filtering**: Disable unnecessary signatures
4. **Resource allocation**: Ensure adequate CPU/Memory/Storage

### Signature Management
1. Regular updates (daily/weekly)
2. Test before production deployment
3. Maintain backup of custom rules
4. Document rule modifications

## Common Pitfalls

### 1. Alert Fatigue
**Problem:** Too many alerts overwhelm analysts
**Solution:** 
- Tune rules aggressively
- Implement alert correlation
- Prioritize by severity

### 2. Insufficient Tuning
**Problem:** High false positive rate wastes time
**Solution:**
- Baseline normal traffic first
- Whitelist known-good patterns
- Regular tuning iterations

### 3. Poor Signature Updates
**Problem:** Missing new threats
**Solution:**
- Automate signature updates
- Monitor threat intelligence
- Test updates before deployment

### 4. Incomplete Coverage
**Problem:** Blind spots in monitoring
**Solution:**
- Deploy NIDS at network chokepoints
- Install HIDS on critical servers
- Monitor encrypted traffic (metadata)

### 5. Lack of Integration
**Problem:** IDS isolated from other security tools
**Solution:**
- Integrate with SIEM
- Connect to threat intelligence feeds
- Enable automated response (if using IPS)

### 6. Insufficient Logging/Retention
**Problem:** Cannot investigate incidents
**Solution:**
- Centralized log collection
- Adequate storage capacity
- Retention policies (typically 3-12 months)

## IDS vs. Firewall

| Aspect | Firewall | IDS |
|--------|----------|-----|
| **Function** | Access control | Threat detection |
| **Action** | Allow/block | Alert/log |
| **Analysis** | Headers/metadata | Full packet inspection |
| **Coverage** | Network boundary | Network + hosts |

## Best Practices

1. **Defense in Depth**: Use IDS alongside firewalls, antivirus, etc.
2. **Regular Reviews**: Audit alerts and rules monthly
3. **Threat Intelligence**: Update rules based on current threats
4. **Testing**: Conduct regular IDS effectiveness tests
5. **Documentation**: Maintain current rule and configuration docs
6. **Training**: Ensure SOC team understands IDS capabilities
7. **Incident Response**: Have playbooks for IDS alerts
8. **Integration**: Connect with SIEM and other security tools

## Limitations

- Cannot detect evasion techniques (encryption, obfuscation)
- High false positive rates with anomaly detection
- Requires tuning and maintenance
- May not detect advanced persistent threats (APTs)
- Performance degradation in high-traffic environments
- Signature updates lag behind threats
