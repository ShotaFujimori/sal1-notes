# 38. SAL1 — Security Solutions: IDS Fundamentals (Cheat Sheet)

---

## TL;DR
- **IDS = Intrusion Detection System**: monitors traffic/activities **after** connections are established and **alerts** on suspicious behavior; it **does not block** by itself (that’s IPS/firewall). Answer to “Can IDS prevent?” → **Nay**. 
- Types by **deployment**: **HIDS** (on hosts) vs **NIDS** (on networks). Types by **detection**: **Signature-based**, **Anomaly-based**, **Hybrid**. 
- **Snort** is a widely used open-source IDS: built-in rule sets + **custom rules**; supports **sniffer**, **packet-logging**, and **NIDS** modes.

---

## IDS Overview (Why & Where)
- Firewall ≈ gatekeeper; **IDS ≈ surveillance camera** that watches what slipped past and **generates alerts**.   
- **HIDS**: per-host depth; management overhead at scale. **NIDS**: centralized view; sees lateral movement across hosts. 
- **Signature**: fast on known patterns; misses zero-days. **Anomaly**: baseline vs deviation; can catch unknowns but noisier. **Hybrid**: both.

## Snort — Files, Modes & First Look
**Key paths**
```bash
# Snort directory & important files (AttackBox/Ubuntu layout)
ls /etc/snort
# → snort.conf, rules/, classification.config, reference.config, ...
````



**Modes (choose per task)**

* **Sniffer mode** – print packets (troubleshooting).
* **Packet-logging mode** – write **pcap** for later forensics.
* **NIDS mode** – real-time detection with rules → alerts.

## Snort Rule Anatomy (Quick Reference)

```text
alert icmp any any -> $HOME_NET any (msg:"Ping Detected"; sid:10001; rev:1;)
# action  proto src_ip src_port   dst_ip     dst_port   (metadata...)
```

* **action**: `alert` / `pass` / …
* **proto**: `tcp`/`udp`/**`icmp`**/…
* **$HOME_NET** from `snort.conf` (your monitored range)
* **msg**: alert text | **sid**: unique rule ID | **rev**: rule revision

## Create & Test a Custom Rule (Local)

**1) Edit local rules**

```bash
sudo nano /etc/snort/rules/local.rules

# Example (loopback ICMP)
alert icmp any any -> 127.0.0.1 any (msg:"Loopback Ping Detected"; sid:10003; rev:1;)
```



**2) Run Snort (console alerts)**

```bash
# -q quiet banners | -l log dir | -i interface | -A console | -c config
sudo snort -q -l /var/log/snort -i lo -A console -c /etc/snort/snort.conf
```

Then, in another terminal:

```bash
ping 127.0.0.1
```

(You should see **“Loopback Ping Detected”** alerts.)

## Run Snort on a PCAP (Forensics)

```bash
# Analyze historical capture with your current rule set
cd /etc/snort
sudo snort -q -l /var/log/snort -r Intro_to_IDS.pcap -A console -c /etc/snort/snort.conf
```

Use this to answer questions (e.g., “what IP attempted SSH?”, “what other msg besides SSH?”, “sid for SSH rule?”).

## Copy-Paste Snort Recipes

```bash
# 1) Live detect on eth0 for your HOME_NET
sudo snort -q -l /var/log/snort -i eth0 -A console -c /etc/snort/snort.conf

# 2) Pure packet sniff (no detection)
sudo snort -v -i eth0

# 3) Packet logging (pcap output under /var/log/snort)
sudo snort -b -l /var/log/snort -i eth0

# 4) Analyze a PCAP with your rules
sudo snort -q -l /var/log/snort -r sample.pcap -A console -c /etc/snort/snort.conf
```

## Gotchas (and Fast Fixes)

| Pitfall                                 | Why it hurts                                                 | Fix                                                                                   |
| --------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| Expecting IDS to **block**              | IDS only **alerts**; no prevention                           | Pair with **IPS/firewall** for enforcement; or automate SOAR actions                  |
| Wrong interface / not seeing traffic    | Snort not on the path; interface not in **promiscuous** mode | Use the correct `-i` (e.g., `eth0`, `lo`); enable SPAN/TAP for NIDS visibility        |
| No alerts from your custom rule         | Rule disabled or mis-scoped `$HOME_NET`                      | Confirm rule in `local.rules`, included by `snort.conf`, and `$HOME_NET` set properly |
| Flood of false positives (anomaly mode) | Baseline not tuned                                           | Fine-tune baseline; suppress noisy SIDs; add context conditions                       |
| SID collisions                          | Multiple rules share same `sid`                              | Use your own **sid range** (e.g., 1,000,000+) and increment **rev** on edits          |
| Logging but empty console               | Using logging/sniffer flags, not NIDS                        | Use **`-A console`** with a detection config; verify rules loaded                     |
|                                         |                                                              |                                                                                       |
