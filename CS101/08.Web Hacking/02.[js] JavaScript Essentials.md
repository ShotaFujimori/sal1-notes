# 24 — Web Hacking: JavaScript Essentials (Notes)

## TL;DR

* JavaScript (JS) adds interactivity to HTML/CSS and is core to modern web apps. Attackers can also abuse legitimate JS features.&#x20;
* Know the basics (variables, data types, functions, loops) and how to run JS in the browser console. &#x20;
* Integrate JS **internally** (code inside `<script>` in HTML) or **externally** (separate `.js` file via `src`). &#x20;
* Dialogue functions `alert`, `prompt`, `confirm` can be misused (e.g., for annoyance or as a stepping stone to XSS). &#x20;
* Client-side logic (e.g., simple login checks) is easy to bypass; never rely on it alone.&#x20;
* Minification/obfuscation shrink or hide JS but still run; deobfuscation tools can reveal readable code. &#x20;
* Best practices: validate on the server, avoid untrusted libraries, don’t hardcode secrets, and minify/obfuscate in production.   &#x20;

---

## Core JS building blocks

* **Variables:** `var` (function scope), `let`/`const` (block scope).&#x20;
* **Data types:** `string`, `number`, `boolean`, `null`, `undefined`, `object`.&#x20;
* **Functions:** group reusable logic; call with arguments.&#x20;
* **Loops:** `for`, `while`, `do…while` repeat while a condition holds.&#x20;

**Quick console demo**

```js
// Hello, World + basics
console.log("Hello, World!");
let age = 25;
if (age >= 18) { console.log("You are an adult."); } else { console.log("You are a minor."); }
function greet(name) { console.log("Hello, " + name + "!"); }
greet("Bob");
```

Run in Chrome DevTools → **Console**.&#x20;

## Integrating JavaScript in HTML

### Internal JS (script is inside the HTML)

```html
<p id="result"></p>
<script>
  let x = 5, y = 10;
  document.getElementById("result").innerHTML = "The result is: " + (x + y);
</script>
```

Used for simple pages and quick demos. &#x20;

### External JS (separate `.js` file)

```html
<!-- external.html -->
<p id="result"></p>
<script src="script.js"></script>
```

Keeps HTML clean; easier reuse/maintenance across pages.&#x20;

**How to tell which is used:** View Page Source—inline code shows `<script>` without `src`; external uses a `src` attribute.&#x20;

---

## Dialogue functions (and abuse)

* `alert("Hello")` → info box with **OK**.&#x20;
* `prompt("Name?")` → input box; returns value or `null`.&#x20;
* `confirm("Proceed?")` → **OK/Cancel**; returns `true/false`.&#x20;

**Abuse example:** a looped `alert` to create denial-of-service–like annoyance.&#x20;

---

## Control flow & common bypass

* `if/else`, `switch`, and loops direct execution.&#x20;
* **Client-side auth checks** (e.g., validating username/password purely in JS) are trivial to bypass—logic is visible and editable in the browser.&#x20;

---

## Minified & obfuscated JS

* **Minification:** removes whitespace/comments and shortens names to reduce size; still runs the same.&#x20;
* **Obfuscation:** intentionally hard to read (renamed variables, dummy code, packed strings).&#x20;
* Obfuscated snippets still execute; online tools can **deobfuscate** to a readable form. &#x20;

---

## Best practices (security)

* **Always** validate on the **server**, not just client side.&#x20;
* Don’t include **untrusted libraries** via `src`.&#x20;
* **Never hardcode secrets** (API keys, tokens).&#x20;
* **Minify/obfuscate** production JS to raise the bar for reverse-engineering.&#x20;
