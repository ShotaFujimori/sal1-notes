# 26. SAL1 Note — Web Hacking: Burp Suite — *The Basics*

## 1) What you’ll learn (room goals)

* Introduce Burp Suite and its core workflow.
* Understand the **Burp Proxy** and how to route traffic through it.
* Configure a browser with **FoxyProxy** to use Burp.
* Use **Target → Site map**, **Issue definitions**, and **Scope** effectively.
* Perform a first interception and a simple input-tampering exercise.

## 2) Editions & scope of this room

* Focus: **Burp Suite Community Edition** features. 
* Q&A recap:

  * Which edition runs on a server and performs constant scanning? **Burp Suite Enterprise**. 
  * Burp is used when attacking web apps and **mobile** applications. 

---

## 3) Burp Community — key tools you’ll use first

* **Proxy** – intercept/modify requests & responses.
* **Repeater** – resend & tweak requests for manual testing (e.g., SQLi trial-and-error).
* **Intruder** – limited in Community, but useful for simple spraying/fuzzing.
* **Decoder** – encode/decode/transform data inside Burp.
* **Comparer** – diff two pieces of data (word/byte level). 

---

## 4) The Burp Proxy: concepts & options

**What it does**

* Captures requests/responses between your browser and the target; lets you forward, drop, edit, or send to other tools.
* Logs HTTP and **WebSocket** traffic into **HTTP history** / **WebSockets history** even when intercept is off.  

**Notable settings (Proxy → *Proxy settings*)**

* **Response interception rules** – enable rule-based interception of server responses.
* **Match & Replace** – regex-based on-the-fly rewrites (e.g., change user-agent/cookies). 

**Tip**: Explore Proxy options to build fluency. 

---

## 5) Routing your browser through Burp (FoxyProxy on Firefox)

1. Install **FoxyProxy Basic** (already on AttackBox).
2. Click the FoxyProxy button → **Options** → **Add** new proxy.
3. Configure:

   * **Title**: Burp
   * **Proxy IP**: `127.0.0.1`
   * **Port**: `8080`
     Save, then select this profile to route traffic via Burp.  
4. In Burp, ensure **Proxy → Intercept is on**.
5. Visit a page (e.g., `http://10.201.67.149/`). The browser will “hang” while the request appears in Burp—forward/drop as needed. 

**Gotchas**

* If intercept is left **on**, your browser won’t load pages until you forward or turn it off.
* Close other tabs to avoid WebSocket noise in the history when practicing.  

---

## 6) Target tab: Site map • Issue definitions • Scope

* **Site map** – auto-maps everything you browse; great for discovering API endpoints.
* **Issue definitions** – reference library of vulnerability types with descriptions/links.
* **Scope** – include/exclude hosts to focus collection and reduce noise. 

**Workflow tip (scoping)**
Right-click your target in **Target → Site map** → **Add to scope**, then (usually) choose to stop logging out-of-scope traffic. Check/adjust in **Target → Scope**. 

---

## 7) Burp’s built-in browser (Chromium)

* Launch via **Proxy → Open Browser**; it’s pre-configured for the proxy.
* On Linux as root (AttackBox), sandboxing may block it. Either:

  1. Run Burp as a low-priv user (recommended), or
  2. **Settings → Tools → Burp’s browser → Allow … without a sandbox** (less secure; fine for labs).

## 8) Mini exercise: quick client-side filter bypass (contact form)

1. With Proxy active & **Intercept ON**, submit the support form with benign data.
2. Replace the captured email value with

   ```html
   <script>alert("Succ3ssful XSS")</script>
   ```
3. Select the payload → **Ctrl+U** to URL-encode → **Forward**.
   You should see an alert pop—successful reflected XSS.

## 10) Essential terms & concepts (quick reference)

* **Burp Proxy**: Intercept, view, edit, forward/drop traffic between client and server. 
* **Intercept**: The hold-and-review step before requests/responses proceed. 
* **HTTP history / WebSockets history**: Burp’s logs of past traffic for replay/analysis. 
* **Repeater**: Manual resend/tune requests for testing logic and payloads. 
* **Intruder**: Spray/fuzz endpoints (rate-limited in Community). 
* **Decoder**: Encode/decode/transform data in-suite. 
* **Comparer**: Diff responses or snippets at word/byte level. 
* **Match & Replace**: Regex-based rewrite engine in Proxy settings. 
* **Response interception rules**: Optional ruleset to catch responses automatically. 
* **FoxyProxy**: Browser add-on to switch proxies; set `127.0.0.1:8080` for Burp. 
* **Site map**: Auto tree of visited paths (useful for API discovery). 
* **Issue definitions**: Built-in vuln knowledge base. 
* **Scope**: Include/exclude hosts to limit logging/analysis to targets.

## 11) Practical checklist

* [ ] Start Burp; confirm **Proxy listener** and **Intercept** status.
* [ ] In Firefox, enable **FoxyProxy → Burp (127.0.0.1:8080)**.
* [ ] Add your target to **Scope**; consider disabling out-of-scope logging. 
* [ ] Use **HTTP history** to review/forward, **Repeater** to test, **Decoder**/**Comparer** as needed.
