## 1) Databases at a glance
- **Relational (SQL):** structured, tabular data; relationships across tables.  
- **Non-relational (NoSQL):** non-tabular documents/objects; flexible schema.  
- **Table / Row / Column:** schema defines columns + types; each record is a row.  
- **Primary key:** uniquely identifies a row (one per table).  
- **Foreign key:** column(s) that reference a key in another table to create relationships. :contentReference[oaicite:2]{index=2}

## 3) Database statements (cheat-sheet)

| Statement       | Purpose             | Example                              | Notes                       |   |
| --------------- | ------------------- | ------------------------------------ | --------------------------- | - |
| CREATE DATABASE | Make a new database | `CREATE DATABASE thm_bookmarket_db;` | First step before tables    |   |
| SHOW DATABASES  | List all databases  | `SHOW DATABASES;`                    | Includes default system DBs |   |
| USE             | Select active DB    | `USE thm_bookmarket_db;`             | Affects subsequent queries  |   |
| DROP DATABASE   | Remove a DB         | `DROP DATABASE name;`                | Irreversible; use with care |   |

## 4) Table statements (cheat-sheet)

| Statement       | Purpose                   | Example                                                                                                                          | Notes                      |   |
| --------------- | ------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | -------------------------- | - |
| CREATE TABLE    | Create table with columns | `CREATE TABLE book_inventory( book_id INT AUTO_INCREMENT PRIMARY KEY, book_name VARCHAR(255) NOT NULL, publication_date DATE );` | Define types + constraints |   |

| DROP TABLE      | Remove table              | `DROP TABLE table_name;`                                                                                                         | Deletes all data           |   |

## 5) CRUD operations

| Op     | SQL                      | Example                                                                                                           | What it does   |   |
| ------ | ------------------------ | ----------------------------------------------------------------------------------------------------------------- | -------------- | - |
| Create | `INSERT INTO`            | `INSERT INTO books(id,name,published_date,description) VALUES (1,"Android Security Internals","2014-10-14","…");` | Adds a new row |   |
| Read   | `SELECT`                 | `SELECT * FROM books;` or `SELECT name,description FROM books;`                                                   | Retrieves data |   |
| Update | `UPDATE … SET … WHERE …` | `UPDATE books SET description="…" WHERE id=1;`                                                                    | Modifies rows  |   |
| Delete | `DELETE FROM … WHERE …`  | `DELETE FROM books WHERE id=1;`                                                                                   | Removes rows   |   |

## 6) Clauses (query shaping)

| Clause   | Purpose                  | Example                                            | Effect               |   |
| -------- | ------------------------ | -------------------------------------------------- | -------------------- | - |
| DISTINCT | Remove duplicates        | `SELECT DISTINCT name FROM books;`                 | Unique names only    |   |
| GROUP BY | Aggregate by column(s)   | `SELECT name, COUNT(*) FROM books GROUP BY name;`  | Per-name counts      |   |
| ORDER BY | Sort results             | `SELECT * FROM books ORDER BY published_date ASC;` | ASC/DESC sorting     |   |
| HAVING   | Filter after aggregation | `… GROUP BY name HAVING name LIKE '%Hack%';`       | Filters grouped rows |   |

---

## 7) Operators (logic & comparison)

| Operator       | Use                       | Example                                                                           | Notes                 |   |
| -------------- | ------------------------- | --------------------------------------------------------------------------------- | --------------------- | - |
| LIKE           | Pattern match             | `WHERE description LIKE "%guide%"`                                                | Wildcards: `%`, `_`   |   |
| AND / OR / NOT | Combine/negate conditions | `WHERE cat="Offensive" AND name="Bug Bounty Bootcamp"`                            | Truth-table logic     |   |
| BETWEEN        | Range check               | `WHERE id BETWEEN 2 AND 4`                                                        | Inclusive bounds      |   |
| = / !=         | Equality / inequality     | `WHERE name="Designing Secure Software"` / `WHERE category!="Offensive Security"` | Strings quoted        |   |
| < / >          | Less / Greater            | `WHERE published_date < "2020-01-01"`                                             | Compare numbers/dates |   |
| <= / >=        | LE / GE                   | `WHERE published_date >= "2021-11-02"`                                            | Inclusive compare     |   |

---

## 8) Functions (a taste)

| Function        | Purpose             | Example                                                                            | Output                      |   |
| --------------- | ------------------- | ---------------------------------------------------------------------------------- | --------------------------- | - |
| COUNT()         | Tally rows          | `SELECT COUNT(DISTINCT category) FROM hacking_tools;`                              | Number of unique categories |   |
| CONCAT()        | Join strings        | `SELECT CONCAT(name," is a type of ",category," book.") AS info FROM books;`       | `"… is a type of …"`        |   |
| GROUP\_CONCAT() | Join grouped values | `SELECT category, GROUP_CONCAT(name SEPARATOR ", ") FROM books GROUP BY category;` | Per-category list of titles |   |

## 10) Gotchas & tips

* Always set an appropriate **PRIMARY KEY** and use the right **data types**.
* `WHERE` filters **before** aggregation; `HAVING` filters **after** aggregation.
* Be precise with quotes and semicolons in MySQL; syntax errors are common.
* Deleting demo rows can break later examples—follow the room’s notes.&#x20;
