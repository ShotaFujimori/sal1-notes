## TL;DR
- Public-key (asymmetric) crypto gives us **authentication, integrity, signatures, and key distribution**. Confidentiality at the end of the day is usually handled by a **symmetric cipher** (e.g., AES).
- Core in practice: **RSA / DH(E) / SSH keys / Digital signatures / Certificates (PKI) / PGP/GPG**.  
- Golden rules for keys: **never share private keys**, set permissions to **0600**, and protect them with a **passphrase**. Only the **public key** is given to servers or other parties.

## Gotchas
- **Never share private keys**. Set `~/.ssh/id_*` permissions to **0600**. A passphrase **encrypts the private key locally** and is never sent to a server.
- Do not skip the **host-key fingerprint** check on first SSH connect (MITM risk). Investigate any “host key changed” warnings.
- Treat **2048-bit RSA as the minimum**; prefer **Ed25519/ECDSA** for new deployments.  
- Build **automatic certificate renewal** (Let’s Encrypt/ACME) into operations. Broken chains are a common outage cause.
- Weak passphrases for GPG/SSH keys can be cracked with tools like `john` (`ssh2john`/`gpg2john`). Use strong ones.

## Important terms & concepts
- **Public key / Private key**: The shareable key vs. the strictly protected key.  
- **Asymmetric encryption (public-key)**: Uses different keys (e.g., RSA, ECC).  
- **RSA**: n=p×q, public (n,e), private (n,d); used for signatures/key transport.  
- **Diffie–Hellman (DH/ECDH)**: Key agreement for a shared secret over an open channel.  
- **Key exchange / Key transport**: Agreeing on a key vs. safely delivering a generated key.  
- **Digital signature**: Sign with private key, verify with public; proves authenticity/integrity.  
- **Certificate / PKI / CA / Chain of trust**: How identities are vouched for and verified.  
- **Fingerprint**: Short hash identifying a key/cert; verify during SSH first-connect.  
- **SSH keys**: `id_ed25519` etc.; add public key to `authorized_keys`.  
- **DSA / ECDSA / Ed25519**: Signature algorithms; **Ed25519** is fast and robust.  
- **Let’s Encrypt / ACME**: Free automated certificate issuance/renewal.  
- **PGP / GPG / OpenPGP**: Ecosystem for encrypting/signing emails/files.  
- **Passphrase**: Encrypts your private key file locally (not transmitted).  
- **Modulo / φ(n)**: Number-theory pieces behind RSA (Euler’s totient).  
- **Man-in-the-Middle (MITM)**: Prevent with fingerprint/certificate validation.

## Appendix: Diffie–Hellman Key Exchange (correct formulas)

**What it is.**  
Diffie–Hellman (DH) lets two parties agree on a shared secret over an eavesdropped channel. Security relies on the hardness of the **discrete logarithm** problem.

**Do not mix with RSA.**  
Formulas like `n = p × q` and `φ(n) = (p − 1)(q − 1)` are **RSA** (factorization). DH uses a **prime modulus** `p` (or an elliptic-curve group), not a composite `n`.

#### Finite-field DH (a.k.a. “mod-p DH”)
- Choose a large **prime** `p` and a **generator** `g` of a large subgroup of ℤ\*_p (commonly a “safe prime” `p = 2q + 1` and `g` of order `q`).
- Alice picks a private `a` (uniform random in `[1, q−1]`) and sends **A = g^a mod p**.
- Bob picks a private `b` and sends **B = g^b mod p**.
- Shared secret:
  - Alice computes **s = B^a mod p = (g^b)^a mod p = g^(ab) mod p**  
  - Bob computes **s = A^b mod p = (g^a)^b mod p = g^(ab) mod p**
- Both get the same `s`. A **KDF** (e.g., HKDF) is then applied to `s` to derive symmetric keys.

> **Correct DH formulas:**  
> `A = g^a mod p`  
> `B = g^b mod p`  
> `shared = A^b mod p = B^a mod p = g^(ab) mod p`

#### Tiny worked example (toy numbers)
Let `p = 23`, `g = 5`.  
Alice: `a = 6` → `A = 5^6 mod 23 = 8`  
Bob: `b = 15` → `B = 5^15 mod 23 = 19`  
Shared:
- Alice: `s = B^a mod 23 = 19^6 mod 23 = 2`
- Bob:   `s = A^b mod 23 = 8^15 mod 23 = 2`  
Both sides get `s = 2` (then run a KDF).  
*(These small values are for illustration only; real DH uses ~2048-bit `p`, or better, ECDH.)*

#### Elliptic-Curve DH (ECDH)
- Pick a curve with base point **G** of large prime order `n`.
- Alice: private `a`, public **A = a·G**.  
  Bob: private `b`, public **B = b·G**.
- Shared: **S = a·B = b·A = ab·G**.  
  Typically you take the x-coordinate of `S` and feed it to a **KDF**.

#### Security notes / gotchas
- **Authenticate** the peer (e.g., with certificates or SSH host keys) to prevent **MITM**.  
- Prefer **ephemeral DH** (**DHE/ECDHE**) so you get **forward secrecy**.  
- Use a **safe prime** `p` and validated `g` (or a vetted curve like **X25519/Ed25519**).  
- Always run a **KDF** on the raw shared secret; don’t use it directly as an encryption key.
