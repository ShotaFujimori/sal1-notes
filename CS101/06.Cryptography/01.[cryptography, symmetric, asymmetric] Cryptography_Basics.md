## TL;DR
- Cryptography protects **confidentiality, integrity, authenticity** for data at rest and in transit.
- **Plaintext →(cipher,key)→ Ciphertext**; reverse with the right key only.
- Two families: **symmetric** (one secret key; fast) vs **asymmetric** (public/private keys; solves key exchange).
- Use modern ciphers: **AES** (sym), **RSA/Diffie-Hellman/ECC** (asym). Avoid **DES/3DES** for new systems.
- Core math shows up everywhere: **XOR** and **modulo**.

## Gotchas
- **Don’t use DES/3DES** for new systems; migrate to **AES**.
- Symmetric keys are fast but **hard to distribute** securely without a PKI or out-of-band channel.
- Asymmetric crypto is slower; typically used for **key exchange & identity**, then switch to symmetric for bulk data.
- **Modulo results are 0…n-1**; modulo is **not reversible**.
- **XOR alone** is not secure unless used in a proper construction (e.g., OTP with truly random one-time key).

## Glossary: Important Terms & Concepts

| Term | Meaning / Why you care |
|---|---|
| **Plaintext** | The original readable data before encryption. |
| **Ciphertext** | The scrambled, unreadable result of encryption. |
| **Cipher** | The algorithm that transforms plaintext ⟷ ciphertext (e.g., AES, RSA). |
| **Key** | The value that drives the cipher; keep it secret (sym) or manage as a key pair (asym). |
| **Encryption** | Process that converts plaintext → ciphertext to provide confidentiality. |
| **Decryption** | Process that converts ciphertext → plaintext using the correct key. |
| **Confidentiality** | Property that only authorized parties can read the data (achieved by encryption). |
| **Integrity** | Assures data hasn’t been altered (hashes, MACs, digital signatures, AEAD modes). |
| **Authenticity** | Proves the sender/owner is who they claim (signatures, certificates/PKI). |
| **Symmetric encryption** | Same key for encrypt/decrypt; very fast; challenge is safe key distribution. |
| **Asymmetric encryption** | Public/private key pair; solves key exchange and enables signatures, slower than sym. |
| **DES** | Legacy 56-bit symmetric cipher; **insecure** today. |
| **3DES** | Triple-DES; legacy and deprecated for new designs—replace with AES. |
| **AES** | Modern symmetric standard (128/192/256-bit); widely used (TLS, disk/VPN). |
| **RSA** | Asymmetric system based on integer factorization; used for key exchange and signatures. |
| **Diffie-Hellman (DH)** | Key-agreement protocol to derive a shared secret over an insecure network (enables PFS when ephemeral). |
| **ECC** | Elliptic-curve cryptography; strong security with shorter keys (e.g., P-256). |
| **XOR (⊕)** | Bitwise “difference” operator; core building block in stream ciphers and pads. |
| **Modulo (mod)** | Remainder arithmetic (0…n-1); fundamental to RSA/DH/ECC math. |
| **Caesar cipher** | Simple letter shift; educational example, **not secure**. |
| **Vigenère** | Polyalphabetic substitution; historically important, broken by modern analysis. |
| **Enigma** | WWII rotor machine; historically significant, not secure by modern standards. |
| **One-time pad (OTP)** | Information-theoretically secure if key is truly random, as long as the message, and never reused; impractical key handling. |
| **PCI DSS** | Payment Card Industry standard; mandates strong crypto to protect cardholder data. |
| **HIPAA / GDPR / DPA** | Regulations that require protecting PHI/PII with appropriate crypto and controls. |
| **Public key** | The shareable half of an asymmetric pair; used to encrypt to you and to verify your signatures. |
| **Private key** | The secret half; used to decrypt and to create digital signatures—must be protected. |
| **Key exchange** | Any method to establish a shared symmetric key (e.g., DH inside TLS handshakes). |
| **Digital signature** | Private-key operation that binds identity and integrity; anyone can verify with the public key. |
| **Certificate / PKI** | X.509 cert binds an identity to a public key; PKI (CAs, chains, CRLs/OCSP) builds trust for TLS, code signing, etc. |
