# 🛡️ Windows Threat Detection 3 (C2, Persistence & Impact) — Reference Sheet

> **TL;DR:** This room covers the *late-stage* MITRE tactics an attacker uses **after** the initial breach: **Command & Control (C2)**, **Persistence**, and **Impact**. You learn how attackers stay resident on a Windows host (backdoor users, services, scheduled tasks, Startup folder, Run keys) and how to detect each one through **Sysmon** (Event IDs 1, 11, 13, 15, 22) and **Security/System** event logs (4625, 4697, 4698, 4720, 4724, 4732, 7045). The recurring skill is mapping *one event ID → one persistence technique* and proving an attack chain with **evidence, not guesswork**.

---

## 🔑 Master Event ID Cheat Sheet (the most important table)

| Event ID | Log Source | Meaning | What you use it for in this room |
|---|---|---|---|
| **1** | Sysmon | Process Create | Detect `sc.exe` / `schtasks.exe` launches; read `Image`, `ParentImage`, `ParentCommandLine` to prove execution context |
| **11** | Sysmon | File Create | Detect new files dropped into the **Startup folder** |
| **13** | Sysmon | Registry value set | Detect new **Run key** values (`TargetObject` shows the key name + path) |
| **15** | Sysmon | File stream created (ADS) | Detect downloaded archives; logs MD5/SHA256/IMPHASH + a `Contents` preview |
| **22** | Sysmon | DNS Query | Find the **C2 domain** AND the **process** that queried it (`Image` = the malware) |
| **4625** | Security | Failed logon | Count brute-force / failed login attempts |
| **4697** | Security | A service was installed | Detect malicious **service** persistence |
| **4698** | Security | A scheduled task was created | Detect malicious **scheduled task** persistence |
| **4720** | Security | A user account was created | Detect **backdoor user** creation |
| **4724** | Security | Password reset attempt | Detect account takeover via password reset |
| **4732** | Security | Member added to a security-enabled **local** group | Detect **privilege escalation** (e.g. adding user to Administrators) |
| **7045** | System | A service was installed | **Fallback** for service creation when 4697 auditing is off |

## ⚠️ Gotchas

| Gotcha | Detail |
|---|---|
| **Event ID 11 ≠ execution** | It logs file **creation** (the persistence *setup*), not the malware running. The actual launch appears later as Event ID **1**. "Placed/created" vs "ran" are different events. |
| **Parent is explorer.exe, not cmd.exe** | A Startup-folder script is *created* by `cmd.exe` but *launched* by `explorer.exe` at logon. The creating process is **not** the launching parent. The question asks for the **parent of execution** → `C:\Windows\explorer.exe`. |
| **Run key name lives in "Before Reboot" logs** | The Run key value name (Event ID **13**, `TargetObject`) is recorded when persistence is set, i.e. *before* reboot. "After Reboot" logs show **execution results** (Event ID 1), not the key name. |
| **Sysmon 22 `Image` = the C2 malware path** | The process that issued the DNS query *is* the malware. That's how you find where it was hidden (`AppData\Roaming\update.exe`). |
| **`Contents: PK` = ZIP file** | In an Event ID 15 (ADS) log, `PK` is the ZIP/PKZIP magic byte signature — confirms a ZIP archive even from the stream header. |
| **`QueryStatus: 9003` ≠ "no C2"** | 9003 = `DNS_INFO_NO_RECORDS` (lookup returned nothing). Common for dead/sinkholed C2 domains in labs. A failed DNS query still proves C2 *intent*. |
| **The 4732 log you open may show the wrong group** | There can be multiple 4732 events (e.g. one for `Users`, one for `Administrators`). The question wants the **privileged** group → **Administrators**, not whichever event opened first. |
| **Service creation has TWO event IDs** | Security **4697** *and* System **7045**. If 4697 auditing isn't enabled, pivot to 7045. |
| **Scheduled tasks > services in the wild** | Tasks are easier to hide/configure, so they are the **most common** persistence method (APT28, APT41). Don't only check services. |
| **Don't trust account names** | Attackers avoid "hacker" and use innocuous names like **support**. Investigate *who created it, from which IP, when* instead of pattern-matching the name. |
| **`AppData\Roaming` & `C:\Users\Public` are favorite hideouts** | User-writable, low visibility, used by legit apps. A name like `update.exe` mimics a real updater. |
| **`ServiceType 0x10` + `Start Type 2`** | `0x10` = own-process service; Start Type **2** = Automatic → runs at every boot. That combination is what makes the service *persistent*. |
| **Best detection stage = Initial Access** | Stop the chain early. By the time you see Impact (ransomware), it's too late. |
| **C2 isn't always required** | After an RDP breach an attacker can type commands live. C2 is what they add so access survives RDP being closed/secured. |

## 🛰️ Task 2 — Command and Control (C2)

**MITRE Tactic:** Command and Control. The channel an attacker uses to send commands and keep control of the victim 24/7.

| Concept | Detail |
|---|---|
| **Attacks without C2** | Type commands directly in an **RDP** session after an RDP breach. Lost the moment RDP is closed/secured. |
| **Simplest C2** | The phishing attachment *itself* becomes the process that connects back and waits for commands (e.g. **Cobalt Strike** beacon). |
| **Advanced C2** | Attachment downloads a *second-stage* C2 malware, hides it (e.g. `C:\Temp`, `AppData\Roaming`), and runs it as a stealthy new process — survives deletion of the original attachment. |

### Detection workflow (Sysmon)

| Step | Event ID | What it reveals |
|---|---|---|
| 1. Suspicious download | **15** (ADS file stream) | `TargetFilename` of the downloaded archive + hashes + `Contents: PK` (ZIP) |
| 2. Locate the C2 binary | **22** (DNS Query) | `Image` = full path of the process beaconing out = where the malware hides |
| 3. Identify the C2 server | **22** (DNS Query) | `QueryName` = the C2 domain |

**Worked evidence (from this room):**
```text
Event ID 15  (File stream / ADS)
  Image:          chrome.exe
  TargetFilename: C:\Users\Administrator\Downloads\URGENT!.zip
  Contents:       PK            # ZIP magic bytes

Event ID 22  (DNS Query)
  QueryName:   route.m365officesync.workers.dev   # C2 domain
  QueryStatus: 9003                                # DNS_INFO_NO_RECORDS
  Image:       C:\Users\Administrator\AppData\Roaming\update.exe  # C2 malware
```

| Q&A | Answer |
|---|---|
| Which suspicious archive did the user download? | **URGENT!.zip** |
| Where did the attackers hide the C2 malware file? | **C:\Users\Administrator\AppData\Roaming\update.exe** |
| What is the domain of the Command and Control server? | **route.m365officesync.workers.dev** |

## 👤 Task 3 — Persistence Overview (Backdoor Users)

| Concept | Detail |
|---|---|
| **Persistence (MITRE)** | Maintaining reliable, long-term access that **survives reboots and password changes**. |
| **Persist via RDP** | Re-access an exposed service repeatedly; often paired with an extra method: a backdoor/web shell, or a new admin user. |

### Commands — managing (backdoor) users

#### Create a user
**Purpose:** Add a local account the attacker controls.
```cmd
:: CMD
net user "mr.backd00r" "p@ssw0rd!" /add
# Creates local user "mr.backd00r" with the given password
```
```powershell
# PowerShell
New-LocalUser "mr.backd00r" -Password (Read-Host -AsSecureString)
# Equivalent PowerShell cmdlet for local user creation
```

#### Make the user an administrator
**Purpose:** Grant RDP login + admin rights (default users can't do either).
```cmd
:: CMD
net localgroup Administrators "mr.backd00r" /add
# Adds the account to the local Administrators group
```
```powershell
# PowerShell
Add-LocalGroupMember "Administrators" -Member "mr.backd00r"
# Same operation via cmdlet
```

### Detection event IDs (Security log)

| Action | Event ID |
|---|---|
| User account created | **4720** |
| Member added to privileged group | **4732** |
| Password reset (account takeover) | **4724** |

### Investigating a backdoored user (don't just look at the name)
1. **Who** created the account — can the person confirm it?
2. **Source IP + time** of the creator's login — expected?
3. **Other suspicious events** inside the creator's session?

**Worked evidence (from this room):**
```text
Event 4625 (failed logon, x6)
  Account Name:  Administrator        # targeted account
  Logon Type:    3 (network / NTLM)
  Status / Sub:  0xC000006D / 0xC000006A   # unknown user or bad password
  Source IP:     10.14.97.15          # attacker

Event 4720 (user created)
  Subject:     Administrator          # who created it
  New Account: support                # backdoor user

Event 4732 (added to group)
  Member: support → Group: Administrators   # privilege escalation
```

| Q&A | Answer |
|---|---|
| How many times did the threat actor fail to log in to the Administrator? | **6** |
| After the successful login, which backdoor user did the attacker create? | **support** |
| Which privileged group was the backdoor user added to? | **Administrators** |

**MITRE refs:** `T1505.003` (Web Shell), `T1136` (Create Account), `T1098.007` (Account Manipulation: Additional Local/Domain Groups).

## ⚙️ Task 4 — Persistence: Services & Scheduled Tasks

These run **after OS startup** and need administrative privileges.

| Method | Attack Example | Logging |
|---|---|---|
| **Windows Service** | `sc create "BadService" binpath= "C:\malware.exe" start= auto` | Launch of `sc.exe`: **Sysmon 1** · Service creation: **Security 4697** (or **System 7045**) |
| **Scheduled Task** | `schtasks /create /tn "BadTask" /tr "C:\malware.exe" /sc onstart /ru System` | Launch of `schtasks.exe`: **Sysmon 1** · Task creation: **Security 4698** |

### Three ways to detect a malicious **service**
1. `sc.exe create` launch → **Sysmon Event ID 1**
2. Service creation → **Security 4697** or **System 7045**
3. Suspicious process with a **`services.exe`** parent

### Three ways to detect a malicious **scheduled task**
1. `schtasks.exe /create` launch → **Sysmon Event ID 1**
2. Task creation → **Security 4698**
3. Suspicious process with a **`svchost.exe [...] -s Schedule`** parent

### Commands

#### Create a malicious service
**Purpose:** Run a binary automatically after every boot.
```cmd
sc create "BadService" binpath= "C:\malware.exe" start= auto
# NOTE the space after "binpath=" and "start=" — required by sc.exe syntax
# start= auto → starts at boot (persistence)
```

#### Create a malicious scheduled task
**Purpose:** Run a binary at startup, as SYSTEM.
```cmd
schtasks /create /tn "BadTask" /tr "C:\malware.exe" /sc onstart /ru System
# /sc onstart → trigger at boot   /ru System → run as SYSTEM (highest privilege)
```

**Worked evidence (from this room):**
```text
Event 4697 (service installed)  → persists "Nessie"
  Service Name:      Data Protection Service
  Service File Name: C:\Windows\Help\nessie.exe
  Service Type:      0x10        # own-process
  Service Start Type:2           # Automatic (boot)
  Service Account:   LocalSystem

Event 4698 (scheduled task)     → persists "Troy"
  Task Name:  \AmazonSync
  Trigger:    <BootTrigger>      # runs at startup
  Command:    "C:\Program Files\Common Files\troy.exe"
  Principal:  S-1-5-18           # SYSTEM
```

### Flag exercise — Troy
1. Find the task **AmazonSync** (Event 4698) → its `Action` points to `C:\Program Files\Common Files\troy.exe`.
2. Run `troy.exe`. It asks: *"What was my parent commandline?"*
3. Look up **Sysmon Event ID 1** (After Reboot) where `Image = ...\troy.exe`, read **`ParentCommandLine`**.
4. Answer with the verified value (not a guess):
   ```text
   C:\Windows\system32\svchost.exe -k netsvcs -p -s Schedule
   ```
   (Confirms the task was launched by the **Schedule** service under `svchost.exe`.)

| Q&A | Answer |
|---|---|
| Which Windows service was created to persist the Nessie malware? | **Data Protection Service** |
| Which scheduled task was created to persist the Troy malware? | **AmazonSync** |
| What flag do you get after finding and running the Troy malware? | **THM{c2_is_on_schedule!}** |

**MITRE ref:** `T1543.003` (Create or Modify System Process: Windows Service).

## 🚀 Task 5 — Persistence: Run Keys & Startup Folder

Per-user methods that run when a **specific user logs in** (no admin required). Both share one MITRE technique: **`T1547.001`**.

| Method | Attack Example | Logging |
|---|---|---|
| **Startup folder** | `copy C:\malware.exe "%AppData%\Microsoft\Windows\Start Menu\Programs\Startup\malware.exe"` | New startup item → **Sysmon Event ID 11** |
| **Run key** | `reg add "HKCU\Software\Microsoft\Windows\CurrentVersion\Run" /v BadKey /t REG_SZ /d "C:\malware.exe"` | New registry value → **Sysmon Event ID 13** |

### Key paths

| Scope | Startup Folder | Run Key |
|---|---|---|
| **Per-user** | `C:\Users\<USER>\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup\` | `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run` |
| **All users** | `C:\ProgramData\Microsoft\Windows\Start Menu\Programs\StartUp` | `HKEY_LOCAL_MACHINE\Software\Microsoft\Windows\CurrentVersion\Run` |

### Detection
- **Startup:** monitor file creation (**Sysmon 11**) inside the Startup path. Programs launched this way have an **`explorer.exe`** parent → hard to tell from legit user activity.
- **Run keys:** monitor registry value sets (**Sysmon 13**) on the `...\CurrentVersion\Run` key.

### Command — add a Run key
**Purpose:** Auto-run a binary at user logon via the registry.
```cmd
reg add "HKCU\Software\Microsoft\Windows\CurrentVersion\Run" /v BadKey /t REG_SZ /d "C:\malware.exe"
# /v = value NAME (what shows in Sysmon 13 TargetObject)
# /d = value DATA (the path that gets executed)
```

### Odin (Startup folder) — the explorer.exe chain
```text
Event 11 (file created)   ── the SETUP
  Image:          C:\Windows\system32\cmd.exe   # creator (not the launcher)
  TargetFilename: ...\Start Menu\Programs\Startup\odin.cmd

odin.cmd contents:
  @echo off
  powershell -Command "Write-Output 'Doing bad stuff...'; <loop of random 0/1>; Write-Output 'Done doing bad stuff!'"

Event 1 (process create) ── the EXECUTION (after logon)
  ParentImage:       C:\Windows\explorer.exe     # ← the answer
  ParentCommandLine: C:\Windows\Explorer.EXE
```
**Why `explorer.exe`?** `cmd.exe` only *dropped* `odin.cmd` into Startup. At the next logon, **Explorer** (the Windows shell) processes the Startup folder and launches it → so Odin's parent is `explorer.exe`. The "last output line" is read from the **script contents**, not the event log (stdout isn't in Sysmon).

### Kitten (Run key) — found via DNS, then registry
```text
Event 22 (DNS Query)
  QueryName: kitten-c2.apt057.thm
  Image:     C:\Users\Public\kitten.exe      # the malware path

Event 13 (registry value set)  ── look in "Before Reboot"
  RuleName:     T1060,RunKey
  Image:        C:\Windows\system32\reg.exe
  TargetObject: HKU\...\CurrentVersion\Run\Basket   # Run key NAME = Basket
  Details:      C:\Users\Public\kitten.exe
```
**Flag exercise:** run `kitten.exe`, it asks *"How is my Run key named?"* → answer **Basket** → flag.

| Q&A | Answer |
|---|---|
| What is the parent process image of the "Odin" malware? | **C:\Windows\explorer.exe** |
| What is the last line that the "Odin" malware outputs? | **Done doing bad stuff!** |
| What flag do you get after finding and running the "Kitten" malware? | **THM{persisting_in_basket!}** |

**MITRE refs:** `T1547.001` (Registry Run Keys / Startup Folder), legacy `T1060`.

## 💥 Task 6 — Impact & Threat Detection Recap

### Why attackers want Persistence
| Reason | Real-world example |
|---|---|
| Add host to a **botnet** | **Kraken Botnet** — combines crypto miner + data stealer + C2 |
| **Espionage** (state-sponsored) | **Volt Typhoon** — hid in the US electric grid for ~1 year |
| **Entry point** into a wider network | A full-network breach took attackers **29 days** |

### Active Directory & Ransomware
- A Windows network usually means a large **Active Directory** → the top threat is **ransomware**.
- Ransomware can halt entire companies (**McLaren** hospitals — 743,000 patients affected): encrypted servers, stolen data, ransom notes auto-printed.
- **Recap:** every complex attack starts from one simple breach → detect and stop it, ideally right at **Initial Access**, before Impact.

| Q&A | Answer |
|---|---|
| What is the biggest threat to most corporate Windows networks? | **Ransomware** |
| At which stage is it best to detect and stop the attack? | **Initial Access** |

## 🧭 Parent-Process Detection Signatures (quick recall)

| If you see a suspicious child of… | …suspect this persistence method |
|---|---|
| `services.exe` | Malicious **Windows service** |
| `svchost.exe ... -s Schedule` | Malicious **scheduled task** |
| `explorer.exe` | **Startup folder** (or Run key) launched at logon |
