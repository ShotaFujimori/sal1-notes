# 🦈 Wireshark: The Basics — Reference Sheet

> **TL;DR:** Wireshark is a GUI-based packet analyzer for live capture and PCAP inspection. Core workflow: load file → dissect packets across 7 layers → navigate/search/filter → export objects/streams. Display filters narrow visible packets without discarding them; capture filters limit what gets captured. Key operations: Follow Stream, Export Objects, Expert Info, Find Packet, Mark/Comment.

---

## ⚠️ Gotchas

| Gotcha | Detail |
|---|---|
| Wireshark ≠ IDS | It reads and displays packets only — no blocking, no alerting |
| Wireshark doesn't modify packets | Read-only — use it for analysis, not modification |
| Capture filter ≠ display filter | Capture filters restrict what is recorded; display filters restrict what is shown |
| Search pane must match content location | Searching "packet details" content in "packet list" pane returns no results |
| Marked packets are session-only | Marks are lost when the capture file is closed |
| Comments persist in the file | Unlike marks, comments are saved in the PCAP until manually removed |
| Export Objects works only for specific protocols | DICOM, HTTP, IMF, SMB, TFTP only |
| Time default is "Seconds Since Beginning of Capture" | Change to UTC for real-world timeline correlation |
| Expert Info shows false positives | Suggestions only — always verify before acting |
| Double-click opens packet in new window | Single-click selects; double-click opens details in separate window |
| Follow Stream auto-applies a filter | Remove it with the X button to restore full packet view |

## 1. Wireshark GUI Overview

### Five Main UI Sections
| Section | Description |
|---|---|
| **Toolbar** | Menus and shortcuts for sniffing, filtering, sorting, exporting, merging |
| **Display Filter Bar** | Main query and filter input field (`Ctrl+/` shortcut) |
| **Recent Files** | List of recently opened PCAPs — double-click to reopen |
| **Capture Filter & Interfaces** | Available network interfaces + capture filter input |
| **Status Bar** | Tool status, active profile, total/displayed packet counts |

### Three Packet Panes
| Pane | Shows | Notes |
|---|---|---|
| **Packet List** | Summary per packet: No., Time, Source, Dest, Protocol, Length, Info | Click to select a packet |
| **Packet Details** | Hierarchical protocol breakdown of selected packet | Expandable tree; click field to highlight in Bytes pane |
| **Packet Bytes** | Hex + decoded ASCII of selected packet | Highlights selected field from Details pane |

### Traffic Controls
| Button | Color | Action |
|---|---|---|
| Shark button | Blue | Start live capture (sniffing) |
| Stop button | Red | Stop capture |
| Restart button | Green | Restart capture |

## 2. File Operations

### Loading & Managing Files
| Action | Menu Path | Notes |
|---|---|---|
| Open PCAP | `File → Open` or drag-and-drop or double-click | Supports `.pcap`, `.pcapng` |
| Merge PCAPs | `File → Merge` | Select second file; save merged result before working on it |
| View file details | `Statistics → Capture File Properties` or pcap icon (bottom-left) | Shows hash, capture time, comments, interface, statistics |
| Export packets | `File → Export Specified Packets` | Saves a subset of packets to a new file |
| Export objects | `File → Export Objects → [Protocol]` | Extracts files from DICOM, HTTP, IMF, SMB, TFTP streams |

### Capture File Properties — Key Fields
| Field | Description |
|---|---|
| File hash (SHA256/MD5) | Used to verify file integrity and share with threat intel |
| Capture time | Start/end timestamps of the capture |
| Interface | Which NIC or interface was used for capture |
| File comments | Analyst notes embedded in the capture file |
| Total packets | Total number of packets in the file |

## 3. Packet Dissection — 7 Layers

### Packet Layer Breakdown (HTTP Packet Example)
| Layer | Wireshark Label | OSI Layer | Key Fields |
|---|---|---|---|
| 1 | **Frame** | Physical (L1) | Frame number, length, arrival time, encapsulation type, coloring rule |
| 2 | **Ethernet II (Source MAC)** | Data Link (L2) | Src/Dst MAC address, EtherType |
| 3 | **Internet Protocol (Source IP)** | Network (L3) | Src/Dst IP, TTL, Protocol, Fragment offset, Total length |
| 4 | **TCP/UDP (Protocol)** | Transport (L4) | Src/Dst port, Seq/Ack numbers, Flags, Window size, Checksum |
| 4+ | **Protocol Errors** | Transport (L4) | Reassembled TCP segments, segment count, reassembled length |
| 5 | **Application Protocol** | Application (L5) | HTTP headers, FTP commands, SMB requests — protocol-specific details |
| 5+ | **Application Data** | Application (L5) | Raw payload content (HTML, file bytes, etc.) |

### Layer 1 — Frame Fields
| Field | Description |
|---|---|
| Frame number | Wireshark-assigned packet number |
| Frame length | Total bytes on wire |
| Arrival time | Timestamp when packet was captured |
| Encapsulation type | e.g., Ethernet |
| Protocols in frame | e.g., `eth:ethertype:ip:tcp:http:data-text-lines` |
| Coloring rule | Which display filter triggered the color |

### Layer 3 — IP Header Fields
| Field | Description |
|---|---|
| Version | IPv4 or IPv6 |
| Header length | IP header size in bytes |
| Total length | Total IP packet size |
| TTL | Time to Live — hops remaining |
| Protocol | Transport protocol number (6=TCP, 17=UDP, 1=ICMP) |
| Src/Dst address | Source and destination IP |
| Fragment offset | Used in fragmentation attack detection |
| Flags | More Fragments (MF), Don't Fragment (DF) |

### Layer 4 — TCP Header Fields
| Field | Description |
|---|---|
| Source port | Sending port |
| Destination port | Receiving port |
| Sequence number | Position in byte stream (used for session hijacking detection) |
| Acknowledgment number | Next expected byte from peer |
| Flags | SYN, ACK, PSH, FIN, RST, URG |
| Window size | Receiver buffer size |
| Checksum | Error detection |

## 4. Packet Coloring

### Coloring Rule Types
| Type | Persistence | How to Create |
|---|---|---|
| **Permanent** | Saved in profile — survives restart | `View → Coloring Rules` or right-click menu |
| **Temporary** | Session only — lost on close | `View → Conversation Filter` or right-click menu |

### Default Color Legend
| Color | Meaning |
|---|---|
| Green | HTTP traffic |
| Dark blue | DNS traffic |
| Light blue | UDP traffic |
| Black | TCP errors / RST packets |
| Light purple | TCP traffic |
| Yellow | Windows-specific traffic (SMB, NetBIOS) |
| Dark red | Routing protocols |

### Colourise Conversation
| Feature | Description |
|---|---|
| **Colourise Conversation** | Highlights related packets by color without applying a filter |
| **Conversation Filter** | Hides unrelated packets — reduces displayed count |
| **Reset** | `View → Colourise Conversation → Reset Colourisation` |

## 5. Packet Navigation

### Navigation Methods
| Action | Menu / Shortcut | Description |
|---|---|---|
| Go to packet by number | `Go → Go to Packet` | Jump directly to a specific packet number |
| First/Last packet | Toolbar buttons | Jump to start or end of capture |
| Previous/Next packet | Toolbar buttons | Step through packets one at a time |
| Find packet | `Edit → Find Packet` (`Ctrl+F`) | Search by content, filter, hex, string, or regex |

### Find Packet — Search Options
| Input Type | When to Use | Notes |
|---|---|---|
| **Display filter** | Filter-based search | Use standard Wireshark filter syntax |
| **Hex** | Raw byte-level search | Enter hex values |
| **String** | Plain text content search | Case-insensitive by default |
| **Regex** | Pattern-based search | Regular expression syntax |

### Find Packet — Pane Selection (Critical)
| Search Pane | Contains | If Wrong Pane: |
|---|---|---|
| **Packet List** | Summary info (protocol, src/dst, info column) | Won't find content only in Packet Details |
| **Packet Details** | Full protocol field values | Won't find raw byte-level content |
| **Packet Bytes** | Raw hex/ASCII payload | Won't find protocol field names |

### Packet Annotation Features
| Feature | Persistence | How to Access | Color When Applied |
|---|---|---|---|
| **Mark packet** | Session only (lost on close) | `Edit` menu or right-click | Black |
| **Comment packet** | Permanent (saved in file) | `Edit` menu or right-click | Shown in Packet Details |

### Export Options
| Feature | Menu Path | Protocols Supported |
|---|---|---|
| **Export Packets** | `File → Export Specified Packets` | All (saves packet subset as new file) |
| **Export Objects** | `File → Export Objects → [Protocol]` | DICOM, HTTP, IMF, SMB, TFTP only |

### Time Display Options
| Format | When to Use | Menu Path |
|---|---|---|
| Seconds since beginning | Default — relative timing | — |
| **UTC** | Real-world timeline correlation | `View → Time Display Format → UTC Date and Time of Day` |
| Date and time of day | Human-readable timestamps | `View → Time Display Format` |

## 6. Expert Info

### Severity Levels
| Severity | Color | Meaning | Example |
|---|---|---|---|
| **Chat** | Blue | Normal workflow information | HTTP GET/200 sequences |
| **Note** | Cyan | Notable events | TCP retransmission, app error codes |
| **Warn** | Yellow | Unusual errors or problem statements | Unusual error codes |
| **Error** | Red | Serious problems | Malformed packets, checksum errors |

### Expert Info Groups
| Group | Description |
|---|---|
| **Checksum** | Checksum errors in packets |
| **Comment** | Packet comment detection |
| **Deprecated** | Deprecated protocol usage detected |
| **Malformed** | Malformed packet detection |

## 7. Packet Filtering

### Two Filter Types
| Type | When Applied | Affects | Use Case |
|---|---|---|---|
| **Capture filter** | Before/during capture | What gets recorded | Limit capture size; target specific hosts/protocols |
| **Display filter** | After capture | What is shown | Investigate without discarding data |

### Display Filter Methods
| Method | How | Applies Filter? |
|---|---|---|
| **Apply as Filter** | Right-click field → Apply as Filter | ✅ Immediately |
| **Prepare as Filter** | Right-click field → Prepare as Filter | ❌ Adds to bar, waits for Enter |
| **Conversation Filter** | Right-click → Conversation Filter | ✅ Shows only conversation packets |
| **Colourise Conversation** | Right-click → Colourise Conversation | ❌ Colors without filtering |
| **Apply as Column** | Right-click → Apply as Column | N/A — adds field as visible column |
| **Follow Stream** | Right-click → Follow TCP/UDP/HTTP Stream | ✅ Shows full stream in dialog |

### Display Filter — Quick Reference
```
# Protocol name filters
http
dns
tcp
udp
arp
ftp
smtp
smb
tls

# Port-based filters
tcp.port == 80          # HTTP
tcp.port == 443         # HTTPS
tcp.port == 22          # SSH
udp.port == 53          # DNS
tcp.port == 25          # SMTP

# IP address filters
ip.addr == 192.168.1.1           # Any direction
ip.src == 192.168.1.1            # Source only
ip.dst == 192.168.1.1            # Destination only

# MAC address filter
eth.addr == 00:11:22:33:44:55

# Combined filters
ip.addr == 192.168.1.1 && tcp.port == 80
http || dns
!(arp)                           # Exclude ARP
```

### Follow Stream — Color Coding
| Color | Meaning |
|---|---|
| **Red** | Packets originating from the **client** |
| **Blue** | Packets originating from the **server** |

### Follow Stream — Access Path
```
# Method 1: Right-click menu
Right-click packet → Follow → TCP Stream / UDP Stream / HTTP Stream

# Method 2: Menu bar
Analyse → Follow TCP/UDP/HTTP Stream

# Remove stream filter after following:
Click X button on the right side of the display filter bar
```

### Apply as Column
```
# Add any packet field as a visible column:
Right-click a field in Packet Details → Apply as Column
# Toggle column visibility: click on column header area at top of Packet List
```
