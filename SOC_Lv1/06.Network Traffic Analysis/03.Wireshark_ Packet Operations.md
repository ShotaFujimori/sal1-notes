# 🦈 Wireshark: Packet Operations — Reference Sheet

> **TL;DR:** Wireshark's Statistics menus provide a high-level summary of pcap files (resolved addresses, protocol hierarchy, conversations, endpoints, DNS, HTTP). Packet filtering uses two modes — **Capture Filters** (BPF syntax, set before capture) and **Display Filters** (Wireshark syntax, changeable anytime). Advanced filters (`contains`, `matches`, `in`, `upper`, `lower`, `string`) enable deep packet-level investigation.

---

## ⚠️ Gotchas

| Gotcha | Detail |
|---|---|
| `!=value` is deprecated | Use `!(value)` style instead — e.g. `!(ip.src == 10.10.10.222)`. The `!=` form can give inconsistent results. |
| Capture filters ≠ Display filters | Completely different syntax. You **cannot** use display filter expressions for capture and vice versa. |
| `ip.addr` vs `ip.src`/`ip.dst` | `ip.addr` matches in **either** direction. `ip.src`/`ip.dst` only matches in a specific direction. |
| Resolved Addresses hostname source | Hostnames come from **DNS answers in the capture file** — not from live DNS lookups. |
| GeoIP requires extra setup | Not enabled by default. Needs MaxMind DB files + path configured under Edit → Preferences → Name Resolution → MaxMind database directories. |
| IP/Port name resolution is off by default | Must enable manually: Edit → Preferences → Name Resolution. MAC address resolution is on by default. |
| `matches` is case-insensitive, `contains` is case-sensitive | Important for server/header searches. |
| Yellow filter bar = warning, not error | The filter works but may be unreliable. Green = valid, Red = invalid. |
| Capture filters sniff at wire level | Only use them if you know exactly what traffic pattern to match — missed packets are **gone**. |
| `string()` needed for numeric-field regex | You can't apply `matches` directly to integer fields like `frame.number` — wrap with `string()` first. |

## 📊 Statistics Menu Overview

| Menu Item | Purpose | Path |
|---|---|---|
| Resolved Addresses | Lists IP↔hostname mappings (from DNS answers in capture) | Statistics → Resolved Addresses |
| Protocol Hierarchy | Tree view of all protocols with packet counts & % | Statistics → Protocol Hierarchy |
| Conversations | Traffic between two endpoints (Ethernet/IPv4/IPv6/TCP/UDP) | Statistics → Conversations |

| HTTP | HTTP breakdown: request/response codes, request sequences | Statistics → HTTP |

## 🗂️ Statistics Details

### Resolved Addresses
- Lists IPs and DNS names from the capture
- Hostnames are sourced from **DNS answers**, not real-time resolution
- Tabs: Hosts / Ports / Capture File Comments

### Protocol Hierarchy
- Displays protocols in a **tree** with packet counters and byte percentages
- Right-click any row to apply as a filter

### Conversations
- 5 base formats: **Ethernet, IPv4, IPv6, TCP, UDP**
- Shows bytes transferred in both directions
- "Follow Stream" button available in TCP tab

### Endpoints
- Similar to Conversations, but shows unique single-endpoint stats
- Enable **Name Resolution** (lower-left checkbox) to resolve MACs → manufacturer names
- MAC resolution uses first 3 bytes via IEEE database

### GeoIP Mapping
- Requires MaxMind DB files (not included by default)
- Wireshark supports MaxMind DB resolver (latest versions pre-configured)
- Setup: Edit → Preferences → Name Resolution → MaxMind database directories
- Shows country/city/AS org in Endpoints and packet details
- **Note: Active internet connection required to view the map in browser**

## 🔍 Filter Types Comparison

| | Capture Filter | Display Filter |
|---|---|---|
| **Purpose** | Save only specific traffic to file | Narrow visible packets for analysis |
| **When set** | Before capture starts | Any time (changeable during capture) |
| **Changeable?** | ❌ No | ✅ Yes |
| **Syntax** | BPF (byte offsets, hex, masks) | Wireshark protocol syntax |
| **Protocols supported** | Limited | 3000+ |
| **Quick reference** | Capture → Capture Filters | Analyse → Display Filters |

## 🛠️ Capture Filter Syntax

| Component | Options |
|---|---|
| **Scope** | `host`, `net`, `port`, `portrange` |
| **Direction** | `src`, `dst`, `src or dst`, `src and dst` |
| **Protocol** | `ether`, `wlan`, `ip`, `ip6`, `arp`, `rarp`, `tcp`, `udp` |

```bash
tcp port 80          # Capture only TCP port 80 traffic
host 10.10.10.100    # Capture traffic to/from this host
net 192.168.1.0/24   # Capture subnet traffic
```

## 🛠️ Display Filter Syntax

### Comparison Operators

| English | C-Like | Description | Example |
|---|---|---|---|
| `eq` | `==` | Equal | `ip.src == 10.10.10.100` |
| `ne` | `!=` | Not equal (use `!()` form) | `!(ip.src == 10.10.10.100)` |
| `gt` | `>` | Greater than | `ip.ttl > 250` |
| `lt` | `<` | Less than | `ip.ttl < 10` |
| `ge` | `>=` | Greater than or equal | `ip.ttl >= 0xFA` |
| `le` | `<=` | Less than or equal | `ip.ttl <= 0xA` |

### Logical Operators

| English | C-Like | Example |
|---|---|---|
| `and` | `&&` | `(ip.src == 10.10.10.100) AND (ip.dst == 10.10.10.111)` |
| `or` | `\|\|` | `(ip.src == 10.10.10.100) OR (ip.src == 10.10.10.111)` |
| `not` | `!` | `!(ip.src == 10.10.10.222)` |

### Filter Bar Color Coding

| Color | Meaning |
|---|---|
| 🟢 Green | Valid filter |
| 🔴 Red | Invalid filter |
| 🟡 Yellow | Warning — works but unreliable; replace with valid filter |

## 🌐 Protocol Filters Quick Reference

### IP Filters

| Filter | Description |
|---|---|
| `ip` | Show all IP packets |
| `ip.addr == 10.10.10.111` | All packets containing this IP (either direction) |
| `ip.addr == 10.10.10.0/24` | All packets from/to this subnet |
| `ip.src == 10.10.10.111` | Packets **originating from** this IP |
| `ip.dst == 10.10.10.111` | Packets **sent to** this IP |

### TCP/UDP Filters

| Filter | Description |
|---|---|
| `tcp.port == 80` | All TCP packets on port 80 |
| `udp.port == 53` | All UDP packets on port 53 |
| `tcp.srcport == 1234` | TCP packets originating from port 1234 |
| `tcp.dstport == 80` | TCP packets sent to port 80 |
| `udp.srcport == 1234` | UDP packets from port 1234 |
| `udp.dstport == 5353` | UDP packets to port 5353 |

### HTTP Filters

| Filter | Description |
|---|---|
| `http` | All HTTP packets |
| `http.response.code == 200` | HTTP 200 OK responses |
| `http.request.method == "GET"` | HTTP GET requests |
| `http.request.method == "POST"` | HTTP POST requests |

### DNS Filters

| Filter | Description |
|---|---|
| `dns` | All DNS packets |
| `dns.flags.response == 0` | DNS requests (queries) |
| `dns.flags.response == 1` | DNS responses |
| `dns.qry.type == 1` | DNS type A records |

## 🔬 Advanced Filters

### `contains` — Case-sensitive substring match

```wireshark
http.server contains "Apache"
# Finds HTTP packets where the server field contains "Apache"
```

| | |
|---|---|
| **Type** | Comparison Operator |
| **Case-sensitive** | ✅ Yes |
| **Use case** | Find exact keyword in a specific field |

---

### `matches` — Regex pattern match

```wireshark
http.host matches "\.(php|html)"
# Finds HTTP packets where host field matches .php or .html
```

| | |
|---|---|
| **Type** | Comparison Operator |
| **Case-sensitive** | ❌ No (case-insensitive) |
| **Use case** | Find patterns; complex queries may have margin of error |

---

### `in` — Set membership

```wireshark
tcp.port in {80 443 8080}
# Finds TCP packets on port 80, 443, or 8080
```

| | |
|---|---|
| **Type** | Set Membership |
| **Use case** | Filter multiple values for one field without chaining OR |

---

### `upper()` — Convert to uppercase then filter

```wireshark
upper(http.server) contains "APACHE"
# Case-insensitive server search by normalizing to uppercase
```

---

### `lower()` — Convert to lowercase then filter

```wireshark
lower(http.server) contains "apache"
# Case-insensitive server search by normalizing to lowercase
```

---

### `string()` — Convert numeric field to string for regex

```wireshark
string(frame.number) matches "[13579]$"
# Finds all frames with odd frame numbers
```
