# Elastic Stack: The Basics — Quick Cheat Sheet

## TL;DR

* **Elasticsearch** = stores, searches, analyzes data
* **Logstash** = ingests, filters, normalizes, forwards data
* **Beats** = lightweight agents that ship data from endpoints
* **Kibana** = search, investigate, visualize, dashboard
* Main flow: **Beats → Logstash → Elasticsearch → Kibana** 

---

## 1) Core Components

### Elasticsearch

**Role:** Search + analytics engine for JSON documents.

**Example command**

```bash
curl -X GET "http://localhost:9200/_cat/indices?v"
```

**Explanation:**
Lists indices stored in Elasticsearch.

**Concrete example**

```bash
curl -X GET "http://localhost:9200/vpn_connections/_search?q=UserName:Suleman"
```

---

### Logstash

**Role:** Collects data, filters/normalizes it, sends it onward.

**Config structure**

```conf
input { ... }
filter { ... }
output { ... }
```

**Explanation:**

* `input` = source
* `filter` = parse/normalize
* `output` = destination

**Concrete example**

```conf
input { beats { port => 5044 } }
filter { }
output { elasticsearch { hosts => ["localhost:9200"] } }
```



---

### Beats

**Role:** Host-based data shippers.

**Example command**

```bash
filebeat -e
```

**Explanation:**
Runs Filebeat in foreground and ships logs.

**Concrete example**

```bash
winlogbeat.exe -e
```

**Use case:**
Send Windows Event Logs to Elasticsearch / Logstash. 

---

### Kibana

**Role:** Front-end for searching, investigating, and visualization.

**Example action/query**

```kql
UserName : Suleman
```

**Explanation:**
Searches logs where `UserName` equals `Suleman`.

**Concrete example**

```kql
Source_ip : 238.163.231.224 AND UserName : Suleman
```

## 3) KQL Quick Reference

### Free Text Search

```kql
"United States"
```

**Explanation:**
Finds logs containing the full term anywhere.

**Concrete example**

* Returns logs containing **United States**.
* The PDF notes this returned **2304 hits** in the example. 

---

### Wildcard Search

```kql
United*
```

**Explanation:**
Matches terms starting with `United`.

**Concrete example**

* Matches **United States** (and would also match **United Nations** if present). 

---

### AND

```kql
"United States" AND "Virginia"
```

**Explanation:**
Both terms must exist.

**Concrete example**

* Narrows results to U.S. logs mentioning **Virginia**. 

---

### OR

```kql
"United States" OR "England"
```

**Explanation:**
Either term can exist.

**Concrete example**

* Shows logs containing either country. 

---

### NOT

```kql
"United States" AND NOT ("Florida")
```

**Explanation:**
Includes U.S. logs but excludes Florida.

**Concrete example**

* Useful for excluding known-noisy values. 

---

### Field-Based Search

```kql
Source_ip : 238.163.231.224
```

**Explanation:**
Uses `Field : Value` format.

**Concrete example**

```kql
Source_ip : 238.163.231.224 AND UserName : Suleman
```

**Steps**


**Concrete example**

---

## Gotchas

* **Wrong index pattern = no useful data.** Use `vpn_connections` in this lab.
* **KQL matches full words by default.** `United` alone may return nothing; use `United*`.
* **Field syntax matters.** Use `Field : Value`, not random punctuation chaos.
* **Don’t forget to save** visualizations and dashboards, or they vanish into the void.
