# 59.SLA1 — Introduction to SIEM — Cheat Sheet

**Focus:** Understanding how Security Information and Event Management (SIEM) systems centralize, normalize, and correlate logs to detect threats.

## TL;DR

* 
**The Problem:** Networks generate thousands of logs across scattered devices, making manual analysis impossible and hiding the broader context of attacks.


* 
**The Solution:** A SIEM centralizes data from all sources, standardizes the formatting (Normalization), and looks for relationships between events (Correlation).


* 
**The Output:** It uses logical detection rules to trigger real-time alerts and displays data on analysts' dashboards.



---

## 1. Log Source Types

**Concept:** Devices are generally split into two categories based on what they monitor.

* 
**Host-Centric Logs:** Events occurring within a specific machine (e.g., Windows, Linux).


* 
*Examples:* File access, user authentication, process execution, registry key edits, and PowerShell execution.




* 
**Network-Centric Logs:** Events generated when hosts communicate across the network or internet (e.g., Firewalls, Routers, IDS/IPS).


* 
*Examples:* SSH connections, FTP file access, web traffic, and VPN activity.





---

## 2. Linux & Windows Log Locations

**Concept:** Before logs get to the SIEM, they are generated locally. Here is where common logs reside.

| OS / App | Command / Location | Explanation |
| --- | --- | --- |
| **Windows** | `Event Viewer` | Windows records events and assigns a unique Event ID to each activity.

 |
| **Linux (Web)** | `cat /var/log/httpd` or `/var/log/apache` | Stores HTTP requests, responses, and error logs.

 |
| **Linux (Tasks)** | `cat /var/log/cron` | Stores events related to scheduled cron jobs.

 |
| **Linux (Auth)** | `cat /var/log/auth.log` or `/var/log/secure` | Stores authentication and login-related logs.

 |
| **Linux (Core)** | `cat /var/log/kern` | Stores kernel-related events.

 |

## 3. Log Ingestion Methods

**Concept:** How the SIEM actually pulls the data from the endpoints.

* 
**Agent / Forwarder:** A lightweight tool installed directly on the endpoint that captures and sends logs (e.g., Splunk Forwarder).


* 
**Syslog:** A standard protocol used to send real-time data from web servers and databases to a centralized destination.


* 
**Port-Forwarding:** The SIEM listens on a specific port, and endpoints forward data directly to it.


* 
**Manual Upload:** Ingesting offline structured data (like a .CSV file) for quick, localized analysis.



---

## 4. Detection Rules & Alerting

**Concept:** Detection rules are logical expressions designed to catch threats. When conditions are met, an alert triggers.

### Action: Detect Log Clearing

* 
**Rule Logic:** `If Log source is WinEventLog AND EventID is 104` $\rightarrow$ `Trigger Alert`.


* 
**Explanation:** Event ID 104 is generated whenever a user tries to remove or clear event logs, which adversaries do to hide their tracks.



### Action: Detect Suspicious Discovery Commands

* 
**Rule Logic:** `If Log Source is WinEventLog AND EventCode is 4688 AND NewProcessName contains whoami` $\rightarrow$ `Trigger Alert`.


* **Explanation:** Event ID 4688 logs process execution. Adversaries often run `whoami` after privilege escalation to confirm their new permissions.



---

## 5. Post-Alert Investigation Actions

Once an alert triggers, you must investigate the associated events to determine the verdict:

* 
**If False Positive:** Tune the detection rule to prevent similar benign alerts from triggering in the future.


* 
**If True Positive:** * Perform further investigation.


* Contact the asset owner to inquire about the activity.


* Isolate the infected host.


* Block the suspicious IP address.





---

## Gotchas & Pitfalls

* 
**The "Harmless" Log Trap:** A single log showing a user accessing a file might look normal (Limited Context). However, SIEM correlation might reveal that this file access happened immediately after an unusual VPN login and right before a massive outbound network connection (Data Exfiltration).


* 
**Parsing Failures:** Different logs come in different sizes and formats (Format Issues). If logs are not properly parsed (broken down into fields) and normalized (converted into one consistent format), your detection rules will fail to trigger.
