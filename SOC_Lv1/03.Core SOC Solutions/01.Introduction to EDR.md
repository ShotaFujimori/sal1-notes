
# 58.SAL1 — Introduction to EDR — Exam Cheat Sheet

**Focus:** Understanding EDR fundamentals, architecture, telemetry collection, detection techniques, and response capabilities for endpoint security.

---

## TL;DR

EDR provides deep-level endpoint protection through three pillars: Visibility (detailed telemetry collection), Detection (behavioral and signature-based analysis), and Response (automated and manual threat containment). EDR agents deployed on endpoints monitor all activities and send telemetry to a central console where correlation, machine learning algorithms, and threat intelligence matching detect advanced threats. Unlike traditional antivirus that relies primarily on signature-based detection, EDR monitors complete behavior chains, detects fileless malware, identifies anomalies from baseline behavior, and enables analysts to take immediate response actions including host isolation, process termination, file quarantine, remote access, and artifact collection. EDR is a host-only security solution that does not detect network-level threats and works best when integrated with SIEM and other security tools for comprehensive protection.

---

## EDR Definition and Core Purpose

EDR is a security solution designed to monitor, detect, and respond to advanced threats at the endpoint level. It provides deep-level protection for endpoints regardless of location, ensuring constant monitoring even when devices operate outside organizational network perimeter protection. This capability is critical in the modern remote work environment where traditional network-based security controls cannot protect devices operating from home networks, coffee shops, or other external locations.

**Popular EDR Solutions:** CrowdStrike Falcon, SentinelOne ActiveEDR, Microsoft Defender for Endpoint, OpenEDR, Symantec EDR. While underlying architectures are mostly similar across vendors, specific features and capabilities may vary.

---

## Three Pillars of EDR

EDR functionality revolves around three core features that work together to provide comprehensive endpoint security.

### Pillar 1: Visibility

Visibility provides the complete context necessary for effective analysis and detection. EDR collects detailed data from endpoints including process modifications, registry modifications, file and folder modifications, user actions, and much more. This information is presented in structured formats enabling analysts to view complete process trees with activity timelines showing the sequence of actions. Historical data for any endpoint remains accessible for threat hunting and forensic investigation purposes. Every detection in EDR arrives with full contextual information.

**Process Tree Visualization:** Graphical representation shows which processes spawned on the endpoint with each node representing a process and connecting lines representing parent-child relationships. Clicking the plus icon on each process reveals all network connections, registry changes, and file changes associated with that process.

**Lab Example:** In the process tree visualization, cmd.exe spawned sc.exe as a child process, indicating potential service manipulation activity.

---

### Pillar 2: Detection

Detection capabilities surpass traditional antivirus by incorporating both signature-based and behavior-based detection methods. EDR identifies unexpected user activities and uses machine learning to detect deviations from baseline behavior, instantly flagging anomalies. It detects fileless malware residing in memory and allows feeding custom IOCs for threat detection. Detections are mapped to MITRE ATT&CK framework providing tactical and technical context.

**Detection Dashboard:** Shows all detections across different endpoints with each row containing severity level, time, triggering file, hostname, username, and MITRE Tactic via Technique field mapping. Clicking any detection reveals rich details supporting SOC analyst investigation.

**Detection Techniques:**
- **Behavioral Detection:** Observes complete file behavior rather than just signature matching
- **Anomaly Detection:** Flags activity deviating from established endpoint baseline
- **IOC Matching:** Compares activity against threat intelligence feeds
- **MITRE ATT&CK Mapping:** Maps detections to attack tactics and techniques
- **Machine Learning:** Identifies complex attack patterns that bypass traditional detection

---

### Pillar 3: Response

Response capabilities empower analysts to take action on detected threats from any endpoint within the central EDR console. Analysts can isolate complete endpoints, terminate processes, quarantine files, connect remotely to hosts, or execute independent actions all from within the EDR console.

**Available Response Actions:**
- **Isolate Host:** Disconnects endpoint from network to contain lateral movement
- **Terminate Process:** Stops specific malicious processes without full isolation
- **Quarantine:** Moves malicious files to isolated location preventing execution
- **Remote Access:** Connects to endpoint shell for deeper investigation
- **Artifact Collection:** Extracts memory dumps, event logs, folder contents, registry hives

**Remote Access Example:** CrowdStrike Falcon RTR (Real Time Response) console allows analysts to remotely access endpoint shell and run commands and scripts for custom response actions.

## EDR vs Antivirus Comparison

Both solutions protect endpoints but differ significantly in protection depth and detection sophistication.

**Airport Analogy:** Antivirus functions like immigration passport checks matching travelers against known criminal databases and blocking entry on matches. EDR functions like security officers stationed inside the airport with CCTV monitoring and motion sensors, continuously watching behavior even for travelers who passed immigration. EDR detects suspicious behavior patterns like roaming near restricted areas or leaving bags unattended that immigration checks would miss.

### Attack Scenario Comparison

A six-step attack scenario demonstrates how EDR detects threats that traditional antivirus misses.

**Attack Chain:**
1. User receives phishing email with malicious Word document containing VBA macro
2. User downloads and opens the document
3. Malicious macro executes silently spawning PowerShell
4. Obfuscated PowerShell command downloads sophisticated second-stage payload
5. Payload injects into legitimate svchost.exe process
6. Attacker gains remote access to system

**Response Comparison:**

| Attack Step | Antivirus Response | EDR Response |
|-------------|-------------------|--------------|
| Step 1 | Does nothing if file has no previous signature | Logs file download activity and monitors |
| Step 2 | Does nothing since winword.exe is legitimate | Records winword.exe execution and monitors |
| Step 3 | Does nothing if macro has no signature | Detects and flags unusual parent-child relationship (winword.exe spawning PowerShell.exe) |
| Step 4 | Typically does not detect obfuscated PowerShell | Flags obfuscated script execution |
| Step 5 | Does not monitor memory injections | Detects process injection in svchost.exe |
| Step 6 | Lacks network visibility | Flags unexpected svchost.exe outbound connection |
| **Final Action** | **May mark as clean** | **Generates alert with full attack chain** |

**Lab Example:** In the attack scenario, the legitimate process hijacked by the attacker was svchost.exe through process injection technique.

## EDR Architecture Components

### EDR Agents (Sensors)

Agents deployed inside endpoints function as the eyes and ears of EDR, monitoring all activities and sending detailed information to the central console in real time. Agents perform basic signature-based and behavior-based detections independently before sending results to the console where alerts are triggered. These lightweight agents run continuously on endpoints collecting telemetry without significantly impacting system performance.

---

### EDR Console

The central brain receives all detailed data from agents and performs correlation and analysis using complex logic and machine learning algorithms. Threat intelligence information is matched against collected data. The console connects all dots to form detections presented as alerts. The dashboard provides holistic views of detection status across all endpoints with severity classifications (Critical, High, Medium, Low, Informational) enabling priority-based investigation.

**Post-Detection Workflow:** SOC analysts acknowledge alerts and prioritize based on EDR-assigned severities. Clicking alerts reveals complete details including executed files, processes, network connections, and registry modifications. Analysts determine whether alerts are False Positives or True Positives using their expertise and available data, then take appropriate actions from within the EDR console.

---

## EDR Telemetry Types

Telemetry is the comprehensive data collected from endpoints representing the black box containing everything necessary for detection and investigation.

**Collected Telemetry Categories:**

**Process Executions and Terminations** track all running and idle processes, identifying suspicious child-parent relationships, suspicious executables initiating processes, and malware payloads.

**Network Connections** monitor all endpoint network activity, identifying C2 server connections, unusual port usage, data exfiltration attempts, and lateral movement within networks.

**Command Line Activity** captures all commands executed in CMD, PowerShell, and other shells, identifying malicious command execution and obfuscated PowerShell scripts often missed by traditional antivirus.

**Files and Folders Modifications** track changes occurring during data staging, ransomware execution, and malicious file dropping by threat actors.

**Registry Modifications** monitor Windows registry changes which are goldmines of configuration information. Many malicious activities involve registry modifications detected by EDR.

**Lab Examples:**
- Network Connections telemetry helps detect C2 communications
- Windows configuration settings are primarily stored in the registry
- Telemetry enables analysts to understand full event chains, identify root causes, and reconstruct attack timelines

## Advanced Detection Techniques

### Behavioral Detection

Observes complete file behavior rather than just matching signatures with known threats. Advanced threats craft malware to appear clean and use legitimate processes for attacks. EDR catches suspicious behavior patterns.

**Example:** Process winword.exe spawning PowerShell.exe gets flagged due to unusual parent-child relationship indicating Word document with malicious macro.

---

### Anomaly Detection

EDR learns baseline behavior of endpoints over time. Any activity deviating from this baseline gets flagged. This detects malicious activity causing behavioral deviations but can generate false positives. Full context enables analysts to identify legitimacy.

**Example:** Process modifying auto-start registry key on endpoint where this is uncommon behavior triggers anomaly detection.

---

### IOC Matching

EDR integrates with threat intelligence feeds. Except for zero-day attacks, most attacks have published indicators. EDR flags activity matching known IOCs instantly.

**Example:** User downloads file dropping an executable. When executable hash matches threat intelligence feed for known attack tool, EDR flags it immediately.

---

### MITRE ATT&CK Mapping

Flagged activities are mapped to MITRE tactics and techniques showing attack stages. This helps analysts understand attacker objectives and methods.

**Example:** EDR detects scheduled task creation and maps it to:
- **Tactic:** Persistence
- **Technique:** Scheduled Task/Job

---

### Machine Learning Algorithms

Advanced threat actors evade defenses making activities sometimes bypass advanced detection techniques. ML models trained on large datasets of normal and malicious behaviors detect complex attack patterns.

**Example:** Fileless attacks and multi-staged intrusions where individual actions are not inherently malicious but the ML algorithm identifies the complete activity chain as malicious.

---

## Response Capabilities Reference

### Isolate Host

Disconnects endpoint from network through EDR console. Most effective for containing malicious activity. Attacks typically start from single endpoints and move laterally to compromise entire networks. Timely isolation prevents lateral movement.

**Use Case:** When critical systems cannot be isolated due to business operations, use alternative response methods.

---

### Terminate Process

Stops specific processes without full host isolation. Appropriate when isolation would cause excessive business disruption. Analysts can terminate any process anytime from EDR console.

**Warning:** Terminating legitimate processes can disrupt endpoint operations. This action requires careful consideration.

---

### Quarantine

Moves malicious files to isolated locations preventing execution. Analysts can review quarantined files to restore or permanently remove them.

---

### Remote Access

Analysts remotely access endpoint shells when EDR built-in response is insufficient. Enables deeper visibility and custom actions within endpoints. Analysts can run scripts or collect desired data through remote access.

---

### Artifacts Collection

Extracts data from endpoints for detailed forensic investigation or legal reporting without physical device access.

**Commonly Extracted Artifacts:**
- Memory Dump
- Event Logs  
- Specific Folder Contents
- Registry Hives

## Critical Exam Points

EDR provides deep-level endpoint protection through three pillars: Visibility, Detection, and Response. EDR agents monitor endpoints and send telemetry to central console where detection occurs. Unlike antivirus relying on signature-based detection, EDR monitors behavior chains, detects fileless malware, identifies anomalies, and enables immediate response actions. Detection techniques include behavioral detection, anomaly detection, IOC matching, MITRE ATT&CK mapping, and machine learning algorithms. Response capabilities include host isolation, process termination, file quarantine, remote access, and artifact collection. EDR is a host-only solution that does not detect network-level threats. EDR integrates with SIEM and other security solutions to form comprehensive security ecosystems. Visibility feature provides complete context for all detections. The process spawning sc.exe was cmd.exe. EDR component collecting telemetry from endpoints is the Agent also known as Sensor.

## Common Pitfalls

**Over-reliance on EDR Alone:** EDR is host-only and does not detect network-level threats. Organizations need complementary solutions like NDR (Network Detection and Response) and SIEM for comprehensive coverage. Never assume EDR provides complete visibility across all attack vectors.

**Ignoring False Positive Context:** Anomaly detection can generate false positives when legitimate activities deviate from baseline. Analysts must examine full context provided by EDR rather than making quick verdicts based solely on detection flags. The visibility pillar exists specifically to enable informed decision-making.

**Delayed Response Actions:** When EDR alerts on potential lateral movement or data exfiltration, delays in executing host isolation or process termination allow attackers additional time to accomplish objectives. Response capabilities are useless if not applied promptly when True Positives are confirmed.

**Misunderstanding Agent vs Console Functions:** Agents perform basic detections but advanced correlation, machine learning analysis, and comprehensive threat intelligence matching occur at the console level. Agents are sensors collecting and transmitting data, not the analytical brain making complex detection decisions.

**Terminating Legitimate Processes:** The terminate process response capability requires careful judgment. Terminating critical business processes can cause operational disruption exceeding the threat damage. Analysts must understand process purposes before termination, especially for processes like database services or authentication systems.

**Neglecting MITRE ATT&CK Context:** EDR maps detections to MITRE tactics and techniques providing crucial context about attacker objectives and stage in kill chain. Ignoring this mapping prevents analysts from understanding whether they are observing initial access, persistence establishment, or active exfiltration, which directly impacts response urgency and strategy.

**Assuming All Alerts Require Isolation:** Host isolation is the most severe response action and inappropriate for every detection. Many alerts require only process termination, file quarantine, or simple monitoring. Unnecessary isolation disrupts business operations and creates alert fatigue when analysts learn their actions cause excessive disruption.

**Inadequate Threat Intelligence Integration:** EDR IOC matching effectiveness depends on quality and currency of integrated threat intelligence feeds. Organizations failing to maintain updated threat intelligence feeds miss opportunities for rapid detection of known threats, forcing reliance entirely on behavioral and anomaly detection which may have higher false positive rates.
