# Cyber Kill Chain Cheat Sheet

Based on **64.SLA1 Note_ Cyber Defence Frameworks - Cyber Kill Chain.pdf**. The Cyber Kill Chain is a framework created by **Lockheed Martin in 2011** to describe the stages adversaries move through during an intrusion, from planning to achieving their goals. It is useful for understanding, detecting, and interrupting attacks such as ransomware, breaches, and APT activity. 

---

## TL;DR

The **Cyber Kill Chain** breaks an attack into **7 phases**:

1. **Reconnaissance** – gather target information
2. **Weaponization** – prepare malware/exploit/payload
3. **Delivery** – send the payload to the victim
4. **Exploitation** – trigger code execution
5. **Installation** – establish persistence
6. **Command & Control (C2)** – remotely control the victim
7. **Actions on Objectives** – steal data, escalate privileges, move laterally, or cause damage

The analyst mindset is simple: **find the phase, identify the evidence, and break the chain before the attacker reaches the objective**. 

---

## 1) Reconnaissance

### What it is

Reconnaissance is the **research and planning phase**. The attacker gathers information about the target such as employees, business processes, internet-facing infrastructure, and exposed technologies. This phase is often passive and hard to detect. 

### Key ideas

* **Passive Recon**: no direct interaction with target
* **Active Recon**: direct probing, scanning, or social engineering
* Common OSINT sources:

  * search engines
  * media
  * social media
  * blogs/forums
  * public databases
  * WHOIS / technical data 

### Execution Commands

#### WHOIS lookup

```bash
whois example.com
```

**Explanation:**
Retrieves domain registration and ownership-related information.

**Concrete Example:**

```bash
whois target.com
```

#### DNS / basic recon

```bash
nslookup example.com
```

**Explanation:**
Checks how a domain resolves and can reveal IP-related infrastructure.

**Concrete Example:**

```bash
nslookup target.com
```

#### Email / subdomain harvesting with theHarvester

```bash
theHarvester -d example.com -b all
```

**Explanation:**
Collects public information such as email addresses, names, subdomains, IPs, and URLs from multiple sources.

**Concrete Example:**

```bash
theHarvester -d target.com -b all
```

### PDF-linked examples

The PDF explicitly mentions:

* **OSINT**
* **Passive Recon**
* **Active Recon**
* **Email harvesting**
* tools such as **theHarvester**, **Hunter.io**, and **OSINT Framework** 

### Gotchas

* Recon is often invisible because much of it uses public data.
* Public employee info on LinkedIn or company pages can dramatically improve phishing quality.
* Sloppy recon leads to sloppy attacks; good recon creates very believable lures. Sneaky little goblin work. 👀

## 2) Weaponization

### What it is

Weaponization is where the attacker turns gathered information into an **attack-ready payload**, combining malware, exploits, and delivery mechanisms. This can involve building malware, buying malware, creating malicious documents, or setting up backdoors and C2 infrastructure. 

### Key terms

* **Malware**: software designed to damage, disrupt, or gain unauthorized access
* **Exploit**: code that abuses a vulnerability
* **Payload**: the malicious code executed on the target 

### Common attacker tactics from the PDF

* malicious Office docs with **macros / VBA**
* infected **USB drives**
* **C2 infrastructure**
* **backdoors**
* phishing templates / fake OAuth consent apps 

### Execution Commands

#### YARA scan for suspicious payload traits

```bash
yara suspicious_rule.yar suspicious.docm
```

**Explanation:**
Scans a file for known malicious patterns such as macro indicators or tool signatures.

**Concrete Example:**

```bash
yara office_macro_rule.yar invoice.docm
```

#### Strings inspection

```bash
strings suspicious.exe | head
```

**Explanation:**
Pulls readable strings from a binary to spot URLs, suspicious commands, filenames, or embedded artifacts.

**Concrete Example:**

```bash
strings payload.exe | grep -i powershell
```

#### File type inspection

```bash
file suspicious.docm
```

**Explanation:**
Identifies the actual file type and may reveal disguised files.

**Concrete Example:**

```bash
file invoice.pdf.exe
```

### Gotchas

* Weaponization may happen entirely outside the victim environment, so defenders may see no signal yet.
* A malicious document is not always enough; the attacker still needs successful delivery and execution.
* Custom malware is harder to detect than commodity malware, because the attacker is trying not to show up wearing a name tag.

---

## 3) Delivery

### What it is

Delivery is the phase where the attacker transmits the malicious payload into the target environment. The PDF highlights **phishing emails**, **USB drops**, and **watering hole attacks** as common delivery methods. 

### Common delivery methods from the PDF

* **Phishing email**
* **USB drop**
* **Watering hole attack**
* malicious links or attachments
* drive-by download via compromised site or fake extension prompt 

### Execution Commands

#### Check email header source path (Linux-style with grep)

```bash
grep -i "Received:" suspicious_email.eml
```

**Explanation:**
Reviews the email path to understand where a message originated and how it was routed.

**Concrete Example:**

```bash
grep -i "Received:" payroll_update.eml
```

#### Extract URLs from an email

```bash
grep -Eo 'https?://[^ ]+' suspicious_email.eml
```

**Explanation:**
Finds suspicious links embedded in a phishing email.

**Concrete Example:**

```bash
grep -Eo 'https?://[^ ]+' invoice_notice.eml
```

#### Hash a USB-delivered file

```powershell
Get-FileHash .\promo_usb_file.exe -Algorithm SHA256
```

**Explanation:**
Creates a hash of a suspicious file delivered by USB or download for triage.

**Concrete Example:**

```powershell
Get-FileHash .\Target_Gift_USB.exe -Algorithm SHA256
```

### Gotchas

* Delivery is where user awareness matters a lot.
* Not every phishing email succeeds; many attacks die here if the user or controls catch it.
* USB drops are weirdly effective because curiosity is a powerful and chaotic life-form.

---

## 4) Exploitation

### What it is

Exploitation is the point where the attacker’s code **executes on the target** by abusing a vulnerability or triggering malicious content. The PDF lists malicious macro execution, zero-days, and known CVEs as examples. 

### Signs of exploitation from the PDF

* unexpected process spawns
* registry changes
* new services created
* suspicious command-line arguments in logs 

### Execution Commands

#### List suspicious processes

```powershell
Get-Process | Select-Object ProcessName, Id, Path
```

**Explanation:**
Shows running processes and paths to identify abnormal child processes or strange binaries.

**Concrete Example:**
Look for Office spawning script engines or shells such as:

* `winword.exe -> powershell.exe`
* `excel.exe -> cmd.exe`

#### Search for suspicious command lines in Windows logs

```powershell
Get-WinEvent -LogName Security | Select-Object -First 50
```

**Explanation:**
Reviews recent security events for suspicious activity. In real environments, you would filter for process creation or related telemetry.

#### Check recent services

```powershell
Get-Service | Sort-Object Status, DisplayName
```

**Explanation:**
Can reveal newly installed or suspicious services after exploitation.

### Gotchas

* Exploitation may be silent if the attacker uses a zero-day.
* Macro-based execution often looks boring right before it becomes catastrophic.
* Process trees are gold here; parent-child relationships often tell the real story.

---

## 5) Installation

### What it is

Installation is where the attacker establishes **persistence** so access survives reboots, cleanup, or patching. The PDF explains persistence via **web shells**, **backdoors**, **Windows services**, **run keys**, **startup folders**, and **timestomping**. 

### Persistence examples from the PDF

* web shell on web server
* Meterpreter backdoor
* modified or created Windows services
* Registry **Run Keys**
* Startup Folder persistence
* **Timestomping** to alter timestamps and hide artifacts 

### Execution Commands

#### Query Run Keys

```powershell
reg query HKCU\Software\Microsoft\Windows\CurrentVersion\Run
```

**Explanation:**
Checks a common persistence location that launches programs when the user logs in.

**Concrete Example:**

```powershell
reg query HKLM\Software\Microsoft\Windows\CurrentVersion\Run
```

#### Query Windows services

```powershell
sc query
```

**Explanation:**
Lists Windows services, useful for spotting newly created or suspicious persistence mechanisms.

**Concrete Example:**

```powershell
sc qc Spooler
```

#### Search startup folder

```powershell
Get-ChildItem "$env:APPDATA\Microsoft\Windows\Start Menu\Programs\Startup"
```

**Explanation:**
Lists files that run automatically at user login.

#### File timestamp inspection

```powershell
Get-Item .\suspicious.exe | Select-Object Name, CreationTime, LastWriteTime, LastAccessTime
```

**Explanation:**
Helps detect timestomping or suspicious timestamp inconsistencies.

### Gotchas

* Persistence often hides in places admins rarely check consistently.
* Service names may masquerade as legitimate OS components.
* Timestomping is classic attacker stage makeup: the malware puts on a fake mustache and hopes nobody notices 🎭

## 6) Command & Control (C2)

### What it is

After persistence, the attacker establishes a **Command & Control** channel so the compromised host can communicate with an external server and receive instructions. The PDF notes that beaconing often happens over **HTTP**, **HTTPS**, or **DNS tunneling**. 

### Common C2 methods from the PDF

* **HTTP** on port 80
* **HTTPS** on port 443
* **DNS tunneling**
* periodic beaconing between infected host and attacker-controlled infrastructure 

### Execution Commands

#### Netstat connection review

```bash
netstat -ano
```

**Explanation:**
Lists active network connections and owning processes. Good for finding suspicious outbound connections.

**Concrete Example:**
Look for unusual repeated outbound connections to the same external IP.

#### DNS request inspection in PCAP

```bash
tshark -r traffic.pcap -Y "dns"
```

**Explanation:**
Shows DNS traffic that may indicate tunneling or repeated suspicious lookups.

#### HTTP request inspection in PCAP

```bash
tshark -r traffic.pcap -Y "http.request"
```

**Explanation:**
Shows outbound HTTP requests that may reveal beaconing patterns.

#### Filter HTTPS / HTTP connections on a host

```powershell
Get-NetTCPConnection | Where-Object {$_.RemotePort -in 80,443}
```

**Explanation:**
Helps identify suspicious outbound traffic on common web ports.

### Gotchas

* HTTP/HTTPS C2 blends into normal traffic very well.
* DNS tunneling is sneaky because DNS is often trusted and noisy.
* Repetition is the giveaway: one request may be normal, but periodic beaconing starts to smell like trouble.

## 7) Actions on Objectives

### What it is

This is the attacker’s endgame. After access is established, the attacker performs the real mission: stealing credentials, escalating privileges, reconning internally, moving laterally, exfiltrating data, deleting backups, or corrupting systems. 

### Common actions from the PDF

* collect credentials
* privilege escalation
* internal reconnaissance
* lateral movement
* collect and exfiltrate sensitive data
* delete backups / shadow copies
* overwrite or corrupt data 

### Execution Commands

#### Review local users / groups

```powershell
net user
```

**Explanation:**
Lists user accounts that may have been targeted or abused.

**Concrete Example:**

```powershell
net localgroup administrators
```

#### Check shadow copies

```powershell
vssadmin list shadows
```

**Explanation:**
Shows available shadow copies. This is useful because attackers may delete them to prevent recovery.

#### Review PowerShell activity

```powershell
Get-WinEvent -LogName "Windows PowerShell" | Select-Object -First 20
```

**Explanation:**
Looks for suspicious PowerShell use during exfiltration, recon, or lateral movement.

#### Search for archive creation / staging clues

```powershell
Get-ChildItem C:\Users\Public -Recurse -Include *.zip,*.7z,*.rar -ErrorAction SilentlyContinue
```

**Explanation:**
Attackers often stage data into archives before exfiltration.

### Gotchas

* This phase may involve multiple objectives at once.
* Ransomware often combines exfiltration, encryption, backup deletion, and extortion.
* By this point, the attacker is not “testing”; they are harvesting the crop.

## Practice Analysis Mapping

The PDF includes a practice analysis section and asks the learner to map items into the correct Kill Chain phase for a real-world breach scenario. The listed items are:

* **exploit public-facing application**
* **data from local system**
* **powershell**
* **dynamic linker hijacking**
* **spearphishing attachment**
* **fallback channels** 

A practical mapping is:

| Item                              | Likely Kill Chain Phase                                       |
| --------------------------------- | ------------------------------------------------------------- |
| spearphishing attachment          | Delivery                                                      |
| exploit public-facing application | Exploitation                                                  |
| dynamic linker hijacking          | Installation                                                  |
| fallback channels                 | Command & Control                                             |
| data from local system            | Actions on Objectives                                         |
| powershell                        | Often Exploitation / Actions on Objectives depending on usage |

This is an analyst-style interpretation of the listed examples based on the phase definitions in the PDF.

## Limitations of the Traditional Cyber Kill Chain

The PDF is very clear: the traditional Cyber Kill Chain is useful, but **not sufficient by itself**. It was established in **2011**, focuses heavily on **malware delivery** and **network perimeter defense**, and does **not adequately cover Insider Threats** or the modern reality where adversaries combine many TTPs. The PDF recommends also using **MITRE ATT&CK** and the **Unified Kill Chain** for a broader defensive model. 

### Why this matters

* attackers change hashes and IPs quickly
* threats are more complex now
* insider threats are not well modeled
* behavior-based frameworks are needed too 

---

## Final Takeaway

The Cyber Kill Chain is still a very useful mental model because it teaches defenders to ask:

* **What phase is this?**
* **What evidence should exist here?**
* **Where can we break the chain?**

That is the practical magic. You do not need perfect visibility everywhere. You need enough visibility to interrupt the adversary before they reach the objective. And the earlier you break the chain, the less cleanup misery you inherit later. Very economical. Very unglamorous. Very effective. 🛡️
