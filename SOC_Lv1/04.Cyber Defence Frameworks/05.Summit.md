# 67.SAL1 — Summit Challenge — Exam Cheat Sheet

**Focus:** Purple team simulation applying Pyramid of Pain framework to detect and prevent malware execution through iterative detection engineering.

---

## TL;DR

Summit is a practical purple team challenge where defenders configure security tools to detect and prevent malware execution on simulated internal workstation while external penetration tester attempts malware execution. The objective follows Pyramid of Pain's ascending priority of indicators to increase simulated adversary's operational costs until they back down. Challenge requires iterative detection engineering starting from easy-to-change indicators (hashes, IPs) progressing to difficult-to-change indicators (TTPs). Each pyramid level enables detection and prevention of various attack indicators. Prerequisites include completing Pyramid of Pain and MITRE framework rooms. Success requires understanding indicator types, detection capabilities at each pyramid level, and effective defensive tool configuration.

---

## Challenge Objective

PicoSecure conducting threat simulation and detection engineering engagement to bolster malware detection capabilities after multiple incident response activities. Assigned to work with external penetration tester in iterative purple team scenario where tester attempts malware execution on simulated internal user workstation while defender configures security tools for detection and prevention.

**Goal:** Follow Pyramid of Pain ascending priority to increase simulated adversary operational costs and chase them away permanently.

---

## Purple Team Methodology

Purple team exercises combine red team (offensive) and blue team (defensive) operations. Penetration tester executes attack techniques while defender implements detections collaboratively rather than adversarially. Iterative approach allows defenders to improve detections based on attack execution feedback.

**Workflow:**
1. Attacker attempts technique execution
2. Defender observes attack indicators
3. Defender implements detection rules
4. Test detection effectiveness
5. Attacker modifies technique if detected
6. Repeat until detection coverage complete

---

## Pyramid of Pain Framework Application

Challenge follows Pyramid of Pain ascending from easy-to-change indicators (trivial for adversary) to difficult-to-change indicators (painful for adversary requiring significant operational changes).

### Level 1: Hash Values (Trivial)

**Indicator Type:** File hashes (MD5, SHA1, SHA256)

**Detection Method:** Block known malicious file hashes

**Adversary Cost:** Trivial - simple file modification changes hash

**Implementation:** Configure antivirus, EDR, or firewall to block specific file hashes

**Example:**
```
Block hash: 5f4dcc3b5aa765d61d8327deb882cf99
```

**Limitation:** Adversary recompiles or slightly modifies malware generating new hash

---

### Level 2: IP Addresses (Easy)

**Indicator Type:** Malicious IP addresses for C2 communication

**Detection Method:** Block connections to known malicious IPs

**Adversary Cost:** Easy - obtain new infrastructure or use fast-flux DNS

**Implementation:** Configure firewall rules blocking malicious IP ranges

**Example:**
```
Deny outbound to: 192.0.2.100
Deny outbound to: 198.51.100.0/24
```

**Limitation:** Adversary quickly obtains new IP addresses through cloud providers or compromised infrastructure

---

### Level 3: Domain Names (Simple)

**Indicator Type:** Malicious domain names for C2 servers

**Detection Method:** Block DNS resolution or connections to malicious domains

**Adversary Cost:** Simple - register new domains or use domain generation algorithms (DGA)

**Implementation:** Configure DNS sinkhole or web proxy blocking

**Example:**
```
Block domain: malicious-c2-server.com
Block domain: *.evil-domain.net
```

**Limitation:** Adversary registers new domains or implements DGA generating thousands of potential domains

---

### Level 4: Network/Host Artifacts (Annoying)

**Indicator Type:** Artifacts created on network or host during attack

**Detection Method:** Identify suspicious registry keys, files, user agents, or network patterns

**Adversary Cost:** Annoying - requires code changes and testing

**Implementation:** Configure SIEM rules detecting specific artifacts

**Example Host Artifacts:**
```
Registry key: HKCU\Software\Microsoft\Windows\CurrentVersion\Run\MalwareName
File path: C:\Users\Public\suspicious.exe
Mutex name: Global\UniqueMalwareMutex
```

**Example Network Artifacts:**
```
User-Agent: Mozilla/4.0 (compatible; MSIE 6.0; Windows NT 5.1)
URI pattern: /admin/get.php?id=
Beacon interval: Every 60 seconds exactly
```

**Limitation:** Adversary modifies code to use different artifacts requiring development and testing time

---

### Level 5: Tools (Challenging)

**Indicator Type:** Specific tools used in attacks (Mimikatz, Cobalt Strike, PowerShell Empire)

**Detection Method:** Detect tool signatures, behaviors, or capabilities

**Adversary Cost:** Challenging - replace with alternative tools or develop custom ones

**Implementation:** Configure EDR detecting known tool behaviors or signatures

**Example:**
```
Detect Mimikatz:
- LSASS memory access patterns
- Specific function calls
- Known Mimikatz modules

Detect Cobalt Strike:
- Named pipe patterns
- Beacon configuration artifacts
- SMB communication patterns
```

**Limitation:** Adversary develops custom tools or heavily modifies existing ones requiring significant development resources

---

### Level 6: TTPs (Tough)

**Indicator Type:** Tactics, Techniques, and Procedures (how adversary operates)

**Detection Method:** Detect behavioral patterns regardless of tools used

**Adversary Cost:** Tough - requires fundamental operational changes

**Implementation:** Configure behavioral analytics detecting attack patterns mapped to MITRE ATT&CK

**Example TTPs:**
```
Credential Dumping (T1003):
- Detect any LSASS memory access
- Monitor credential file access
- Alert on unusual authentication patterns

Lateral Movement (T1021):
- Detect suspicious remote execution
- Monitor unusual SMB/RDP sessions
- Alert on admin share access patterns

Persistence (T1547):
- Monitor registry run key modifications
- Detect scheduled task creation
- Alert on service installations
```

**Advantage:** Adversary must fundamentally change operational methods which is expensive, time-consuming, and reduces effectiveness

## Detection Engineering Approach

**Progressive Hardening:** Start with high-confidence, low-effort detections (hashes, IPs) progressing to complex behavioral detections (TTPs). Each level increases adversary operational costs.

**Iterative Improvement:** Test detections against attack attempts, identify gaps, implement additional coverage, and retest. Purple team collaboration accelerates this cycle.

**Defense in Depth:** Implement detections at multiple pyramid levels simultaneously. When adversary bypasses hash-based detection, IP blocking still provides defense. When they bypass that, domain blocking activates, and so forth.

**Operational Balance:** Lower pyramid levels (hashes, IPs) are easy to implement but easy to bypass. Higher levels (tools, TTPs) are harder to implement but provide durable protection. Effective defense requires coverage across all levels.

---

## Challenge Success Criteria

Successfully completing Summit challenge requires:

1. **Understanding Indicator Types:** Recognize which pyramid level each indicator belongs to
2. **Implementing Detections:** Configure security tools appropriate for each indicator type
3. **Testing Coverage:** Verify detections trigger appropriately on attack attempts
4. **Iterating Improvements:** Enhance detections based on bypass attempts
5. **Achieving TTP Detection:** Reach top of pyramid with behavioral detections making continued attacks prohibitively expensive

## Tool Configuration Examples

**Antivirus/EDR:** Configure hash-based blocking at file execution or creation

**Firewall:** Implement IP and port-based blocking rules for network communications

**DNS/Web Proxy:** Block malicious domains at resolution or connection time

**SIEM:** Create correlation rules detecting artifact patterns across multiple data sources

**Behavioral Analytics:** Implement machine learning or rule-based detection for TTP identification

## Critical Exam Points

Summit is purple team challenge applying Pyramid of Pain framework to malware detection. Objective is increasing adversary operational costs through progressive detection implementation. Pyramid levels ascend from trivial (hashes) through easy (IPs), simple (domains), annoying (artifacts), challenging (tools), to tough (TTPs). Each level represents increasing adversary cost to bypass. Hash detection is trivial to bypass through file modification. IP blocking is easy to bypass through new infrastructure. Domain blocking is simple to bypass through new registrations or DGA. Artifact detection is annoying requiring code changes. Tool detection is challenging requiring alternative tools. TTP detection is tough requiring fundamental operational changes. Prerequisites include Pyramid of Pain and MITRE framework understanding. Purple team methodology involves collaborative attacker-defender iteration. Defense in depth requires coverage across multiple pyramid levels. Success requires reaching TTP-level behavioral detection making attacks prohibitively expensive.

## Common Pitfalls

**Over-reliance on Lower Pyramid Levels:** Implementing only hash or IP blocking provides false security sense. Adversaries trivially bypass these detections. Organizations believing they're protected because they block known malware hashes miss novel or slightly modified variants. Always implement detections across multiple pyramid levels.

**Ignoring False Positive Management:** Behavioral TTP detections at pyramid top generate more false positives than hash-based detections. Without proper tuning and context, analysts become overwhelmed leading to alert fatigue and missed true positives. Implement detections progressively with thorough testing.

**Misunderstanding Purple Team Methodology:** Purple team exercises are collaborative, not adversarial. Some participants treat them as competitions where attackers try to "win" against defenders. This defeats the purpose which is improving defensive capabilities through shared knowledge. Maintain collaborative mindset throughout exercises.

**Static Detection Implementation:** Configuring detections once without iteration fails as adversaries evolve. Summit challenge requires iterative approach where detections improve based on bypass attempts. Static defenses become obsolete quickly as threat landscape changes.

**Neglecting Tool Capabilities:** Different security tools excel at different pyramid levels. Antivirus handles hashes well but struggles with behavioral detection. SIEM excels at correlation across artifacts. EDR provides strong TTP detection. Using wrong tool for pyramid level reduces effectiveness. Match tool capabilities to indicator types.

**Skipping Lower Levels:** While TTP detection is most valuable, it shouldn't replace lower pyramid levels entirely. Hash and IP blocking still provide value for known threats with minimal operational overhead. Complete defense strategy covers all levels with appropriate effort allocation.

**Insufficient Testing:** Implementing detection rules without validation against actual attack techniques leads to blind spots. Summit challenge emphasizes testing each detection against simulated attacks. Production environments require similar validation through purple team exercises or attack simulation platforms.

**Missing MITRE ATT&CK Mapping:** TTP-level detection requires understanding which MITRE techniques apply. Detecting "suspicious behavior" without mapping to specific ATT&CK techniques prevents systematic coverage validation. Map all behavioral detections to ATT&CK techniques ensuring comprehensive coverage.
