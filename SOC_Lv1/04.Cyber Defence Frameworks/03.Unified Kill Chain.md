# 65.SAL1 — Unified Kill Chain — Exam Cheat Sheet

**Focus:** Understanding the 18-phase UKC framework for mapping attacker methodology from reconnaissance to objectives achievement.

---

## TL;DR

The Unified Kill Chain is a modern framework with 18 phases describing attacker methodology from initial reconnaissance to achieving objectives. Published in 2017 by Paul Pols, it complements frameworks like Lockheed Martin's Cyber Kill Chain and MITRE ATT&CK. The 18 phases are grouped into three goals: IN (Initial Foothold - gaining access), THROUGH (Network Propagation - expanding control), and OUT (Action on Objectives - achieving attack goals). Each phase maps to MITRE tactics and provides defenders with understanding of attack progression to implement defensive measures. The framework helps identify attack surfaces, supports threat modeling, and enables reconstruction of attack paths. Understanding the UKC allows defenders to either pre-emptively protect systems or disrupt attacker attempts at any phase.

---

## Kill Chain Foundation

Kill Chain originates from military terminology explaining various stages of an attack. In cybersecurity, it describes the methodology and path attackers use to approach and intrude targets. Example kill chain includes scanning, exploiting web vulnerability, and escalating privileges. The objective is understanding attacker kill chains to put defensive measures in place for pre-emptive protection or attack disruption.

---

## Threat Modeling Process

Threat modeling is a series of steps to improve system security by identifying risk through four phases:

**Phase 1:** Identify systems and applications needing protection and their environmental function. Determine if systems are critical to operations or hold sensitive information like payment data or addresses.

**Phase 2:** Assess vulnerabilities and weaknesses in systems and applications and how they could be potentially exploited.

**Phase 3:** Create action plans to secure systems and applications from highlighted vulnerabilities.

**Phase 4:** Implement policies preventing vulnerability recurrence where possible, such as SDLC for applications or phishing awareness training for employees.

**UKC Role:** The framework encourages threat modeling by helping identify potential attack surfaces and system exploitation methods. IT assets refer to software or hardware pieces.

**Related Frameworks:** STRIDE, DREAD, and CVSS are frameworks specifically used in threat modeling.

---

## UKC Framework Overview

Published 2017 by Paul Pols, updated 2022. The UKC aims to complement (not compete with) frameworks like Lockheed Martin's and MITRE ATT&CK. Contains 18 official phases covering everything from reconnaissance to data exfiltration and attacker motivation understanding.

**Key Benefits:**

| UKC Advantage | Traditional Framework Limitation |
|---------------|----------------------------------|
| Modern (2017, updated 2022) | Frameworks like MITRE released 2013 when cybersecurity landscape differed |
| Extremely detailed (18 phases) | Other frameworks have small handful of phases |
| Covers entire attack lifecycle including reconnaissance, exploitation, post-exploitation, and attacker motivation | Limited phase coverage |
| Realistic attack scenarios with phases recurring (e.g., reconnaissance after exploitation for pivoting) | Linear models not accounting for back-and-forth phase movement |

## Goal 1: IN (Initial Foothold)

Focus on gaining access to system or networked environment. Attackers employ numerous tactics investigating systems for potential vulnerabilities to exploit for foothold establishment.

### Phase 1: Reconnaissance (MITRE TA0043)

Gathering information about targets through active or passive methods. Information gathered throughout later UKC stages.

**Collected Information:**
- Systems and services running on targets (beneficial for weaponization and exploitation)
- Contact lists or employee lists for impersonation in social engineering or phishing
- Potential credentials for later stages like pivoting or initial access
- Network topology and networked systems for pivoting opportunities

---

### Phase 2: Weaponization (MITRE TA0001)

Setting up necessary infrastructure for attack execution. Examples include command and control server setup or systems capable of catching reverse shells and delivering payloads.

---

### Phase 3: Social Engineering (MITRE TA0001)

Manipulating employees to perform actions aiding adversary attacks.

**Examples:**
- Getting users to open malicious email attachments (phishing)
- Impersonating web pages to capture user credentials
- Calling or visiting targets while impersonating users for password resets or unauthorized site access

---

### Phase 4: Delivery (MITRE TA0001)

Transmitting weaponized objects to targeted environments through various methods.

---

### Phase 5: Exploitation (MITRE TA0002)

Taking advantage of system weaknesses or vulnerabilities. Defined as abuse of vulnerabilities for code execution.

**Examples:**
- Uploading and executing reverse shells to web applications
- Interfering with automated scripts for code execution
- Abusing web application vulnerabilities for system-level code execution

---

### Phase 6: Persistence (MITRE TA0003)

Maintaining access to systems after initial foothold establishment.

**Examples:**
- Creating services allowing attacker access regain
- Adding systems to C2 servers for remote command execution
- Leaving backdoors executing on specific actions (e.g., reverse shell when administrators log in)

---

### Phase 7: Defense Evasion (MITRE TA0005)

Evading defensive measures in systems or networks.

**Evaded Defenses:**
- Web application firewalls
- Network firewalls
- Antivirus systems
- Intrusion detection systems

**Value:** Helps form responses and improve future defense systems by understanding evasion techniques.

---

### Phase 8: Command & Control (MITRE TA0011)

Establishing communications between adversary and target system using weaponization stage efforts.

**Capabilities:**
- Execute commands
- Steal data, credentials, and information
- Pivot to other network systems

---

### Phase 9: Pivoting (MITRE TA0008)

Reaching systems within networks not otherwise accessible (not exposed to internet). Networks often contain systems with valuable data or weaker security not directly reachable. Example: gaining web server access to attack internal network systems.

---

## Goal 2: THROUGH (Network Propagation)

Follows successful foothold establishment. If defensive controls prevent objective achievement, attackers seek additional access and privileges. Attackers establish bases as pivot points for internal network information gathering.

### Phase 10: Discovery (MITRE TA0007)

Uncovering system and network information to build knowledge base.

**Information Gathered:**
- Active user accounts and permissions granted
- Applications and software in use
- Web browser activity
- Files, directories, and network shares
- System configurations

---

### Phase 11: Privilege Escalation (MITRE TA0004)

Gaining more prominent permissions within pivot systems using discovered vulnerabilities and misconfigurations.

**Escalation Targets:**
- SYSTEM/ROOT
- Local Administrator
- User accounts with Admin-like access
- User accounts with specific access or functions

---

### Phase 12: Execution (MITRE TA0002)

Deploying malicious code using pivot systems as hosts.

**Deployed Tools:**
- Remote trojans
- C2 scripts
- Malicious links
- Scheduled tasks

**Purpose:** Facilitate recurring presence and uphold persistence.

---

### Phase 13: Credential Access (MITRE TA0006)

Stealing account names and passwords through various methods working with Privilege Escalation.

**Methods:**
- Keylogging
- Credential dumping (e.g., Mimikatz)

**Advantage:** Using legitimate credentials makes detection harder during attacks.

---

### Phase 14: Lateral Movement (MITRE TA0008)

Moving through networks using credentials and elevated privileges to jump onto other targeted systems for primary objective achievement. Stealthier techniques are preferred.

---

## Goal 3: OUT (Action on Objectives)

Wrapping up adversary attack journey with critical asset access to fulfill attack goals, typically compromising CIA triad (Confidentiality, Integrity, Availability).

### Phase 15: Collection (MITRE TA0009)

Gathering valuable data of interest, compromising data confidentiality and leading to exfiltration.

**Target Sources:**
- Drives
- Browsers
- Audio and video
- Email

---

### Phase 16: Exfiltration (MITRE TA0010)

Stealing data packaged using encryption and compression to avoid detection. Previously deployed C2 channels and tunnels facilitate this process.

---

### Phase 17: Impact (MITRE TA0040)

Compromising data integrity and availability by manipulating, interrupting, or destroying assets.

**Methods:**
- Account access removal
- Disk wipes
- Data encryption (ransomware)
- Defacement
- Denial of Service (DoS) attacks

**Goal:** Disrupt business and operational processes.

---

### Phase 18: Objectives

Achieving strategic goals for attacks with full system and network power and access.

**Examples:**
- Financial motivation: Encrypting files with ransomware for payment
- Reputation damage: Releasing private confidential information publicly

## Practical Scenario Examples

**Failed administrator logins:** Privilege Escalation phase - attacker seeking elevated permissions.

**Mimikatz detected dumping OS and user secrets:** Credential Access phase - post-exploitation credential theft.

**Large traffic spike to unknown suspicious IP:** Exfiltration phase - data removal from network.

**PII released to public:** Compromises Confidentiality element of CIA triad.

**Phishing emails:** Tactic to gain foothold through social engineering and delivery.

**Password reset impersonation:** Social Engineering phase.

**C2 server setup:** Weaponization phase.

**Vulnerability exploitation:** Exploitation phase.

**Moving between systems:** Pivoting phase.

**Malicious service for re-access:** Persistence phase.

## Critical Exam Points

UKC has 18 phases released in 2017 and updated in 2022. Kill Chain term originates from military. Asset is the technical term for software or hardware in IT. Defense Evasion is the phase where attackers evade detection. Exfiltration is the phase where attackers remove data from networks. Objectives is the phase where attackers achieve their goals. The three main goals are IN (Initial Foothold), THROUGH (Network Propagation), and OUT (Action on Objectives). UKC complements frameworks like MITRE ATT&CK rather than competing. Each phase maps to specific MITRE tactics. Threat modeling involves four steps: identify systems, assess vulnerabilities, create action plans, implement prevention policies. The framework accounts for realistic attack scenarios where phases recur rather than following linear progression.

## Common Pitfalls

**Linear Thinking:** Attackers do not progress through UKC phases linearly. After exploiting a machine, attackers return to reconnaissance for pivoting. Defenders assuming linear progression miss lateral movement and privilege escalation cycles occurring throughout attacks.

**Confusing Pivoting with Lateral Movement:** Pivoting (Phase 9) establishes the compromised system as a staging point and tunnel for operations. Lateral Movement (Phase 14) uses that established position with credentials to jump to other systems. Pivoting comes first in the IN goal, Lateral Movement comes later in THROUGH goal after credential access and privilege escalation.

**Overlooking Defense Evasion Importance:** Defense Evasion phase provides critical intelligence on how attackers bypassed security controls. Many analysts focus on what happened rather than how defenses failed. Understanding evasion techniques directly informs security improvements preventing future bypasses.

**Ignoring Objectives Phase:** Some analysts stop investigation after identifying Impact phase activities like ransomware deployment. The Objectives phase reveals attacker strategic goals and motivations essential for threat attribution, understanding if the attack is financially motivated, state-sponsored, or activism-driven. This context influences incident response priorities and future security investments.

**Misidentifying Weaponization vs Exploitation:** Weaponization involves setting up infrastructure (C2 servers, payload delivery systems). Exploitation involves actually using vulnerabilities for code execution. Confusing these phases leads to incomplete incident timelines and missed infrastructure indicators.

**Credential Access Detection Gaps:** Credential dumping tools like Mimikatz executing on IT manager workstations clearly indicate Credential Access phase. However, organizations often lack monitoring for LSASS access, registry hive reading, or SAM database queries. Without these detections, attackers steal credentials unnoticed enabling persistent lateral movement.

**Assuming Single Goal Completion:** Sophisticated attacks cycle through goals multiple times. After achieving initial OUT phase objectives on one system, attackers return to THROUGH phases for additional systems. Analysts declaring incidents resolved after containing one compromised host may miss ongoing campaigns affecting other network segments.
