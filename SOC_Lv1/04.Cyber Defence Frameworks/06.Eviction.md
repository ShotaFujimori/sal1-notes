# 68.SAL1 — Eviction Challenge — Exam Cheat Sheet

**Focus:** Using MITRE ATT&CK Navigator to identify APT28 TTPs, investigate network intrusion, and implement defensive measures across attack lifecycle.

---

## TL;DR

Eviction is practical challenge where SOC analyst investigates potential APT28 (advanced persistent threat) intrusion into E-corp, a rare earth metals manufacturer. Intelligence report indicates APT28 might target similar organizations. Analyst must use MITRE ATT&CK Navigator to identify group's TTPs, determine if network is already compromised, and stop ongoing attacks. Challenge covers full attack lifecycle: reconnaissance, resource development, initial access, execution, persistence, defense evasion, discovery, lateral movement, collection, and exfiltration. Success requires mapping threat intelligence to specific techniques, searching for indicators across network, and implementing appropriate defensive controls. APT28 (also known as Fancy Bear, Sofacy, Sednit) is Russian state-sponsored threat group active since mid-2000s known for targeting government, military, and security organizations. Challenge emphasizes threat-informed defense using ATT&CK framework for systematic threat hunting and incident response.

---

## Scenario Context

**Organization:** E-corp manufactures rare earth metals for government and non-government clients

**Threat:** APT28 (APT group) might be targeting organizations similar to E-corp according to classified intelligence report

**Analyst Role:** Sunny, SOC analyst tasked with:
- Using MITRE ATT&CK Navigator to identify APT28 TTPs
- Determining if APT28 already intruded into network
- Stopping attack if intrusion confirmed

**Methodology:** Threat-informed defense using MITRE ATT&CK framework for systematic investigation

## Attack Lifecycle Investigation

### Phase 1: Reconnaissance (TA0043)

**Investigation Focus:** Identify techniques used for both reconnaissance and initial access preparation

**Common APT28 Reconnaissance Techniques:**
- **Phishing for Information (T1598):** Sending phishing emails to gather information without delivering payloads
- **Search Open Websites/Domains (T1593):** Researching target organization through public sources
- **Gather Victim Network Information (T1590):** Collecting network architecture details
- **Gather Victim Identity Information (T1589):** Identifying key personnel for targeting

**Dual-Purpose Technique:** Phishing serves both reconnaissance (gathering information about targets) and initial access preparation (identifying vulnerable users)

**Detection Strategy:**
```
Monitor for:
- Suspicious email patterns targeting organization
- Unusual queries to public company information
- Social engineering attempts against employees
- Reconnaissance scanning from suspicious IPs
```

---

### Phase 2: Resource Development (TA0042)

**Investigation Focus:** Accounts compromised during infrastructure development

**Common APT28 Resource Development:**
- **Email Accounts (T1586.002):** Compromising email accounts for phishing campaigns
- **Social Media Accounts (T1586.003):** Compromising social media for intelligence gathering and social engineering
- **Cloud Accounts (T1586.003):** Compromising cloud infrastructure for C2 and data staging

**Compromised Account Types:**
- Employee email accounts for internal phishing
- Social media accounts for spear-phishing preparation
- Cloud service accounts for infrastructure establishment
- Third-party vendor accounts for supply chain attacks

**Detection Strategy:**
```
Monitor for:
- Anomalous email account behavior
- Unusual login locations for corporate accounts
- Suspicious social media activity from employee accounts
- Unauthorized cloud resource provisioning
```

---

### Phase 3: Initial Access (TA0001)

**Investigation Focus:** Social engineering techniques making users execute malicious code

**Common APT28 Initial Access Techniques:**
- **Phishing (T1566):** Spearphishing attachments or links
- **Exploit Public-Facing Application (T1190):** Exploiting vulnerabilities in web servers
- **Valid Accounts (T1078):** Using compromised credentials

**Social Engineering Focus:** APT28 heavily relies on spearphishing with malicious attachments

**Detection Strategy:**
```
Monitor for:
- Email attachments with suspicious extensions
- Links to credential harvesting sites
- Unusual authentication attempts
- Exploitation attempts on public applications
```

---

### Phase 4: Execution (TA0002)

**Investigation Focus:** User execution techniques enabling code execution

**User Execution Techniques (T1204):**
- **Malicious File (T1204.002):** User opens malicious attachment or downloaded file
- **Malicious Link (T1204.001):** User clicks malicious link executing code

**Common APT28 Execution Chain:**
1. User receives spearphishing email with attachment
2. User opens malicious document (Word, Excel, PDF)
3. Macro or exploit executes delivering payload
4. Alternatively, user clicks link downloading malware

**Answer Format Example:** "Malicious File and Malicious Link"

**Detection Strategy:**
```
Monitor for:
- Office documents executing macros
- Downloaded files from suspicious sources
- Browser downloads following email link clicks
- Unusual child processes from office applications
```

---

### Phase 5: Execution - Scripting Interpreters

**Investigation Focus:** Scripting interpreters enabling execution after user interaction

**Common APT28 Scripting Interpreters:**
- **PowerShell (T1059.001):** Most common interpreter for Windows environments
- **Windows Command Shell (T1059.003):** cmd.exe for batch scripts
- **JavaScript (T1059.007):** For web-based execution
- **Visual Basic (T1059.005):** VBScript for macro-based execution

**Likely Answer Format:** "PowerShell and Windows Command Shell" or "PowerShell and Visual Basic"

**Detection Strategy:**
```
Monitor for:
- PowerShell execution with obfuscated commands
- cmd.exe spawned by office applications
- Scripts executing from unusual locations
- Encoded or obfuscated script content

Example SIEM Query:
process_name IN (powershell.exe, cmd.exe)
AND parent_process_name IN (winword.exe, excel.exe, outlook.exe)
AND command_line CONTAINS (hidden, encoded, bypass)
```

---

### Phase 6: Persistence (TA0003)

**Investigation Focus:** Registry keys modified for maintaining persistence

**Common APT28 Registry Persistence Keys:**
- **Registry Run Keys (T1547.001):**
  ```
  HKCU\Software\Microsoft\Windows\CurrentVersion\Run
  HKLM\Software\Microsoft\Windows\CurrentVersion\Run
  HKCU\Software\Microsoft\Windows\CurrentVersion\RunOnce
  HKLM\Software\Microsoft\Windows\CurrentVersion\RunOnce
  ```

- **Boot or Logon Autostart Execution:**
  ```
  HKLM\Software\Microsoft\Windows\CurrentVersion\Explorer\Shell Folders
  HKLM\Software\Microsoft\Windows\CurrentVersion\Explorer\User Shell Folders
  ```

**Detection Strategy:**
```
Monitor registry modifications:
- Any changes to Run/RunOnce keys
- New values in autostart locations
- Modifications by unexpected processes
- Registry changes from script interpreters

Example Registry Monitoring:
auditpol /set /subcategory:"Registry" /success:enable /failure:enable

PowerShell Detection:
Get-ItemProperty -Path "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run"
Get-ItemProperty -Path "HKLM:\Software\Microsoft\Windows\CurrentVersion\Run"
```

---

### Phase 7: Defense Evasion (TA0005)

**Investigation Focus:** System binaries used for proxy execution

**Common APT28 Defense Evasion Techniques:**
- **Rundll32 (T1218.011):** Executing malicious DLLs
- **Regsvr32 (T1218.010):** Bypassing application control
- **Mshta (T1218.005):** Executing malicious HTA files
- **Certutil (T1105/T1140):** Downloading files or decoding payloads

**Most Likely Answer:** Rundll32 (extremely common in APT28 campaigns)

**Detection Strategy:**
```
Monitor system binary abuse:
- Rundll32.exe with unusual DLL paths or exports
- Regsvr32.exe with network connections
- Mshta.exe executing remote scripts
- Certutil.exe downloading files

Example Detection Logic:
process_name = "rundll32.exe"
AND (
  command_line CONTAINS (".txt", ".dat", "..\\", "http")
  OR parent_process = "powershell.exe"
  OR network_connection = TRUE
)
```

---

### Phase 8: Discovery (TA0007)

**Investigation Focus:** Tcpdump presence indicating discovery techniques

**Tcpdump Discovery Technique:**
- **Network Sniffing (T1040):** Capturing network traffic to discover network layout, communications, and credentials

**Why APT Uses Tcpdump:**
- Map internal network topology
- Identify active hosts and services
- Capture authentication credentials in cleartext
- Understand data flows for exfiltration planning

**Detection Strategy:**
```
Monitor for:
- Tcpdump installation on Windows systems (unusual)
- Network packet capture tools execution
- Promiscuous mode network interface activation
- Large PCAP file creation

Example Detection:
process_name IN ("tcpdump", "windump", "tshark")
OR command_line CONTAINS ("pcap", "capture", "sniff")
OR file_extension = ".pcap"
```

---

### Phase 9: Lateral Movement (TA0008)

**Investigation Focus:** Remote services exploited for lateral movement

**Common APT28 Lateral Movement Remote Services:**
- **SMB/Windows Admin Shares (T1021.002):** Using admin$ and C$ shares
- **Remote Desktop Protocol (T1021.001):** RDP for interactive access
- **Windows Remote Management (T1021.006):** WinRM for remote command execution
- **SSH (T1021.004):** On Linux systems in network

**Answer Format Example:** "SMB/Windows Admin Shares and Remote Desktop Protocol"

**Detection Strategy:**
```
Monitor for:
- Unusual SMB connections to admin shares
- RDP connections from internal hosts
- WinRM usage from non-administrative systems
- Failed authentication attempts across multiple hosts

Example SIEM Query:
(event_id = 4624 AND logon_type = 3 AND share_name = "\\*\ADMIN$")
OR (event_id = 4624 AND logon_type = 10)
OR (process_name = "wsmprovhost.exe")
```

---

### Phase 10: Collection (TA0009)

**Investigation Focus:** Information repositories targeted for intellectual property theft

**Common APT28 Collection Targets:**
- **Sharepoint (T1213.002):** Corporate document repositories
- **Confluence (T1213.001):** Internal wikis and documentation
- **Network Shared Drive:** File servers with sensitive data
- **Code Repository:** Git, SVN for source code theft

**Most Likely Target:** Sharepoint (common in enterprise environments for IP storage)

**Detection Strategy:**
```
Monitor for:
- Unusual access patterns to Sharepoint
- Mass file downloads from repositories
- Database queries to document management systems
- API calls to cloud storage services

Example Detection:
(source = "sharepoint_logs")
AND (
  download_count > 100 IN last_hour
  OR access_time BETWEEN 02:00 AND 05:00
  OR user_account NOT IN approved_list
)
```

---

### Phase 11: Exfiltration (TA0010)

**Investigation Focus:** Proxy types used when direct C2 connection blocked

**Common APT28 Exfiltration Proxy Techniques:**
- **External Proxy (T1090.002):** Using external proxy services to hide destination
- **Multi-hop Proxy (T1090.003):** Routing through multiple proxies
- **Domain Fronting (T1090.004):** Using CDN or cloud services to hide C2

**Answer Format Example:** "External Proxy and Multi-hop Proxy"

**Why Proxies When C2 Blocked:**
- Bypass firewall restrictions
- Hide true C2 server destination
- Blend traffic with legitimate services
- Evade network monitoring

**Detection Strategy:**
```
Monitor for:
- Connections to known proxy services
- Unusual TLS/SSL certificate patterns
- Traffic to CDN endpoints with suspicious SNI
- Multiple connection hops to reach destination

Example Detection:
(destination_category = "proxy")
OR (ssl_issuer NOT IN trusted_ca_list)
OR (domain_fronting_detected = TRUE)
OR (connection_chain_length > 2)
```

## Threat Hunting Methodology

**Hypothesis-Driven Hunting:**

**Step 1: Form Hypothesis**
```
Example: "APT28 may have gained persistence through registry run keys"
```

**Step 2: Identify Data Sources**
```
Required logs:
- Windows Security Event Logs (Event ID 4657)
- Sysmon Event ID 13 (Registry value set)
- EDR registry monitoring logs
```

**Step 3: Create Hunt Query**
```
(event_id = 4657 OR sysmon_event_id = 13)
AND registry_path CONTAINS (
  "CurrentVersion\\Run",
  "CurrentVersion\\RunOnce"
)
AND (
  creation_time > (now - 30days)
  OR modification_time > (now - 30days)
)
```

**Step 4: Analyze Results**
```
- Verify legitimate vs suspicious entries
- Check file signatures and locations
- Correlate with other indicators
- Escalate confirmed malicious activity
```

**Step 5: Document Findings**
```
- Technique used
- Indicators discovered
- Systems affected
- Response actions taken
- Lessons learned
```

## Common Pitfalls

**Incomplete ATT&CK Mapping:** Investigating only obvious techniques while missing subtle ones. APT28 uses multiple techniques per tactic. Focusing solely on phishing for initial access misses valid account usage or exploitation. Review complete ATT&CK layer for comprehensive coverage.

**Ignoring Sub-Techniques:** ATT&CK sub-techniques provide crucial detail. User Execution splits into Malicious File and Malicious Link. Investigating parent technique without sub-techniques misses specific indicators. Always examine sub-technique level for precise detection.

**Static Intelligence Consumption:** Using outdated APT28 intelligence without checking current ATT&CK layer. Threat groups evolve TTPs continuously. APT28 layer updates regularly with new observations. Always reference current layer, not memorized historical TTPs.

**Tool-Centric Instead of Behavior-Centric:** Searching for specific malware names instead of techniques. APT28 uses various tools implementing same techniques. Searching for "X-Agent" misses custom malware implementing identical techniques. Focus detection on behaviors not tool names.

**Missing Detection Data Sources:** Attempting to hunt for techniques without required telemetry. Detecting registry persistence requires registry monitoring logs. Without Sysmon or EDR registry monitoring, detection is impossible. Map each technique to required data sources before hunting.

**Overwhelming Scope:** Trying to investigate all APT28 techniques simultaneously. This creates analysis paralysis and missed indicators. Prioritize investigation by attack phase following challenge question order: reconnaissance, resource development, initial access, execution, persistence, evasion, discovery, lateral movement, collection, exfiltration.

**Ignoring Timeline Analysis:** Examining techniques in isolation without temporal correlation. APT attacks follow logical progression. Execution precedes persistence. Persistence precedes lateral movement. Timeline correlation identifies attack chains validating true positives versus isolated benign events.

**False Positive Fatigue:** Abandoning hunts after initial false positives without tuning queries. Many techniques have legitimate use cases. PowerShell execution is common in enterprise. Tune detections with additional context: parent process, command line parameters, execution location, user account. Iterative refinement reduces false positives while maintaining detection efficacy.

**Inadequate Documentation:** Failing to document investigation methodology and findings. Future analysts investigating same threat need historical context. Document hypothesis, queries used, results discovered, conclusions drawn, and actions taken. This enables continuous improvement and knowledge transfer.
