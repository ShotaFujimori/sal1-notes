# 66.SAL1 — MITRE Frameworks — Exam Cheat Sheet

**Focus:** Understanding MITRE ATT&CK, CAR, D3FEND, and related frameworks for threat intelligence, detection engineering, and defensive operations.

---

## TL;DR

MITRE is a not-for-profit organization providing crucial cybersecurity frameworks and resources. ATT&CK is a globally-accessible knowledge base of adversary tactics and techniques based on real-world observations, founded in 2013 to document APT group TTPs (Tactics, Techniques, Procedures). The framework evolved from Windows-focused to covering Enterprise (macOS, Linux, cloud), Mobile, and ICS environments. ATT&CK provides standard terminology and unique IDs enabling effective security community communication. CAR offers ready-made detection analytics translating ATT&CK into real detections with SIEM queries. D3FEND maps defensive techniques explaining how security controls work. Additional tools include Adversary Emulation Library, Caldera automation, AADAPT for blockchain threats, and ATLAS for AI/ML threats. These resources enable red and blue teams to understand adversary behavior, develop effective detections, and enhance defenses.

---

## MITRE Organization Mission

MITRE conducts research and development across cybersecurity, artificial intelligence, healthcare, and space systems supporting the mission "to solve problems for a safer world." Key cybersecurity resources include ATT&CK, CAR Knowledge Base, D3FEND, MITRE Engage, and threat emulation tools.

## ATT&CK Framework Foundation

Globally-accessible knowledge base of adversary tactics and techniques based on real-world observations, serving as foundation for threat model development in private sector, government, and cybersecurity product communities.

**TTP Breakdown:**
- **Tactic:** Adversary's goal or objective (the "why" of an attack)
- **Technique:** How adversary achieves their goal or objective
- **Procedure:** Implementation or how the technique is executed

**Evolution:** Initially focused on Windows platform in 2013, expanded to cover macOS, Linux, cloud platforms under Enterprise matrix. Specialized frameworks exist for Mobile and ICS. Framework grows through cybersecurity community contributions. Valuable for both defensive operations and red team attack simulation planning.

---

## ATT&CK Matrix Structure

Visual representation of all tactics and techniques within the framework. Tactics display across the top with techniques nested below, expandable to reveal sub-techniques.

**Navigation Example:**
1. **Tactic:** Reconnaissance (attacker's goal)
2. **Technique:** Active Scanning (how they achieve reconnaissance)
3. **Sub-technique:** Scanning IP Blocks, Vulnerability Scanning, or Wordlist Scanning

**Technique Page Contents:**
- Description and technique ID
- Sub-techniques listing
- Procedure examples (groups, software, campaigns)
- Mitigations
- Detections
- References

**ATT&CK Navigator:** Tool for annotating and exploring matrices with visualization capabilities.

- Create Account technique ID: **T1136**

## ATT&CK Practical Applications

### Framework Benefits

Provides standard and consistent language for describing adversary behavior. Unique IDs enable effective data comparison and incident analysis across security community. Bridges gap between threat intelligence and defensive operations by translating intelligence into detection logic, queries, and playbooks.

### Team Usage Reference

| Team | Goal | ATT&CK Usage |
|------|------|--------------|
| CTI Teams | Collect and analyze threat information | Map observed threat actor behavior to TTPs creating actionable industry-wide profiles |
| SOC Analysts | Investigate and triage security alerts | Link activity to tactics and techniques providing detailed context for alert prioritization |
| Detection Engineers | Design and improve detection systems | Map SIEM/EDR rules to ATT&CK ensuring better detection coverage |
| Incident Responders | Respond to and investigate incidents | Map incident timelines to tactics and techniques for attack visualization |
| Red & Purple Teams | Emulate adversary behavior to test defenses | Build emulation plans and exercises aligned with techniques and known group operations |

## Threat Group Analysis Example

**Mustang Panda (G0129):** China-based APT group targeting government entities, non-profits, and NGOs. Mapped to variety of ATT&CK techniques based on years of attacks.

**Known TTPs:**
- **Initial Access:** Phishing techniques
- **Persistence:** Scheduled tasks
- **Defense Evasion:** File obfuscation
- **Command and Control:** Ingress tool transfer
- **Reconnaissance:** Technique ID **T1598**
- **Access Token Manipulation:** Uses **Cobalt Strike** software

**Analysis Method:** Use Groups section on ATT&CK website, analyze behavior using Navigator layer and technique pages.

## Aviation Sector Threat Intelligence Scenario

**Context:** Security analyst in aviation sector with organization migrating infrastructure to cloud. Task involves using ATT&CK to gather intelligence on APT groups targeting this sector.

**APT33 Profile:**
- **Sector:** Targeted aviation sector
- **Active Since:** At least 2013
- **Cloud Concern:** Sub-technique **Cloud Accounts** (key concern for Office 365 users)
- **Associated Tool:** **Ruler** (linked to APT group and cloud accounts sub-technique)
- **Mitigation:** **User Account Management** (advises removing inactive/unused accounts)
- **Detection Strategy:** **DS0546** (implement to detect abused or compromised cloud accounts)

## Cyber Analytics Repository (CAR)

Knowledge base of analytics developed by MITRE based on ATT&CK adversary model. Defines data model leveraged in pseudocode representations with implementations for specific tools like Splunk and EQL. Focused on providing validated, well-explained analytics with operating theory and rationale.

**Purpose:** Collection of ready-made detection analytics built around ATT&CK. Each analytic describes how to detect adversary behavior, allowing defenders to identify patterns to look for.

**Example Analytic:** CAR-2020-09-001: Scheduled Task - File Access

**Implementation Components:**
- Pseudocode (plain, human-readable instruction description)
- Splunk query examples
- LogPoint search examples
- Unit Tests (for validation)

**Note:** Not every analytic has same implementation examples. CAR has its own ATT&CK Navigator layer mapping techniques to matrix.

**Lab Answers:**
- CAR-2019-07-001 associated tactic: **Defense Evasion**
- Access Permission Modification analytic type: **Situational Awareness**

## D3FEND Framework

D3FEND (Detection, Denial, and Disruption Framework Empowering Network Defense) is structured framework mapping defensive techniques and establishing common language for describing security control functionality.

**Purpose:** While ATT&CK shows how attacks happen, D3FEND shows how to stop them.

**Structure:** Matrix broken into seven tactics with associated techniques and IDs.

**Example Technique:** Credential Rotation (D3-CRO)
- **Purpose:** Regular password rotation preventing attackers from reusing stolen credentials
- **Content:** Explains defense functionality, implementation considerations, relationship to digital artifacts and ATT&CK techniques
- **Perspective:** Shows both attacker's move and defender's countermeasure

**Lab Answers:**
- User Behavior Analysis sub-technique for geolocation data analysis: **User Geolocation Logon Pattern Analysis**
- Digital artifact analyzed by this sub-technique: **Network Traffic**

## Additional MITRE Projects

### Adversary Emulation Library

Free resource of adversary emulation plans maintained by Center for Threat Informed Defense (CTID). Contains emulations mimicking real-world attacks by known threat groups. Provides step-by-step guides for mimicking specific threat groups.

---

### Caldera

Automated adversary emulation tool helping security teams test and enhance defenses. Simulates real-world attacker behavior utilizing ATT&CK framework, allowing defenders to evaluate detection methods and practice incident response in controlled environments. Supports both offensive and defensive operations for red and blue team exercises.

---

### AADAPT Framework

AADAPT (Adversarial Actions in Digital Asset Payment Technologies) is newly released knowledge base with its own matrix covering adversary tactics and techniques related to digital asset management systems. Follows similar structure to ATT&CK, helping defenders understand and mitigate threats targeting blockchain networks, smart contracts, digital wallets, and other digital asset technologies.

**Lab Answer:** Scrape Blockchain Data technique ID: **ADT3025**

---

### ATLAS Framework

ATLAS (Adversarial Threat Landscape for Artificial-Intelligence Systems) is knowledge base and framework with matrix focusing on threats targeting AI and machine learning systems. Documents real-world attack techniques, vulnerabilities, and mitigations specific to AI technology.

**Lab Answer:** LLM Prompt Obfuscation belongs to: **Defense Evasion** tactic

## Common Pitfalls

**Confusing Tactics with Techniques:** Tactics are the "why" (goals/objectives) while techniques are the "how" (methods). Defense Evasion is a tactic; Hide Artifacts is a technique within that tactic. Exam questions testing this distinction require careful reading to identify whether asking for tactic or technique.

**Ignoring Sub-techniques:** Many exam scenarios involve sub-techniques rather than parent techniques. Cloud Accounts is a sub-technique under Valid Accounts. Missing the sub-technique level leads to incomplete threat analysis and incorrect mitigation selection.

**Overlooking Mitigation vs Detection:** Mitigations prevent or reduce attack effectiveness (User Account Management removes inactive accounts). Detections identify attacks in progress (DS0546 detects compromised accounts). Questions asking "how would you stop this" require mitigations; questions asking "how would you detect this" require detection strategies.

**Misapplying CAR vs D3FEND:** CAR provides detection analytics with SIEM queries for identifying adversary behavior based on ATT&CK. D3FEND provides defensive techniques for stopping attacks. If the question involves writing detection rules or queries, use CAR. If the question involves implementing defensive controls, use D3FEND.

**Neglecting Framework Relationships:** ATT&CK, CAR, and D3FEND work together. ATT&CK describes attacker behavior. CAR translates that into detections. D3FEND provides defensive countermeasures. Understanding these relationships prevents confusion when questions reference multiple frameworks together.

**Assuming Single Tool Usage:** Different cybersecurity teams use ATT&CK differently. CTI teams map threat actor behavior. SOC analysts link alerts to TTPs. Detection engineers map SIEM rules. Incident responders map timelines. Red teams build emulation plans. Understanding team-specific usage helps contextualize exam scenarios properly.

**Overlooking Emerging Frameworks:** AADAPT and ATLAS are newer frameworks often overlooked in study. AADAPT covers blockchain and digital asset threats. ATLAS covers AI and ML system threats. Exam questions increasingly include these emerging technology areas requiring familiarity with specialized frameworks.

**Missing Technique ID Patterns:** ATT&CK technique IDs follow pattern T#### (e.g., T1136, T1598). D3FEND uses D3-XXX pattern (e.g., D3-CRO). AADAPT uses ADT#### pattern (e.g., ADT3025). Detection strategies use DS#### or DET#### patterns (e.g., DS0546). Recognizing these patterns helps quickly identify which framework a technique belongs to.
