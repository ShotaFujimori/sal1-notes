# 🐷 Snort — Reference Sheet

> **TL;DR:** Snort is an open-source NIDS/NIPS that operates in three modes: Sniffer (read packets), Packet Logger (save to PCAP), and IDS/IPS (match rules, alert/block). Rules have a fixed two-part structure — Rule Header + Rule Options — and are stored in `/etc/snort/rules/local.rules`. Mastering flags (`-v`, `-d`, `-e`, `-X`, `-l`, `-A`, `-r`, `-c`) is essential for the exam.

---

## ⚠️ Gotchas

| Gotcha | Detail |
|---|---|
| IDS = passive, IPS = active | IDS alerts only. IPS stops the connection. Snort is **passive by default**; you must activate inline mode for IPS. |
| No `<-` direction operator | Only `->` (one-way) and `<>` (bidirectional) exist. There is **no `<-`** operator. |
| Snort2 supports only 4 protocols in rules | IP, TCP, UDP, ICMP only. To detect FTP, filter `tcp port 21` — you cannot use `ftp` as the protocol. |
| `-K ASCII` logs cannot be read by Snort `-r` | ASCII format creates IP-named folders. Only binary (tcpdump) logs can be re-read with `snort -r`. |
| SID scope matters | `<100` = reserved; `100–999,999` = built-in; `>=1,000,000` = user rules. Don't overlap SIDs. |
| `-A none` still logs — it just disables alerts | Traffic is still logged in binary format even with `-A none`. The alert **file** is not created. |
| `fast_pattern` is required with multiple `content` options | When you have two or more `content` options in a rule, `fast_pattern` must be added or Snort may error. |
| IPS mode requires 2 interfaces | `snort -Q --daq afpacket -i eth0:eth1` — IPS needs at least two interfaces. |
| Baselining failure = bad NBA model | If an attack occurs during the NBA training (baselining) period, the anomaly model will treat malicious traffic as normal. |
| `rev` must be incremented on every rule edit | No auto-backup exists. Revision tracking is manual — always bump `rev` when you modify a rule. |
| `-D` (daemon mode) — no console output | Background mode produces no terminal output. Use `ps -ef | grep snort` to confirm it's running, `kill -9 <pid>` to stop. |

## 🔍 IDS vs IPS

| Feature | IDS | IPS |
|---|---|---|
| Mode | Passive monitoring | Active protection |
| Action on detection | Generate alert | Stop / terminate connection |
| User assistance required | Yes — user must act | Minimal |
| Snort default mode | ✅ IDS (passive) | Requires inline mode (`-Q --daq afpacket`) |

## 🏗️ IDS/IPS Types

| Type | Scope | Action |
|---|---|---|
| **NIDS** | Network (whole subnet) | Alert |
| **HIDS** | Single host/endpoint | Alert |
| **NIPS** | Network (whole subnet) | Terminate connection |
| **WIPS** | Wireless network | Terminate connection |
| **HIPS** | Single host/endpoint | Terminate connection |
| **NBA** (Network Behaviour Analysis) | Network | Terminate; requires baselining period |

## 🧠 Detection / Prevention Techniques

| Technique | Approach |
|---|---|
| **Signature-Based** | Matches known malicious patterns stored in DB. Fast, but blind to zero-days. |
| **Behaviour-Based** | Compares current traffic to known normal (baseline). Detects unknown/new threats. |
| **Policy-Based** | Compares activity against security policy config. Detects policy violations. |

## 👁️ Mode 1: Sniffer Mode Flags

| Flag | Description |
|---|---|
| `-v` | Verbose — display TCP/IP output on console (like tcpdump) |
| `-d` | Display packet **data payload** (includes verbose output) |
| `-e` | Display **link-layer headers** (MAC addresses, type) |
| `-X` | Display **full packet in HEX** (most detailed) |
| `-i eth0` | Sniff on a specific interface |

**Flag combinations:**
```bash
sudo snort -v              # Verbose only
sudo snort -vd             # Verbose + payload
sudo snort -de             # Payload + link-layer headers
sudo snort -v -d -e        # Same as above, separated
sudo snort -X              # Full HEX dump (most detailed)
```

## 📁 Mode 2: Packet Logger Mode

| Flag | Description |
|---|---|
| `-l <dir>` | Log to specified directory (default: `/var/log/snort`). Use `-l .` for current dir. |
| `-K ASCII` | Log in ASCII format (IP-named folders, human-readable). Default is binary/tcpdump. |
| `-r <file>` | Read/replay a previously logged binary file |
| `-n <N>` | Stop after processing N packets |

### Log to current directory (binary/tcpdump format)
```bash
sudo snort -dev -l .
# Creates: snort.log.<timestamp> (binary, ~6kB)
# Readable by Snort -r or Wireshark/tcpdump
```

### Log in ASCII format
```bash
sudo snort -dev -K ASCII -l .
# Creates: IP-address-named folders + snort.log.<timestamp>
# Folders contain files named by protocol:port (e.g. ICMP_ECHO, UDP:36648-53)
# Human-readable without Snort
```

### Read binary log with Snort
```bash
sudo snort -r snort.log.1638459842
# Replays and displays packets like sniffer mode
```

### Read log with tcpdump
```bash
sudo tcpdump -r snort.log.1638459842 -ntc 10
# -n: no DNS resolution, -t: no timestamps, -c 10: first 10 packets
```

### Filter log by protocol (BPF)
```bash
sudo snort -r logname.log icmp         # ICMP only
sudo snort -r logname.log tcp          # TCP only
sudo snort -r logname.log 'udp and port 53'  # UDP port 53 only
sudo snort -dvr logname.log -n 10      # First 10 packets with payload
```

### Fix log file ownership (root owns Snort logs)
```bash
sudo chown username file               # Single file
sudo chown username -R directory       # Recursive
```

## 🛡️ Mode 3: IDS/IPS Mode

### IDS/IPS Flags

| Flag | Description |
|---|---|
| `-c <file>` | Load configuration file (required for IDS/IPS) |
| `-T` | Test config file for errors |
| `-N` | Disable logging (alerts still show on console if `-v`) |
| `-D` | Background/daemon mode |
| `-A <mode>` | Alert output mode (see below) |

### Alert Modes (-A)

| Mode | Console Output | File Created | Detail Level |
|---|---|---|---|
| `console` | ✅ Yes | ✅ alert file | Fast-style (timestamp, IPs, ports, msg) |
| `cmg` | ✅ Yes | ✅ alert file | Full header + payload HEX+text |
| `fast` | ❌ No | ✅ alert file | Timestamp, IPs, ports, msg |
| `full` | ❌ No | ✅ alert file | All possible info (default when `-A` omitted) |
| `none` | ❌ No | ❌ No alert file | No alerts; still creates log file |

### Common IDS/IPS Commands

```bash
# Test config
sudo snort -c /etc/snort/snort.conf -T

# IDS mode with console alerts (recommended for real-time monitoring)
sudo snort -c /etc/snort/snort.conf -A console

# IDS mode with CMG alerts (payload detail)
sudo snort -c /etc/snort/snort.conf -A cmg

# IDS mode, disable logging
sudo snort -c /etc/snort/snort.conf -N

# IDS mode in background
sudo snort -c /etc/snort/snort.conf -D

# Run without config file (test local rules only, lower performance)
sudo snort -c /etc/snort/rules/local.rules -A console

# IPS mode (requires 2 interfaces)
sudo snort -c /etc/snort/snort.conf -q -Q --daq afpacket -i eth0:eth1 -A console
```

### Check/kill daemon
```bash
ps -ef | grep snort           # Find daemon PID
sudo kill -9 <pid>            # Kill daemon
```

## 📂 Mode 4: PCAP Investigation

| Flag | Description |
|---|---|
| `-r` / `--pcap-single=` | Read a single PCAP file |
| `--pcap-list="f1.pcap f2.pcap"` | Read multiple PCAPs (space-separated, quoted) |
| `--pcap-show` | Print PCAP filename to console during processing |

```bash
# Single PCAP with full config
sudo snort -c /etc/snort/snort.conf -q -r icmp-test.pcap -A console -n 10

# Multiple PCAPs
sudo snort -c /etc/snort/snort.conf -q --pcap-list="icmp-test.pcap http2.pcap" -A console

# Multiple PCAPs with source file label
sudo snort -c /etc/snort/snort.conf -q --pcap-list="icmp-test.pcap http2.pcap" -A console --pcap-show

# Log output to current dir
sudo snort -c /etc/snort/snort.conf -A full -l . -r mx-1.pcap
```

## 📐 Snort Rule Structure

```
alert icmp any any <> any any (msg:"ICMP Packet Found"; reference:cve,CVE-XXXX; sid:1000001; rev:1;)
|___| |__| |__||__| |  |__||__| |______________________________________________|
Action Proto SrcIP SrcPort Dir DstIP DstPort         Rule Options (in parentheses)
```

### Rule Header Fields

| Field | Options / Notes |
|---|---|
| **Action** | `alert` (generate alert + log), `log` (log only), `drop` (block + log), `reject` (block + log + terminate session) |
| **Protocol** | `ip`, `tcp`, `udp`, `icmp` — only these 4 in Snort2 |
| **Source/Dest IP** | `any`, `192.168.1.56`, `192.168.1.0/24`, `[subnet1, subnet2]`, `!192.168.1.0/24` (negation) |
| **Source/Dest Port** | `any`, `21`, `!21`, `1:1024`, `:1024`, `1025:`, `[21,23]` |
| **Direction** | `->` (src→dst only), `<>` (bidirectional). **No `<-`** |

### Rule Options (General)

| Option | Purpose | Example |
|---|---|---|
| `msg` | Alert message displayed when rule fires | `msg:"FTP Login Attempt";` |
| `sid` | Unique rule ID. User rules: `>=1,000,000` | `sid:1000001;` |
| `rev` | Revision number — increment every edit | `rev:1;` |
| `reference` | CVE or external reference | `reference:cve,CVE-2021-44228;` |

### Rule Options (Payload Detection)

| Option | Purpose | Example |
|---|---|---|
| `content` | Match specific string in payload (case-sensitive). ASCII or HEX. | `content:"GET";` or `content:"|47 45 54|";` |
| `nocase` | Disable case sensitivity for `content` | `content:"GET"; nocase;` |
| `fast_pattern` | Prioritise this content for initial match. **Required with multiple `content` options.** Case-insensitive, once per rule. | `content:"GET"; fast_pattern;` |

### Rule Options (Non-Payload Detection)

| Option | Purpose | Example |
|---|---|---|
| `id` | Filter by IP ID field | `id:35369;` |
| `flags` | Filter TCP flags: F=FIN, S=SYN, R=RST, P=PSH, A=ACK, U=URG | `flags:S;` (SYN only), `flags:PA;` (PSH+ACK) |
| `dsize` | Filter packet payload size | `dsize:100<>300;`, `dsize:>100;`, `dsize:<100;` |
| `sameip` | Match when src IP == dst IP | `sameip;` |

## 📝 Rule Examples

```snort
# Alert all ICMP (bidirectional)
alert icmp any any <> any any (msg:"ICMP Packet Found"; sid:1000001; rev:1;)

# Alert HTTP GET requests (ASCII)
alert tcp any any <> any 80 (msg:"GET Request Found"; content:"GET"; sid:1000001; rev:1;)

# Alert HTTP GET requests (HEX)
alert tcp any any <> any 80 (msg:"GET Request Found"; content:"|47 45 54|"; sid:1000001; rev:1;)

# Alert GET (case-insensitive)
alert tcp any any <> any 80 (msg:"GET Request Found"; content:"GET"; nocase; sid:1000001; rev:1;)

# Alert GET with fast_pattern (multiple content options)
alert tcp any any <> any 80 (msg:"GET Request Found"; content:"GET"; fast_pattern; content:"www"; sid:1000001; rev:1;)

# Alert FTP traffic (TCP port 21)
alert tcp any any <> any 21 (msg:"FTP Port 21 Activity"; sid:1000001; rev:1;)

# Alert traffic NOT to FTP port
alert tcp any any <> any !21 (msg:"Non-FTP Traffic"; sid:1000001; rev:1;)

# Alert by IP ID
alert tcp any any <> any any (msg:"IP ID Match"; id:35369; sid:1000001; rev:1;)

# Alert SYN packets
alert tcp any any <> any any (msg:"SYN Detected"; flags:S; sid:1000001; rev:1;)

# Alert PSH+ACK packets
alert tcp any any <> any any (msg:"PSH-ACK Detected"; flags:PA; sid:1000001; rev:1;)

# Alert same source/destination IP (UDP)
alert udp any any <> any any (msg:"Same IP UDP"; sameip; sid:1000001; rev:1;)

# IPS drop rule
reject icmp any any <> any any (msg:"ICMP Blocked"; sid:1000002; rev:1;)
```

## 🗂️ Snort2 Architecture Components

| Component | Role |
|---|---|
| **Packet Decoder** | Collects and prepares packets for pre-processing |
| **Pre-processors** | Arranges/modifies packets for the detection engine |
| **Detection Engine** | Processes packets; applies rules; primary analysis component |
| **Logging and Alerting** | Generates logs and alert files |
| **Outputs and Plugins** | Syslog/MySQL integrations; rule management plugins |

## 🧾 Snort Cheatsheet (All Key Commands)

```bash
# Version / instance check
snort -V

# Test config
sudo snort -c /etc/snort/snort.conf -T

# Sniffer mode
sudo snort -v                            # Verbose
sudo snort -vd                           # Verbose + payload
sudo snort -de                           # Payload + link-layer headers
sudo snort -X                            # Full HEX dump
sudo snort -v -i eth0                    # Specific interface

# Logger mode
sudo snort -dev -l .                     # Binary log to current dir
sudo snort -dev -K ASCII -l .            # ASCII log to current dir
sudo snort -v -r snort.log.XXXX          # Read binary log
sudo snort -v -r snort.log.XXXX -n 10    # Read first 10 packets
sudo snort -v -r snort.log 'udp and port 53'  # BPF filter

# IDS/IPS mode
sudo snort -c /etc/snort/snort.conf -A console    # Console alerts
sudo snort -c /etc/snort/snort.conf -A cmg        # CMG alerts
sudo snort -c /etc/snort/snort.conf -A fast       # Fast alerts (file only)
sudo snort -c /etc/snort/snort.conf -A full       # Full alerts (file only)
sudo snort -c /etc/snort/snort.conf -A none       # No alerts
sudo snort -c /etc/snort/snort.conf -N            # Disable logging
sudo snort -c /etc/snort/snort.conf -D            # Background daemon
sudo snort -c /etc/snort/rules/local.rules -A console  # Rules-only (no conf)

# IPS mode (2 interfaces required)
sudo snort -c /etc/snort/snort.conf -q -Q --daq afpacket -i eth0:eth1 -A console

# PCAP investigation
sudo snort -c /etc/snort/snort.conf -q -r file.pcap -A console
sudo snort -c /etc/snort/snort.conf -q --pcap-list="f1.pcap f2.pcap" -A console
sudo snort -c /etc/snort/snort.conf -q --pcap-list="f1.pcap f2.pcap" -A console --pcap-show
sudo snort -c /etc/snort/snort.conf -A full -l . -r file.pcap

# Edit local rules
sudo gedit /etc/snort/rules/local.rules
# or
sudo nano /etc/snort/rules/local.rules
```
