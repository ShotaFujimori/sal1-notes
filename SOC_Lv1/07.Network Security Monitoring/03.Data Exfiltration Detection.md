# 🔍 Data Exfiltration Detection — Reference Sheet

> **TL;DR:** Data exfiltration is the unauthorized outbound transfer of sensitive data. Attackers abuse DNS, FTP, HTTP, and ICMP to blend into normal traffic. Detection requires correlating host (Sysmon/EDR), network (Wireshark/pcap), and log (Splunk) telemetry — looking for large/frequent outbound transfers, abnormal protocol payloads, and suspicious process activity.

---

## ⚠️ Gotchas

| Gotcha | Detail |
|---|---|
| DNS is almost always allowed outbound | Attackers exploit this — DNS tunneling works precisely because port 53 is rarely blocked or inspected. |
| Normal ICMP ping ≈ 74 bytes | Anything over 100 bytes in an ICMP echo request is suspicious. Never assume pings are benign. |
| FTP sends credentials in cleartext | USER and PASS commands are visible in Wireshark with no decryption needed. |
| HTTP POST is the primary exfil method | GET can also carry data in query strings for low-and-slow exfiltration. Don't ignore GET. |
| High entropy ≠ encrypted traffic | Base64/Base32-encoded data in DNS subdomains looks random but is NOT necessarily encrypted — it may be decodable. |
| Long DNS query ≠ always malicious | Legitimate CDNs use long subdomains too. Correlate with query count + destination domain reputation. |
| `frame.len` includes headers | Actual payload is smaller than frame length. Use as a filter starting point, then verify in TCP/HTTP stream. |
| STOR = upload, RETR = download in FTP | Exfil = look for STOR (victim sending data OUT). RETR = attacker pulling data back. |
| Splunk sourcetype is case-sensitive | `sourcetype=DNS_logs` and `sourcetype=dns_logs` may return different results — match exactly. |
| Detection depends on correlation | No single log source is enough — always cross-reference proxy/firewall, DNS, Sysmon/EDR, and flow data. |

## 📋 Exfiltration Overview

### Why Attackers Exfiltrate Data

| Motivation | Description |
|---|---|
| Financial Gain | Sell credit cards, PII, credentials on dark web or use for fraud |
| Espionage | Nation-state actors steal IP, trade secrets, classified data |
| Ransomware & Extortion | Steal data first, then encrypt — dual extortion (e.g. DarkSide) |
| Disruption & Sabotage | Leak internal data to damage reputation |
| Persistence & Reconnaissance | Exfiltrated data informs future attack phases |

### Common Exfiltration Phases

| Phase | Description |
|---|---|
| Discovery / Collection | Attacker locates sensitive files on the host |
| Staging / Compression | Aggregates, compresses, encrypts files (ZIP, RAR, 7z, tar, base64, steganography) |
| Exfiltration Transport | Moves data over network, removable media, cloud, or covert channel |
| C2 Coordination | Orchestrates transfer and confirms receipt |

### Real-World Threat Actors

| Actor | Technique | Notes |
|---|---|---|
| APT29 (Cozy Bear) | HTTPS over legitimate domains | Encrypted channels from government networks |
| FIN7 | HTTP POST to C2 servers | Embedded stolen data in POST bodies |
| Lunar Spider (Zloader) | Encrypted C2 channels | Staged exfil over 2-month intrusion |
| DarkSide Ransomware | Dual extortion: exfil + encrypt | Threatened to leak before ransom |
| APT10 (Cloud Hopper) | Cloud-to-cloud transfer | Abused MSP cloud APIs |

## 🗂️ Exfiltration Techniques & Detection Sources

| Technique | Examples | Where to Look |
|---|---|---|
| **Network-based** | HTTP/S uploads, FTP/SFTP/SCP, DNS tunnelling, ICMP, custom TCP/UDP | Proxy/web gateway logs, firewall flows, netflow, DNS logs |
| **Host-based** | PowerShell/Invoke-WebRequest, rclone, awscli, curl/wget, archive creation, USB, ADS | Sysmon EventID 1/3/11, Windows Security 4663/4656, auditd, shell history |
| **Cloud exfiltration** | S3 PutObject, Azure Blob upload, GCS objects, Drive/SharePoint external sharing | CloudTrail, Azure Activity logs, GCP Audit logs |
| **Covert & encoding** | DNS tunnelling, base64/chunked encoding, steganography, low-and-slow splitting | DNS logs, proxy logs with many small POSTs |
| **Insider & collaboration tools** | Slack/Teams/Dropbox/GDrive uploads or external sharing | Audit logs (share events, file downloads), mail logs |

### General Triage Signals

Correlate across: **Proxy/Firewall/Netflow + DNS + Sysmon/EDR (EventID 1/3/11) + mail server logs**

- Large outbound volume to external IPs/domains
- Unknown destination domains
- Suspicious process/command lines
- Many file read events followed by outbound connection
- Multipart/streamed uploads

## 🌐 Task 4 — DNS Tunneling Detection

### How It Works
Data is encoded (Base32/Base64) into DNS subdomain labels and sent to an attacker-controlled resolver. DNS is allowed outbound on almost all networks, making it an ideal covert channel.

### Indicators of DNS Tunneling

| Indicator | Detail |
|---|---|
| High query count to one domain | Far more queries than baseline to a single external domain |
| Long subdomain labels | Full query name > 60–100 characters |
| High entropy in query name | Mixed case letters + digits + `-` or `=` (Base64 pattern) |
| Rare record types | TXT, NULL records or many large TXT responses |
| Queries with no response | Exfil-by-query technique — data is in the query itself |
| Regular timing | Beaconing behaviour — evenly spaced queries |

### Wireshark Filters — DNS Tunneling

```wireshark
# Show all DNS traffic
dns

# Show DNS queries with no response
dns.flags.response == 0

# Find long queries (suspicious subdomain lengths)
dns && frame.len > 70

# Filter on a specific suspicious domain
dns && dns.qry.name contains "tunnelcorp.net"
```

### Splunk Queries — DNS Tunneling

```spl
# Load all DNS logs
index=data_exfil sourcetype=DNS_logs

# Count DNS queries by source IP
index="data_exfil" sourcetype="DNS_logs" | stats count by src_ip

# Find most queried domains (sorted by count)
index="data_exfil" sourcetype="dns_logs" | stats count by query | sort -count

# Find long query names (subdomain encoding)
index="data_exfil" sourcetype="DNS_logs" | where len(query) > 30
```

### DNS Tunneling Investigation Summary

| Finding | Details |
|---|---|
| Suspicious domain | `tunnelcorp.net` |
| Suspicious log count | **315** |
| Host sending most requests | **192.168.1.103** |
| Compromised hosts | Multiple internal hosts (`192.168.1.101`–`.105`) |
| Method | Data sent in chunks in subdomain labels |

## 📁 Task 5 — FTP Exfiltration Detection

### How Attackers Use FTP

- Use legitimate or misconfigured FTP servers to transfer data
- Use compromised credentials (service accounts, guest accounts)
- Use non-standard ports to blend with other traffic

### FTP Key Commands

| Command | Direction | Significance |
|---|---|---|
| USER / PASS | Client → Server | Credentials sent **in cleartext** |
| STOR | Client → Server | Upload (potential exfiltration) |
| RETR | Server → Client | Download |
| PASV | Control channel | Opens ephemeral data port |

### Indicators of FTP Exfiltration

| Indicator | Detail |
|---|---|
| Cleartext credentials | USER/PASS visible in pcap |
| Suspicious usernames | Guest, test, dev, admin — unexpected accounts |
| STOR to external IPs | Repeated uploads to unusual destinations |
| Large data channel transfers | High byte count in PASV sessions |
| Transfers outside business hours | Off-hours activity |
| Sensitive file extensions | `.csv`, `.xlsx`, `.pdf`, `.txt` in STOR commands |

### Wireshark Filters — FTP

```wireshark
# Isolate FTP control and data traffic
ftp || ftp-data

# Show login attempts (credentials in cleartext)
ftp.request.command == "USER" || ftp.request.command == "PASS"

# Find upload commands
ftp contains "STOR"

# Filter for sensitive file types
ftp contains "csv"

# Find large payloads
ftp && frame.len > 90

# Follow TCP Stream
Right-click packet → Follow → TCP Stream
```

### FTP Investigation Summary

| Finding | Answer |
|---|---|
| Guest account connections | **5** |
| Customer file from root account | **customer_data.xlsx** |
| Host sending largest payload | **192.168.1.105** |
| Flag in CSV FTP stream | **THM{ftp_exfil_hidden_flag}** |

## 🌍 Task 6 — HTTP Exfiltration Detection

### How Attackers Use HTTP

| Technique | Description |
|---|---|
| POST uploads | Bulk data in POST body to attacker-controlled server |
| GET with encoded data | Small chunks in query strings (low-and-slow) |
| Custom headers | Data in headers (e.g. `X-Data: <base64>`) — evades DLP |
| Chunked/multipart | Large file split across multiple requests |
| HTTPS/TLS tunneling | Encrypted payload hides content; requires TLS inspection |
| Cloud service staging | Upload to Dropbox/GitHub/Gist then fetch externally |
| CDN abuse | Exfil disguised as uploads to popular services |

### Indicators of HTTP Exfiltration

| Indicator | Detail |
|---|---|
| Large HTTP POST to external host | High `bytes_sent` to unexpected destination |
| Low reputation destination domain | Domain not in baseline traffic |
| Beaconing + large upload | Frequent small GETs followed by one large POST |
| Chunked/multipart transfers | Multiple requests composing one file |

### Wireshark Filters — HTTP

```wireshark
# Show all HTTP traffic
http

# Filter POST requests only
http.request.method == "POST"

# Filter large POST requests (start at 500, increase to 750 to narrow down)
http.request.method == "POST" and frame.len > 500
http.request.method == "POST" and frame.len > 750

# Follow HTTP stream to view content
Right-click packet → Follow → HTTP Stream
```

### Splunk Queries — HTTP

```spl
# Load all HTTP logs
index="data_exfil" sourcetype="http_logs"

# Filter to POST requests only
index="data_exfil" sourcetype="http_logs" method=POST

# Stats on bytes sent by domain (identify large senders)
index="data_exfil" sourcetype="http_logs" method=POST
| stats count avg(bytes_sent) max(bytes_sent) min(bytes_sent) by domain
| sort - count

# Isolate large POST payloads (> 600 bytes)
index="data_exfil" sourcetype="http_logs" method=POST bytes_sent > 600
| table _time src_ip uri domain dst_ip bytes_sent
| sort - bytes_sent
```

|---|---|
| Compromised host | **192.168.1.103** |
| Flag in exfiltrated data | **THM{http_raw_3xf1ltr4t10n_succ3ss}** |

## 📡 Task 7 — ICMP Exfiltration Detection

### How Attackers Use ICMP

| Technique | Description |
|---|---|
| Echo (type 8) / Reply (type 0) tunneling | Encoded data (base64/hex) placed in ICMP payload |
| Custom ICMP types/codes | Uncommon types to avoid signature detection |
| Fragmentation | Large payloads split across multiple fragments |
| Encryption/obfuscation | Base64 payload looks like random data |

### ICMP Normal vs Suspicious

| | Normal Ping | Suspicious |
|---|---|---|
| Frame length | ~74 bytes | > 100 bytes |
| Frequency | Occasional | Burst/periodic |
| Destination | Internal or known test host | External, unknown |
| Payload | Echo pattern / ASCII | High entropy / base64 |
| Response | Reply received | No response found |

### Indicators of ICMP Exfiltration

| Indicator | Detail |
|---|---|
| Persistent ICMP to external host | Not used for legitimate monitoring |
| Large payloads > 64 bytes | Normal ping payload is 32–64 bytes |
| High entropy payload | Base64/hex patterns in payload bytes |
| Burst ICMP with no other traffic | Isolated ICMP sessions from one host |
| Regular timing | Periodically spaced requests = beaconing |

### Wireshark Filters — ICMP

```wireshark
# Show all ICMP traffic
icmp

# Isolate ICMP Echo Requests only
icmp.type == 8

# Find oversized ICMP packets (suspicious if > 100 bytes)
icmp.type == 8 and frame.len > 100

# Normal ping = ~74 bytes total; > 100 = suspicious
```

### ICMP Investigation Summary

| Finding | Answer |
|---|---|
| Flag in ICMP exfiltrated data | **THM{1cmp_3ch0_3xf1ltr4t10n_succ3ss}** |

## 🔧 Filter Quick Reference — All Protocols

### Wireshark

| Protocol | Filter | Purpose |
|---|---|---|
| DNS | `dns` | All DNS traffic |
| DNS | `dns.flags.response == 0` | Queries with no response |
| DNS | `dns && frame.len > 70` | Long DNS queries |
| DNS | `dns && dns.qry.name contains "domain"` | Specific suspicious domain |
| FTP | `ftp \|\| ftp-data` | FTP control + data |
| FTP | `ftp.request.command == "USER" \|\| ftp.request.command == "PASS"` | Credentials |
| FTP | `ftp contains "STOR"` | Upload commands |
| FTP | `ftp contains "csv"` | Sensitive file types |
| FTP | `ftp && frame.len > 90` | Large FTP payloads |
| HTTP | `http` | All HTTP |
| HTTP | `http.request.method == "POST"` | POST requests |
| HTTP | `http.request.method == "POST" and frame.len > 750` | Large POST payloads |
| ICMP | `icmp` | All ICMP |
| ICMP | `icmp.type == 8` | Echo requests only |
| ICMP | `icmp.type == 8 and frame.len > 100` | Oversized pings |
