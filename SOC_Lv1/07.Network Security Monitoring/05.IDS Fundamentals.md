# 🛡️ IDS Fundamentals — Reference Sheet

> **TL;DR:** An Intrusion Detection System (IDS) monitors network or host activity and alerts security teams when suspicious behavior is detected — it detects but does **not** prevent threats. Snort is the most popular open-source IDS, operating in three modes (Sniffer, Packet Logging, NIDS) and using rule files to match known attack signatures.

---

## ⚠️ Gotchas

| Gotcha | Detail |
|---|---|
| IDS ≠ IPS | IDS only **detects and alerts** — it does NOT block or prevent. That's IPS (Intrusion *Prevention* System). |
| Signature-based cannot detect zero-days | No signature in the database = no detection. Zero-days are invisible to signature-only IDS. |
| Anomaly-based generates false positives | Legitimate programs that "behave unusually" get flagged. Fine-tuning the baseline is essential. |
| Promiscuous mode required for full NIDS | Without it, Snort only captures traffic destined for its own host — not all network traffic. |
| `$HOME_NET` is a variable | It's defined in `snort.conf`, not hardcoded in rules. If misconfigured, rules targeting `$HOME_NET` may not fire. |
| Custom rules go in `local.rules` | Do NOT add custom rules to built-in rule files. Use `/etc/snort/rules/local.rules`. |
| `sid` must be unique | Duplicate SIDs cause rule conflicts. Custom rules typically start at `10001`+. |
| `rev` increments on every edit | Every time you modify a rule, bump the `rev` number to track changes. |
| PCAP analysis uses `-r` flag | Real-time traffic uses `-i <interface>`. Offline PCAP analysis uses `-r <file.pcap>`. |
| Packet Logging mode ≠ NIDS mode | Logging mode captures raw traffic to PCAP. NIDS mode applies rules and generates alerts. |

## 🔍 IDS vs Firewall

| Aspect | Firewall | IDS |
|---|---|---|
| Position | Network boundary (perimeter) | Inside the network |
| When it acts | Before connection is established | After traffic has passed through |
| Action | Blocks/allows traffic | Detects and alerts only |
| Analogy | Building gatekeeper | Surveillance camera |

---

## 🏗️ Deployment Modes

| Type | Scope | Pros | Cons |
|---|---|---|---|
| **HIDS** (Host-based IDS) | Single host | Deep visibility into host activities | Resource-intensive; hard to manage at scale |
| **NIDS** (Network-based IDS) | Entire network | Centralized view; detects lateral movement | Less granular per-host detail |

---

## 🧠 Detection Modes

| Mode | How It Works | Zero-Day Detection | False Positives |
|---|---|---|---|
| **Signature-Based** | Matches traffic against known attack signatures in DB | ❌ Cannot detect | Low |
| **Anomaly-Based** | Learns baseline behavior; flags deviations | ✅ Can detect | High (needs fine-tuning) |
| **Hybrid** | Combines signature + anomaly detection | ✅ Can detect | Moderate |

**Key point:** Signature-based = fast and precise for known threats. Anomaly-based = needed for modern zero-days.

## ⚙️ Snort Modes

| Mode | Description | Use Case |
|---|---|---|
| **Packet Sniffer** | Reads and displays packets without analysis | Network troubleshooting/diagnostics |
| **Packet Logging** | Logs traffic to PCAP file for later analysis | Forensic investigation, root cause analysis |
| **NIDS Mode** | Applies rules in real-time; generates alerts | Primary IDS function — proactive monitoring |

## 📐 Snort Rule Format

```
alert icmp any any -> $HOME_NET any (msg:"Ping Detected"; sid:10001; rev:1;)
```

| Field | Example | Description |
|---|---|---|
| **Action** | `alert` | What to do when rule matches (alert, log, drop, etc.) |
| **Protocol** | `icmp` | Protocol to match: `icmp`, `tcp`, `udp`, `ip` |
| **Source IP** | `any` | Origin IP address (`any` = all IPs) |
| **Source Port** | `any` | Origin port (`any` = all ports) |
| **Direction** | `->` | Traffic direction (`->` = one-way, `<>` = bidirectional) |
| **Destination IP** | `$HOME_NET` | Target IP; `$HOME_NET` is defined in `snort.conf` |
| **Destination Port** | `any` | Target port |
| **msg** | `"Ping Detected"` | Alert message displayed when rule fires |
| **sid** | `10001` | Unique Signature ID for this rule |
| **rev** | `1` | Rule revision number (increment on each edit) |

## 💻 Snort Commands

### Start NIDS mode (real-time traffic)

**Purpose:** Monitor live traffic on an interface using rules from `snort.conf`.

```bash
sudo snort -q -l /var/log/snort -i lo -A console -c /etc/snort/snort.conf
# -q         : Quiet mode (suppress banner)
# -l         : Log directory
# -i lo      : Network interface (lo = loopback; replace with eth0 etc.)
# -A console : Output alerts to console
# -c         : Path to Snort config file
```

### Run Snort on a PCAP file (offline forensics)

**Purpose:** Replay and analyze historical traffic from a PCAP file.

```bash
sudo snort -q -l /var/log/snort -r Task.pcap -A console -c /etc/snort/snort.conf
# -r Task.pcap : Read from PCAP file instead of live interface
# Replace Task.pcap with the actual file path
```

### List Snort directory contents

**Purpose:** View all config files and rule folders.

```bash
ls /etc/snort
# Output: classification.config  reference.config  snort.debian.conf
#         community-sid-msg.map  rules             threshold.conf
#         gen-msg.map            snort.conf         unicode.map
```

### Edit custom rules

**Purpose:** Add or modify custom Snort rules.

```bash
sudo nano /etc/snort/rules/local.rules
# After editing: Ctrl+X → Y → Enter to save
```

## 📝 Sample Custom Rule (Loopback Ping)

```snort
alert icmp any any -> 127.0.0.1 any (msg:"Loopback Ping Detected"; sid:10003; rev:1;)
```

**What it does:** Alerts when any ICMP (ping) packet is sent to the loopback address `127.0.0.1`.

**Test it:**
```bash
ping 127.0.0.1
# Expected alert: [1:1000001:1] Loopback Ping Detected {ICMP} 127.0.0.1 -> 127.0.0.1
```

---

## 🔬 Snort Alert Output Format

```
07/24-10:46:52.401504 [**] [1:1000001:1] Loopback Ping Detected [**] [Priority: 0] {ICMP} 127.0.0.1 -> 127.0.0.1
```

| Part | Meaning |
|---|---|
| `07/24-10:46:52.401504` | Timestamp of detection |
| `[1:1000001:1]` | `[generator_id:sid:rev]` |
| `Loopback Ping Detected` | Alert message (from `msg:`) |
| `[Priority: 0]` | Rule priority level |
| `{ICMP}` | Protocol |
| `127.0.0.1 -> 127.0.0.1` | Source IP → Destination IP |
