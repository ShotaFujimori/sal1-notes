# 🛡️ Network Security Monitoring: Network Security Essentials — Reference Sheet

> **TL;DR:** Network security monitoring starts at the perimeter — the boundary between trusted internal networks and the untrusted Internet. SOC analysts monitor two log categories (host-centric and network-centric) to detect attack stages: reconnaissance → initial access → lateral movement → C2 beaconing → data exfiltration. The firewall is the first log to check; correlate with IDS and VPN logs to build a full attack timeline.

---

## ⚠️ Gotchas

| Gotcha | Detail |
|---|---|
| Perimeter ≠ single device | The network perimeter is a collection of controls: firewall, DMZ, VPN gateway, routers — not just one box. |
| Host logs ≠ network logs | Host logs tell you *what happened on a machine*; network logs tell you *who entered/left the network*. Both are required to build a complete timeline. |
| Firewall ALLOW is not always safe | Allowed traffic can still be malicious — an attacker who passes the firewall still shows up in IDS/VPN logs. |
| Port scan = many ports, one source IP | Repetition from one source to many ports on one destination = port scan. Don't mistake it for brute-force. |
| Brute-force = many attempts, one destination | Repetition from one source to one destination/service repeatedly = brute-force / credential stuffing. |
| Regular-interval traffic = C2 beaconing | Perfect time intervals between outbound connections strongly indicate malware beaconing to a C2 server. |
| VPN success after many failures = breach | A burst of FAILED_AUTH followed by SUCCESS_AUTH from the same IP is the telltale sign of a successful brute-force breach. |
| DMZ servers are intentionally exposed | Public-facing servers (web, mail, VPN) live in the DMZ — they *should* receive external traffic, so unusual DMZ traffic needs context. |
| AD compromise = full enterprise at risk | A single compromised domain admin account can give an attacker control over all users, machines, and services in the enterprise. |
| Endpoints are the most common entry point | Phishing and malicious downloads target endpoints first. Lateral movement follows, so endpoint compromise ≠ contained incident. |
| IDS context > firewall block | A firewall block only tells you something was stopped. An IDS alert tells you *what type of attack* it was and *why* it was flagged. |
| Data exfiltration uses normal ports | Exfiltration often uses HTTP (80) or HTTPS (443/8080) to blend in — large outbound POST requests to external IPs are a key indicator. |

## 🏗️ Network Components — Security Relevance

| Component | Role | Attack Relevance |
|---|---|---|
| User Workstations (Endpoints) | Daily work; PCs and laptops | Most common entry point via phishing/malware; gateway for lateral movement |
| File & Database Servers | Store business-critical data | Primary ransomware and exfiltration target |
| Application Servers (Web/Email/VPN) | External-facing services | High-value targets; constantly scanned for vulns; SQL injection, brute-force |
| Active Directory (AD) | Identity backbone; manages users, groups, computers | Target for privilege escalation, persistence, lateral movement |
| Routers & Switches | Network infrastructure; internal communication | If compromised → MitM, traffic rerouting, hidden channels |
| Firewalls / Perimeter Devices | Traffic gatekeeper between internal and external | Logs every connection attempt; first indicator of port scans, brute-force, exploits |

## 👁️ Network Visibility — Log Source Comparison

| Attribute | Host-Centric Logs | Network-Centric Logs |
|---|---|---|
| Generated by | Individual devices (servers, workstations, laptops) | Network appliances (firewalls, IDS/IPS, VPN, proxy) |
| Shows | What happened *on* a specific machine | What happened *between* machines / at the perimeter |
| Answers | Who logged in, what ran, what changed | Who connected to whom, from where, when |
| Examples | Windows Event Log, syslog, EDR, AV, app logs | Firewall logs, IDS alerts, VPN logs, web proxy, router flow |
| Best for | Forensics, process tracking, malware impact | Reconnaissance detection, C2 ID, lateral movement, exfiltration |
| Analogy | What happened *inside a room* | Who *entered/left the building* |

> **Core principle:** Correlate both to build a complete attack timeline.

## 🌐 Network Perimeter Components

| Component | Function |
|---|---|
| Firewall | Filters traffic in/out based on rules; logs all allowed/blocked connections |
| Router / Gateway | Routes traffic between networks; enforces access rules |
| DMZ (Demilitarized Zone) | Buffer zone hosting public-facing servers (web, mail, VPN); isolated from internal LAN |
| VPN Gateway | Secure remote access for employees; logs who connects, from where, when |

### Enterprise Perimeter Layout (Small Business Model)

```
Internet
    |
[Firewall]
    |
[DMZ] — Web Server (public access)
    |
[Internal LAN]
    ├── AD / Auth Server
    ├── File / DB Server
    └── Employee Workstations
    |
[VPN Gateway] — Remote employees
```

## 🔍 Key Perimeter Threat Patterns

| Pattern | Indicator | Log Source |
|---|---|---|
| Port Scanning | Same source IP hits many ports on one target in rapid succession | Firewall (BLOCK entries) |
| Brute-Force Login | Many FAILED_AUTH events from same source IP to same service | VPN / Auth logs |
| Web Application Attack | WAF/IDS BLOCK with `attack_type` = SQL Injection / XSS / Directory Traversal | WAF / IDS logs |
| C2 Beaconing | Regular-interval outbound connections to external IP on unusual port (e.g. 4444) | IDS logs (`ET TROJAN Possible C2 Beaconing`) |
| Lateral Movement | Internal host scanning other internal hosts (SMB 445, RDP 3389, SSH 22) | Firewall + IDS logs |
| Data Exfiltration | Large outbound HTTP POST traffic to external IP on port 80/8080 | IDS (`ET INFO Possible HTTP POST Large Upload`) + Firewall |

## 📋 Firewall Log Format & Analysis

```
<timestamp> <ACTION> <PROTOCOL> <SRC_IP>:<SRC_PORT> -> <DST_IP>:<DST_PORT>
```

**Example:**
```
2025-09-22 08:30:05 BLOCK TCP 203.0.113.10:50001 -> 10.0.0.20:21
2025-09-22 08:30:06 BLOCK TCP 203.0.113.10:50002 -> 10.0.0.20:22
2025-09-22 08:30:08 BLOCK TCP 203.0.113.10:50003 -> 10.0.0.20:23
```
→ Same source IP hitting sequential ports = port scan.

### Useful CLI Commands

```bash
# Show all blocked traffic
cat firewall.log | grep "BLOCK" | head

# Count blocked requests by source IP (find top scanner)
cat firewall.log | grep "BLOCK" | cut -d' ' -f5 | cut -d: -f1 | sort | uniq -c | sort -nr

# Find ALLOW traffic from a specific suspicious IP
cat firewall.log | grep <SUSPICIOUS_IP> | grep "ALLOW"

# Show all traffic from compromised internal host
cat firewall.log | grep <INTERNAL_IP> | grep "ALLOW" | head
```

## 📋 IDS / IDS Alerts Log Format & Analysis

```
<timestamp> [**] [SID:REV] <RULE_NAME> [**] [Classification: <TYPE>] [Priority: N] {PROTOCOL} <SRC>:<PORT> -> <DST>:<PORT>
```

**Example:**
```
2025-09-05 06:10:00 [**] [1:2000201:1] ET EXPLOIT Possible MS-SMB Lateral Movement [**]
  [Classification: Attempted Unauthorized Access] [Priority: 1] {TCP} 10.8.0.23:2001 -> 10.0.0.20:445
```

### Useful CLI Commands

```bash
# Find all C2 beaconing alerts
cat ids_alerts.log | grep C2 | head

# Find SMB lateral movement alerts from a host
cat ids_alerts.log | grep <IP> | grep 'SMB' | cut -d' ' -f6,7,8,9,10,19,21 | head

# Count alert types from a specific host
cat ids_alerts.log | grep <IP> | cut -d' ' -f6,7,8,9,10,19,22,23 | uniq -c | sort -nr | head

# Find data exfiltration indicators
cat ids_alerts.log | grep <IP> | tail
```

---

## 📋 VPN Auth Log Format & Analysis

```
<timestamp> <SRC_IP> <USERNAME> <STATUS> [assigned_ip=<VPN_IP>]
```

**Example:**
```
2025-09-03 02:19:00 45.137.22.13 svc_backup FAIL
2025-09-03 02:19:40 45.137.22.13 svc_backup SUCCESS assigned_ip=10.8.0.23
```
→ Burst of FAIL → SUCCESS from same IP = successful brute-force.

### Useful CLI Commands

```bash
# Count failed attempts by source IP
cat vpn_auth.log | grep FAIL | cut -d' ' -f3 | sort | uniq -c | sort -nr

# Investigate all activity from suspicious IP
cat vpn_auth.log | grep <SUSPICIOUS_IP>
```

## 🗺️ Attack Investigation Workflow

| Stage | What to Look For | Primary Log |
|---|---|---|
| 1. Reconnaissance | BLOCK events; one IP hitting many ports on one target | `firewall.log` |
| 2. Initial Access | ALLOW on sensitive ports (22, 445, 3389); VPN brute-force → SUCCESS | `firewall.log`, `vpn_auth.log` |
| 3. Lateral Movement | Internal IP scanning other internal hosts (SSH/SMB/RDP) | `firewall.log`, `ids_alerts.log` |
| 4. C2 Beaconing | Regular-interval outbound to external IP on port 4444 | `ids_alerts.log` |
| 5. Data Exfiltration | Large HTTP POST from internal host to external IP (80/8080) | `ids_alerts.log`, `firewall.log` |

### Splunk Query (pre-ingested as `index="network_logs"`)
- Source types: `firewall_logs`, `ids_logs`, `vpn_logs`
- Access via `localhost:8000` → Search & Reporting
