
# 56.SAL1 — SOC Workbooks and Lookups — Cheat Sheet

**Focus:** Streamlining alert triage using Asset/Identity Inventories, Network Diagrams, and structured SOC Workbooks (Playbooks).

## TL;DR

* **Context is King:** You cannot triage an alert without knowing **WHO** (Identity) and **WHAT** (Asset) is involved.
* **Identities:** Use inventories (Active Directory, HR Systems) to determine if a user *should* be accessing a resource.
* **Assets:** Use inventories (CMDB, EDR) to know what a server holds (e.g., Financial Records) and its location.
* **Network Diagrams:** Use maps to validate if traffic flow (e.g., VPN  Database) is physically possible or blocked.
* **Workbooks:** Always follow the structured 3-step process: **Enrichment  Investigation  Escalation**.

---

## 1. Context Gathering (Assets & Identities)

**Concept:** Before analyzing *behavior*, validate the *entities*. Is the user a sysadmin? Is the server critical?

### Action: Identity Lookup

**Command/Logic:** `Lookup User Role & Location`
**Explanation:** Check Active Directory (AD) or HR systems (e.g., BambooHR) to verify the user's role.
**Example:**

* **Alert:** User `R.Lund` accessed `Financial Report US 2024.xlsx`.
* **Lookup:** `R.Lund` is a **US Financial Adviser**.
* 
**Verdict:** Access is **Legitimate/Expected**.



### Action: Asset Lookup

**Command/Logic:** `Lookup Host Purpose & Owner`
**Explanation:** Check the Asset Inventory (Excel, EDR, Intune) to identify what data lives on the target server.
**Example:**

* **Alert:** Login to `HQ-FINFS-02` (IP: `172.16.15.89`).
* 
**Lookup:** Server is a **File Server for financial records** located in the **UK Datacenter**.


* **Verdict:** High-value target; closely monitor access logs.

## 2. Network Diagrams (Traffic Analysis)

**Concept:** Visualizing the physical and logical path of an attack to understand the adversary's movement.

### Action: Trace Attack Path

**Command/Logic:** `Map IP $\rightarrow$ Subnet $\rightarrow$ Rules`
**Explanation:** Use the network diagram to correlate External IPs, Internal NAT IPs, and Subnet ACLs.

Scenario Walkthrough (The VPN Attack):

1. **Ingress:** Threat Actor (`103.61.240.174`) hits `vpn.tryhatme.thm` on **Port 10443**.
2. **Access:** Brute-force succeeds; Actor assigned internal IP `10.10.0.53` (VPN Subnet).
3. **Lateral Movement:** Actor scans `172.16.15.0/24` (**Database Subnet**).
4. **Pivot:** Scan blocked by Firewall; Actor switches to `172.16.23.0/24` (**Office Subnet**).

**Verdict:** **True Positive (TP)**.

## 3. SOC Workbooks (Structured Investigation)

**Concept:** A standardized guide (Playbook/Runbook) ensuring every analyst takes the same steps for a specific alert type.

### Action: Execute Workbook Phases

**Command/Logic:** `Follow Phases: Enrichment $\rightarrow$ Investigation $\rightarrow$ Escalation`

**Phase 1: Enrichment**

* **Task:** Gather context using TI (Threat Intel) and Lookups.
* 
**Example:** "Compile list of email recipients", "Identify User Roles".



**Phase 2: Investigation**

* **Task:** Analyze evidence (Sandboxing, Logs).
* 
**Example:** "Analyze attachment in Sandbox", "Review VPN login history".



**Phase 3: Escalation/Response**

* **Task:** Take action (Block, Reset, Report).
* 
**Example:** "Block attachment on EDR", "Write report findings".

## Gotchas & Pitfalls

* **Stale Data:** Asset inventories (especially Excel sheets) are often outdated. If a server says "Test Server" but has high traffic, verify with IT.


* **Hidden Context:** A "Finance Manager" might be logging in from a strange location (e.g., vacation). Don't ban legitimate users; check the **Unusual Login Workbook** first.


* **Skipping Steps:** L1 Analysts must follow the workbook *precisely*. Skipping "Enrichment" leads to false positives; skipping "Escalation" leads to breaches.
