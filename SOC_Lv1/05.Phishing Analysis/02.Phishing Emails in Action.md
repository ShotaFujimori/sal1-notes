# 🎣 Phishing Emails in Action — Reference Sheet

> **TL;DR:** Phishing emails use social engineering (urgency, brand impersonation, spoofed addresses) to trick victims into clicking malicious links or opening weaponized attachments. Always verify the sender, inspect raw source, and never interact with suspicious links/attachments directly.

---

## ⚠️ Gotchas

- **Display name ≠ actual sender address** — Always check the raw `From:` field, not just the display name.
- **Shortened URLs hide true destinations** — Use tools like [WhereGoes](https://wheregoes.com) to expand without visiting.
- **AI-generated phishing is now polished** — Typos/grammar errors are no longer reliable indicators.
- **Tracking pixels phone home** — Opening an email can notify attackers even before you click anything.
- **Legitimate brand domains in a URL ≠ legitimate URL** — e.g., `apps.ios.superlongfakesite.com` is still malicious.
- **BCC hides the real recipient list** — Victims may not even appear in the `To:` field.
- **`.dot` / `.xlsx` files can execute code** — Non-standard attachment types are major red flags.

## Task 2 — Cancel Your Order (PayPal Spoof)

### Techniques
| Technique | Description |
|---|---|
| Spoofed email address | Display name `service@paypal.com` but actual sender is `gibberish@sultanbogor.com` |
| URL shortening | Button links to `https://is.gd/6oCJ4m` — true destination hidden |
| Branded HTML | Legitimate PayPal-style layout to fake authenticity |

### Investigation Steps

**1. Check raw sender address**
```
# In email client: View > Show Original / Raw Source
From: service@paypal.com <gibberish@sultanbogor.com>
# Flag: display name ≠ actual address
```

**2. Expand shortened URL (safe, no visit)**
```
# Tool: https://wheregoes.com
# Input: https://is.gd/6oCJ4m
# Output: reveals true destination before clicking
```

**3. Inspect HTML source for hyperlinks**
```html
<!-- Look for href in anchor tags -->
<a href="https://is.gd/6oCJ4m">Cancel the order</a>
<!-- Flag: shortened URL in CTA button -->
```

### Key Answer
- **Merchant listed:** Amazing Stuff

## Task 3 — Track Your Package (Shipping Spoof)

### Techniques
| Technique | Description |
|---|---|
| Spoofed email address | Display name `Distribution Center`, actual: `contact@beginpro.club` |
| Pixel tracking | Invisible `Tracking.png` image reports email-open event to attacker |
| Link manipulation | Fake tracking number hyperlink masks malicious destination |

### Investigation Steps

**1. Check spoofed sender**
```
From: Distribution Center <contact@beginpro.club>
# Flag: legitimate distribution centers don't use .club domains
```

**2. Find tracking pixel in raw source**
```html
<!-- Look for 1x1 or tiny image tags -->
<img src="https://attacker.com/Tracking.png" width="1" height="1" />
# Flag: invisible image = tracking pixel
```

**3. Defang and analyze hyperlink destination**
```
# Defanged URL format (safe to share/log):
devret[.]xyz
# Replace . with [.] to prevent accidental clicking
```

**Why Yahoo blocked images:** Email providers auto-block remote images to prevent tracking pixels from firing.

### Key Answer
- **Hyperlink root domain (defanged):** `devret[.]xyz`

## Task 4 — Download Document Here (Multi-Stage Redirect)

### Techniques
| Technique | Description |
|---|---|
| Artificial urgency | Link "expires" same day email was sent |
| Brand impersonation | Chains OneDrive → Adobe → fake login portal |
| Link redirection | Multi-hop URL chain bypasses email filters |
| Credential harvesting | Fake login portal captures & exfiltrates credentials |

### Redirect Chain
```
Email CTA Button
    └─► Fake OneDrive page
            └─► Fake Adobe page (suspicious URL)
                    └─► Fake login portal (Outlook/email login)
                                └─► Credentials sent to attacker's server
                                    (victim always gets "generic error")
```

### Investigation Steps

**1. Identify urgency signals**
```
Send date:       Thu, July 15, 2021
Expiry date:     July 15, 2021  ← same day = artificial pressure
```

**2. Recognize credential harvesting portal**
```
# Signs:
- Asks for email + password to "view a document"
- Any credentials entered = "invalid" error
- No real authentication occurring
- Credentials forwarded directly to attacker
```

### Key Answer
- **Attack type:** Credential Harvesting

## Task 5 — Your Account Is on Hold (Netflix Spoof)

### Techniques
| Technique | Description |
|---|---|
| Spoofed display name | `Netllx billing` (misspelled) hides `z99@musacombi.online` |
| Sense of urgency | "Account suspended" triggers immediate action |
| Brand impersonation | HTML templates mimic Netflix branding |
| Malicious attachment | PDF with embedded malicious link instead of direct URL |

### Investigation Steps

**1. Spot brand misspelling in display name**
```
Display name: "Netllx billing"  ← double-l, not Netflix
Actual sender: z99@musacombi.online
```

**2. Inspect PDF attachment**
```
# Attachment contains: "Update Payment Account" button
# Button URL: NOT a netflix.com domain
# Verify with: pdfinfo, pdf-parser, or sandboxed viewer
```

**3. Additional red flags**
```
- Atypical phone number format
- Legitimate help domain used to build false trust
```

### Key Answer
- **Actual sender:** `z99@musacombi.online`

## Task 6 — Your Recent Purchase (Apple Spoof)

### Techniques
| Technique | Description |
|---|---|
| Spoofed display name | `Apple Support` hides `donoreply-storemailsedmopzl07zo7o9@sumpremed.com` |
| BCC recipient | Victim not in `To:` — received via Blind Carbon Copy |
| Blank email body | Entire content is in the attachment only |
| `.dot` file attachment | Microsoft Word Template — unusual for a receipt |

### Investigation Steps

**1. Check BCC usage**
```
To:  noreply.payament_@app.apple.iud456.com  ← fake Apple domain
Bcc: victim@yahoo.com  ← actual recipient hidden
# Flag: BCC hides the true recipient list from spam filters
```

**2. Analyze .dot attachment**
```
# .dot = Microsoft Word Template (not a normal receipt format)
# Contains: large embedded image as clickable link
# Clicking redirects to phishing site
# URL contains "apps" and "ios" to appear legitimate
# Flag: excessive URL length and complexity
```

### Key Answers
- **BCC stands for:** Blind Carbon Copy
- **Attachment extension:** `.dot`

## Task 7 — Scheduled Shipment (DHL Spoof)

### Techniques
| Technique | Description |
|---|---|
| Spoofed email address | Display name `DHL Express`, actual: `info@glamcarcompany.de` |
| Brand impersonation | HTML/logos mimic DHL branding |
| Malicious `.xlsx` attachment | Excel file triggers executable payload on open |

### Investigation Steps

**1. Spot geographic inconsistencies in attachment**
```
Sender domain:    .de (German)
Invoice address:  city in India
Document content: Mandarin text
# Flag: mismatched geos = classic red flag
```

**2. Analyze Excel macro/payload behavior**
```
# On clicking link inside .xlsx:
Attempts to download: regasms.exe
# .exe from a spreadsheet = malicious payload
```

**3. Understand payload impact if executed**
```
Persistence:   Create backdoor / scheduled task
Exfiltration:  Steal files, credentials, browser passwords
Ransomware:    Encrypt system, demand payment
```

### Key Answer
- **Executable name:** `regasms.exe`

## Quick Reference: Red Flags Summary

| Red Flag | What to Check |
|---|---|
| Display name ≠ sender address | Raw `From:` header |
| Urgency / expiring links | Deadlines on same day as send date |
| Shortened URLs | Expand via WhereGoes before clicking |
| Tracking pixels | `<img>` tags with tiny dimensions in raw HTML |
| Unusual attachment types | `.dot`, `.xlsx` with macros, unexpected PDFs |
| Multi-stage redirects | Hover/trace each hop in the chain |
| Credential portals | Always returns "error" — sends creds to attacker |
| BCC recipient | Check `To:` vs `Bcc:` fields |
| Geo inconsistencies | Domain country ≠ invoice country ≠ content language |
