# 🪟 Windows Event Logs — Reference Sheet

> **TL;DR:** Windows Event Logs are binary `.evtx` files (in `C:\Windows\System32\winevt\Logs`) that record system, security, and application activity. You query them three ways: **Event Viewer** (GUI, `eventvwr.msc`), **wevtutil.exe** (CLI), and **Get-WinEvent** (PowerShell). Filter efficiently with **FilterHashtable** or **XPath**, and know the key Event IDs (4104, 4688, 4720, 4799, 1102, 7045…) — some only appear after you enable PowerShell logging / Audit Process Creation.

---

## ⚠️ Gotchas

| Gotcha | Detail |
|---|---|
| Not text files | `.evt` / `.evtx` are proprietary binary; view via Windows API → XML, not a text editor |
| Event IDs are NOT unique | Same ID means different things in different logs (4103 = Executing Pipeline only in PowerShell/Operational) |
| Filter Current Log vs Create Custom View | Nearly identical; in **Filter Current Log** the `By log` / `By source` buttons are greyed out (scope is already the current log) |
| `Where-Object` is slow | Pulls every event through the pipeline first. Use `-FilterHashtable` or `-FilterXPath` to filter at retrieval |
| Get-WinEvent replaced Get-EventLog | `Get-EventLog` is legacy; use `Get-WinEvent` |
| XPath quoting | Wrap the whole XPath in **single quotes**, values in **double quotes** |
| Element vs attribute syntax | `EventID=100` (element value) vs `Provider[@Name="WLMS"]` (attribute) vs `Data[@Name="TargetUserName"]="Sam"` (EventData) |
| TimeCreated is UTC | `SystemTime="...Z"` is UTC; Event Viewer shows local time |
| Level numbers | Informational = **4**, not 3. (1 Critical, 2 Error, 3 Warning, 4 Info, 5 Verbose) |
| Not logged by default | PowerShell Module/Script Block logging and command-line in 4688 must be enabled via GPO/Registry |
| `Measure-Object cmdlet` fails | "cmdlet" is not an argument — just pipe to `Measure-Object` and read `Count` |
| Clear Log button | Legit for maintenance, but attackers clear logs to hide → watch **1102** (Security) / **104** (System) |
| EventData may be empty | Not every event populates `<EventData>` |
| Copy-paste corruption | Long XPath/timestamps pasted into the VM can get mangled — type manually if a query returns nothing |

## 1️⃣ Task 1 — What Are Event Logs?

| Concept | Detail |
|---|---|
| Event logs | Audit trail of system activity; used to diagnose problems and investigate incidents |
| Blue team use | Correlate entries from multiple sources to find links between seemingly unrelated events |
| SIEM | Security Information and Event Management (e.g. **Splunk**, **Elastic**) — central query of logs from all endpoints |
| Why SIEM | Connecting to each machine's logs remotely doesn't scale in an enterprise |
| Linux equivalent | **Syslog** |

**SIEM capabilities**

| Main features | Additional features |
|---|---|
| Threat detection | Basic security monitoring, Advanced threat detection |
| Investigation | Forensics & incident response, Log collection, Normalisation |
| Time to respond | Notifications & alerts, Security incident detection, Threat response workflow |

**Lab access:** RDP via Remmina → Server `MACHINE_IP`, user `administrator`, pass `blueT3aming!` (lab machine takes ~3 min to boot).

## 2️⃣ Task 2 — Event Viewer

### File format & location

| Item | Value |
|---|---|
| Extensions | `.evt` (legacy), `.evtx` (modern) |
| Location | `C:\Windows\System32\winevt\Logs` |
| PowerShell/Operational path | `%SystemRoot%\System32\Winevt\Logs\Microsoft-Windows-PowerShell%4Operational.evtx` |

### Log categories

| Log | Records |
|---|---|
| **System** | OS components — hardware changes, drivers, system changes |
| **Security** | Logon/logoff; defined by audit policy. Best source for unauthorized-activity investigation |
| **Application** | Installed apps — errors, events, warnings |
| **Directory Service** | Active Directory changes (domain controllers) |
| **File Replication Service** | Sharing Group Policies & logon scripts to DCs |
| **DNS Event Logs** | DNS server domain events |
| **Custom Logs** | App-defined; custom size, ACLs etc. |

### 5 event types

| Type | Meaning | Example |
|---|---|---|
| **Error** | Significant problem (data/function loss) | Service fails to load at startup |
| **Warning** | Not significant now, possible future problem | Low disk space |
| **Information** | Successful operation | Network driver loads |
| **Success Audit** | Audited security access succeeded | Successful logon |
| **Failure Audit** | Audited security access failed | Failed network-drive access |

### 3 ways to access logs

| Tool | Type | Launch |
|---|---|---|
| Event Viewer | GUI (MMC snap-in) | Right-click Start → Event Viewer, or `eventvwr.msc` |
| wevtutil.exe | Command line | `wevtutil.exe /?` |
| Get-WinEvent | PowerShell cmdlet | `Get-Help Get-WinEvent` |

### Event Viewer panes

| Pane | Content |
|---|---|
| Left | Tree of log providers (Windows Logs, Applications and Services Logs) |
| Middle | Event list for selected provider + detail split (General / Details) |
| Right | Actions (Open Saved Log, Create Custom View, Filter Current Log, Properties, Connect to Another Computer…) |

### Middle pane columns

| Column | Meaning |
|---|---|
| Level | Event type (Information, Error…) |
| Date and Time | When logged |
| Source | Software that logged it (e.g. PowerShell) |
| Event ID | Numeric ID tied to an operation *within that source* |
| Task Category | Organizes/filters events; defined by the source |

**Details tab:** Friendly View / **XML View** (use XML View to build XPath queries).

### Log Properties (log rotation)

| Setting | Options |
|---|---|
| Maximum log size (KB) | e.g. 15360 |
| When max reached | Overwrite as needed (oldest first) / Archive when full / Do not overwrite (clear manually) |
| Clear Log | Legit maintenance — or attacker anti-forensics |

**Navigation:** `Applications and Services Logs > Microsoft > Windows > PowerShell > Operational` · Remote: right-click `Event Viewer (Local) > Connect to Another Computer...`

### Q&A

| Question | Answer |
|---|---|
| Event ID of earliest event in PowerShell/Operational (excl. warning) | **4103** |
| Filter Event ID 4104 — 2nd command executed | **whoami** |
| Task Category for Event ID 4104 | **Execute a Remote Command** |
| Windows PowerShell log — Task Category for Event ID 800 | **Pipeline Execution Details** |

## 3️⃣ Task 3 — wevtutil.exe

**Purpose:** Retrieve info about logs and publishers, install/uninstall manifests, run queries, export/archive/clear logs.

### Commands (short | long)

| Short | Long | Purpose |
|---|---|---|
| `el` | enum-logs | List log names |
| `gl` | get-log | Get log configuration |
| `sl` | set-log | Modify log configuration |
| `ep` | enum-publishers | List event publishers |
| `gp` | get-publisher | Publisher configuration |
| `im` | install-manifest | Install publishers/logs from manifest |
| `um` | uninstall-manifest | Uninstall publishers/logs |
| `qe` | query-events | Query events from a log or log file |
| `gli` | get-log-info | Log status info |
| `epl` | export-log | Export a log |
| `al` | archive-log | Archive an exported log |
| `cl` | clear-log | Clear a log |

### Common options

| Option | Purpose |
|---|---|
| `/r:VALUE` | Run on remote computer (not for `/im`, `/um`) |
| `/u:VALUE` | Username (`domain\user`); requires `/r` |
| `/p:VALUE` | Password; `*` = prompt; requires `/u` |
| `/a:` | Auth type: Default \| **Negotiate** (default) \| Kerberos \| NTLM |
| `/uni:` | Unicode output true/false |

### `qe` options

| Option | Purpose |
|---|---|
| `/lf:true` | Treat argument as a **path to a log file** |
| `/q:VALUE` | **XPath query** filter |
| `/c:N` | Maximum number of events to read |
| `/rd:true` | Read direction — `true` = newest first |
| `/f:text` | Output format (text / xml) |

### Help

```powershell
wevtutil.exe /?          # general help
wevtutil qe /?           # help for a specific command
```

### Count log names

**Purpose:** How many logs exist on the machine.

```powershell
wevtutil.exe el                 # list all log names
(wevtutil.exe el).Count         # count them
# Output: 1071
```

### Read newest events

**Purpose:** Show last 3 Application events as text.

```powershell
wevtutil qe Application /c:3 /rd:true /f:text
# Application = log name, /c:3 = 3 events, /rd:true = newest first, /f:text = no XML
```

### XPath with wevtutil

```cmd
wevtutil.exe qe Application /q:*/System[EventID=100] /f:text /c:1
# Event[0]: Log Name: Application  Source: WLMS  Event ID: 100  Level: Information ...
```

### Cheat-sheet style queries

```cmd
:: Success & failed logons
wevtutil qe Security /q:"*[System[(EventID=4624 or EventID=4625)]]" /c:5 /rd:true /f:text
:: User account change
wevtutil qe Security /q:"*[System[(EventID=4738)]]" /c:5 /rd:true /f:text
:: New service installed (System log)
wevtutil qe System /q:"*[System[(EventID=7045)]]" /c:5 /rd:true /f:text
:: Multiple account changes
wevtutil qe Security /q:"*[System[(EventID=4725 or EventID=4722 or EventID=4723 or EventID=4724 or EventID=4726 or EventID=4767)]]" /c:10 /f:text
```

### Q&A

| Question | Answer |
|---|---|
| How many log names are on the machine? | **1071** |
| What does `query-events` read? | **event log, log file, structured query** |
| Option to provide a path to a log file | **/lf:true** |
| VALUE for `/q` | **Xpath query** |
| Log name in `wevtutil qe Application /c:3 /rd:true /f:text` | **Application** |
| `/rd` is for | **Event read direction** |
| `/c` is for | **Maximum number of events to read** |

## 4️⃣ Task 4 — Get-WinEvent

**Purpose:** Gets events from event logs and ETL files on local/remote computers; combine sources; filter with XPath, structured XML, or hash tables. Replaces `Get-EventLog`.

### Key parameters

| Parameter | Purpose |
|---|---|
| `-ListLog *` | List logs (LogMode, MaximumSizeInBytes, RecordCount, LogName) |
| `-ListProvider *` | List providers (Name) and the logs they write to (LogLinks) |
| `-LogName` | Log to query |
| `-ProviderName` | Filter by provider |
| `-Path` | Read a saved `.evtx` file |
| `-MaxEvents N` | Number of events to return |
| `-Oldest` | Read oldest first |
| `-FilterHashtable` | Hash-table filter (recommended) |
| `-FilterXPath` | XPath filter |
| `SuppressHashFilter` | Exclude matching events (e.g. `@{Level=4}`) |

### Example 1 — list all logs

```powershell
Get-WinEvent -ListLog *
# LogMode  MaximumSizeInBytes RecordCount LogName
# Circular           15532032       14500 Application
# Circular            1052672         117 Azure Information Protection
# (RecordCount can be 0 or null)
```

### Example 2 — providers and their logs

```powershell
Get-WinEvent -ListProvider *
# Name     : .NET Runtime
# LogLinks : {Application}
```

### Example 8 — providers matching a pattern

```powershell
Get-WinEvent -ListProvider *PowerShell*
# 3rd result: Microsoft-Windows-PowerShell-DesiredStateConfiguration-FileDownloadManager
```

### Example 9 — count event IDs of a provider

```powershell
(Get-WinEvent -ListProvider Microsoft-Windows-PowerShell).Events |
  Format-Table Id, Description | Measure-Object
# Count : 192
```

### Filter with Where-Object (slow)

```powershell
Get-WinEvent -LogName Application | Where-Object { $_.ProviderName -Match 'WLMS' }
# TimeCreated            Id LevelDisplayName
# 12/21/2020 4:23:47 AM 100 Information
```

### Filter with FilterHashtable (recommended)

```powershell
Get-WinEvent -FilterHashtable @{ LogName='Application'; ProviderName='WLMS' }

Get-WinEvent -FilterHashtable @{
    LogName='Application'
    ProviderName='MsiInstaller'
    ID=11707
}   # newline-separated pairs need no semicolons
```

### Hunt for SecureString in script blocks (@mubix)

```powershell
Get-WinEvent -FilterHashtable @{LogName='Microsoft-Windows-PowerShell/Operational'; ID=4104} |
  Select-Object -Property Message | Select-String -Pattern 'SecureString'
```

### Limit results

```powershell
Get-WinEvent -ProviderName 'Microsoft-Windows-PowerShell' -MaxEvents 50
```

### Hash table syntax rules

| Rule | Detail |
|---|---|
| Syntax | `@{ <name> = <value>; [<name> = <value>] ...}` |
| Start | `@` sign |
| Enclose | Braces `{}` |
| Separator | `=` between key and value; `;` between pairs (or newline) |
| Build tip | Add one key-value pair at a time; get values from Event Viewer (Log Name, Source, Event ID) |

### FilterHashtable keys

| Key | Type | Wildcards? |
|---|---|---|
| LogName | `String[]` | Yes |
| ProviderName | `String[]` | Yes |
| Path | `String[]` | No |
| Keywords | `Long[]` | No |
| ID | `Int32[]` | No |
| Level | `Int32[]` | No |
| StartTime | `DateTime` | No |
| EndTime | `DateTime` | No |
| UserID | `SID` | No |
| Data | `String[]` | No |
| `<named-data>` | `String[]` | No |

### Level values

| Value | Level |
|---|---|
| 0 | LogAlways |
| 1 | Critical |
| 2 | Error |
| 3 | Warning |
| **4** | **Informational** |
| 5 | Verbose |

### Q&A

| Question | Answer |
|---|---|
| Example 1 — logs related to OpenSSH | **OpenSSH/Admin, OpenSSH/Operational** |
| Example 8 with `*PowerShell*` — 3rd provider | **Microsoft-Windows-PowerShell-DesiredStateConfiguration-FileDownloadManager** |
| Example 9 — event IDs for Microsoft-Windows-PowerShell | **192** |
| Specify number of events | **-MaxEvents** |
| FilterHashtable Level value for Informational | **4** |

## 5️⃣ Task 5 — XPath Queries

**XPath** = XML Path Language (W3C). Windows Event Log supports a **subset of XPath 1.0**. Both `wevtutil` (`/q:`) and `Get-WinEvent` (`-FilterXPath`) accept it. A query starts with `*` or `Event`.

### Event XML structure (from Details → XML View)

```xml
<Event xmlns="http://schemas.microsoft.com/win/2004/08/events/event">
  <System>
    <Provider Name="WLMS" />
    <EventID Qualifiers="0">100</EventID>
    <Level>4</Level>
    <TimeCreated SystemTime="2020-12-15T01:09:08.940277500Z" />
    <EventRecordID>238</EventRecordID>
    <Channel>Application</Channel>
    <Computer>WIN-1O0UJBNP9G7</Computer>
  </System>
  <EventData>
    <Data Name="TargetUserName">SYSTEM</Data>
  </EventData>
</Event>
```

### XPath patterns

| Target | XPath | Type |
|---|---|---|
| Event ID | `*/System/EventID=100` | Element value |
| Provider | `*/System/Provider[@Name="WLMS"]` | Attribute |
| Timestamp | `*/System/TimeCreated[@SystemTime="2020-12-15T01:09:08.940277500Z"]` | Attribute |
| EventData field | `*/EventData/Data[@Name="TargetUserName"]="System"` | Named Data value |
| Combine | `<cond1> and <cond2>` | Boolean |
| Level + time window | `*[System[(Level <= 3) and TimeCreated[timediff(@SystemTime) <= 86400000]]]` | Last 24 h, Level ≤ 3 |

`*/System/` ≈ `*/*` (valid), but using `System` explicitly is best practice.

### Build step-by-step

```powershell
Get-WinEvent -LogName Application -FilterXPath '*'
Get-WinEvent -LogName Application -FilterXPath '*/System/'
Get-WinEvent -LogName Application -FilterXPath '*/System/EventID=100'
```

### Filter by provider

```powershell
Get-WinEvent -LogName Application -FilterXPath '*/System/Provider[@Name="WLMS"]'
# Returns Event IDs 100 and 101 from WLMS
```

### Combine two conditions

```powershell
Get-WinEvent -LogName Application -FilterXPath '*/System/EventID=101 and */System/Provider[@Name="WLMS"]'
# 12/15/2020 8:48:34 AM 101 Information (3 results)
```

### Filter on EventData

```powershell
Get-WinEvent -LogName Security -FilterXPath '*/EventData/Data[@Name="TargetUserName"]="System"' -MaxEvents 1
# 12/21/2020 10:50:26 AM 4624 Information  An account was successfully logged on...
```

### Q&A

| Question | Answer |
|---|---|
| Query for WLMS events at SystemTime 2020-12-15T01:09:08.940277500Z | **`Get-WinEvent -LogName Application -FilterXPath '*/System/Provider[@Name="WLMS"] and */System/TimeCreated[@SystemTime="2020-12-15T01:09:08.940277500Z"]'`** |
| Query for user Sam with Event ID 4720 | **`Get-WinEvent -LogName Security -FilterXPath '*/EventData/Data[@Name="TargetUserName"]="Sam" and */System/EventID=4720'`** |
| Number of results | **2** |
| Message | **A user account was created** |
| Time of Event ID 4724 for Sam | **12/17/2020 1:57:14 PM** |
| Provider Name | **Microsoft-Windows-Security-Auditing** |

## 7️⃣ Task 7 — Putting Theory into Practice (`merged.evtx`)

| Scenario | Goal | Key ID |
|---|---|---|
| 1 | PowerShell visibility — detect downgrade attack | **400** (EngineVersion 2.0) |
| 2 | Detect event log clearing | **104** / 1102 (check XML for EventRecordID) |
| 3 | Emotet — find encoded payload | **4104** + `ScriptBlockText` |
| 4 | Intern enumerating Administrators via `net1.exe` | **4799** |

### Downgrade attack (Event 400)

**Purpose:** PowerShell v2 lacks Script Block logging — attackers downgrade to evade. Look for `EngineVersion=2.0` or `-Version 2`.

```powershell
Get-WinEvent -Path "$env:USERPROFILE\Desktop\merged.evtx" |
  Where-Object {$_.Id -eq 400 -and $_.Message -match "EngineVersion.*2\.0"} |
  Format-List TimeCreated,Id,ProviderName,Message
# TimeCreated 12/18/2020 7:50:33 AM  Id 400  Engine Lifecycle
```

### Emotet script block (Event 4104)

```powershell
Get-WinEvent -Path "$env:USERPROFILE\Desktop\merged.evtx" `
  -FilterXPath "*[System[(EventID=4104)] and EventData[Data[@Name='ScriptBlockText']]]" `
  -Oldest -MaxEvents 1 | Format-List TimeCreated,Id,ProviderName,Message
# First variable: $Va5w3n8
```

### net1.exe group enumeration (Event 4799)

```powershell
Get-WinEvent -Path "$env:USERPROFILE\Desktop\merged.evtx" |
  Where-Object {$_.Id -eq 4799 -and $_.Message -match "net1.exe"} |
  Format-List TimeCreated,Id,ProviderName,Message
# Group Security ID: S-1-5-32-544 (BUILTIN\Administrators)
```

### SID breakdown

| Part | Meaning |
|---|---|
| `S-1-5` | NT Authority SID prefix |
| `32` | BUILTIN domain |
| `544` | Administrators group |
