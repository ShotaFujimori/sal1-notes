# 🛡️ Sysmon — Reference Sheet

**Learning path:** SOC Level 1 → 13. SIEM Triage for SOC → Log Analysis with SIEM → Prerequisite: Sysmon  
**Room:** https://tryhackme.com/room/sysmon  
**Tags:** `SOC_Lv1` · `Sysmon` · `Windows` · `SIEM` · `DFIR`

> **TL;DR:** Sysmon is a Microsoft Sysinternals Windows service/driver that provides endpoint telemetry beyond standard Windows logs. Its log is `Microsoft-Windows-Sysmon/Operational`. Focus on **Event ID 1 (process), 3 (network), 8 (remote thread), 10 (process access), 11 (file), 13 (registry value), 15 (ADS), and 22 (DNS)**. Install it with a reviewed XML configuration, hunt with `Get-WinEvent -FilterXPath`, and correlate by `ProcessGuid`, parent process, and UTC time rather than treating an individual event as proof of maliciousness.

---

## ⚠️ Gotchas

- **Sysmon is not installed by default** as the standalone Sysinternals tool; it records telemetry, not a malicious/benign verdict.
- **Config controls coverage:** network connections (ID 3) and image loads (ID 7) are not enabled by the basic default setup. Excessive exclusions can conceal attacks.
- **`-i` installs; `-c` updates.** Do not reinstall only to change XML.
- **`ProcessId` can be reused; `ProcessGuid` is the stronger correlation key.**
- **Ports 4444, 5555, or 8080 are clues, not a diagnosis.** Attackers can change ports; legitimate tools can use them.
- **LSASS access does not always mean Mimikatz.** Validate the source process, access mask, host role, baseline, and related logs.
- **UTC matters:** XML `SystemTime` and Sysmon `UtcTime` are UTC; Event Viewer displays local time.
- **`RuleName` ATT&CK IDs may be outdated:** `T1060` and `T1023` are legacy identifiers. Map registry Run keys/Startup folders to current `T1547.001`.
- **Double-check lab file paths.** Both `..\Config` and `..\Configurations` appear in the original notes. Never assume the directory exists.
- **Do not copy lab credentials into GitHub**, especially public repositories.

## 1️⃣ Tasks 1–2 — Introduction and Overview

**Purpose:** Detect, investigate, and correlate process execution, network activity, file writes, Registry changes, and potential evasion techniques.

**Event Viewer:** `Applications and Services Logs → Microsoft → Windows → Sysmon → Operational`.

| Event ID | Name | Key fields | SOC use | Example | Caveat |
|---|---|---|---|---|---|
| **1** | ProcessCreate | `Image`, `CommandLine`, `ParentImage`, `ProcessGuid` | Execution / LOLBins | `mshta.exe` running HTA | Context required |
| **3** | NetworkConnect | `Image`, `DestinationIp`, `DestinationPort` | RAT/C2 | Unknown EXE to port 8080 | Config dependent |
| **5** | ProcessTerminate | `Image`, `ProcessGuid` | Process lifecycle | Short-lived payload | Not malicious alone |
| **7** | ImageLoad | `ImageLoaded`, `Image` | DLL loading | DLL from user profile | Noisy; usually opt-in |
| **8** | CreateRemoteThread | `SourceImage`, `TargetImage` | Possible injection | PowerShell → Notepad | Not all injection produces ID 8 |
| **9** | RawAccessRead | `Image`, `Device` | Raw disk access | `\Device\HarddiskVolume3` | Disk tools may be normal |
| **10** | ProcessAccess | `SourceImage`, `TargetImage`, `GrantedAccess` | LSASS access | Mimikatz → LSASS | Access ≠ dump success |
| **11** | FileCreate | `TargetFilename`, `Image` | Payload/persistence | New file in Startup | Check file and creator |
| **12/13/14** | Registry events | `TargetObject`, `Details` | Autorun/persistence | `CurrentVersion\Run` | Configuration-dependent |
| **15** | FileCreateStreamHash | `TargetFilename`, hash | NTFS alternate streams | `file.exe:Zone.Identifier` | ADS can be legitimate |
| **22** | DNS Query | `QueryName`, `Image` | C2/domain hunting | Suspicious DNS lookup | DNS ≠ successful C2 |

## 3️⃣ Task 4 — Cutting Out the Noise (XPath)

**Goal:** Retrieve specific event IDs and named XML fields from exported `.evtx` files.

| Type | OS | Priv | Command | What | Example |
|---|---|---|---|---|---|
| Count | Windows | User | `(Get-WinEvent -Path $log -FilterXPath '*[System[EventID=3]]').Count` | Count network events | 73,591 in lab |
| Filter | Windows | User | `Get-WinEvent -Path $log -FilterXPath '*[System[EventID=3]]'` | Filter ID 3 | NetworkConnect |
| Inspect | Windows | User | `Get-WinEvent -Path $log -Oldest -MaxEvents 1` | Earliest event | Timeline start |
| XML | Windows | User | `(Get-WinEvent -Path $log -Oldest -MaxEvents 1).ToXml()` | Inspect raw fields/UTC | `SystemTime` |

```powershell
$log = 'C:\Users\THM-Analyst\Desktop\Scenarios\Practice\Filtering.evtx'
# Event ID 3 + named DestinationPort value:
Get-WinEvent -Path $log -FilterXPath '*[System[EventID=3] and EventData[Data[@Name="DestinationPort"]="4444"]]'
# Count Event ID 3:
(Get-WinEvent -Path $log -FilterXPath '*[System[EventID=3]]' | Measure-Object).Count
# Earliest network-event UTC timestamp:
$e = Get-WinEvent -Path $log -FilterXPath '*[System[EventID=3]]' -Oldest -MaxEvents 1
([xml]$e.ToXml()).Event.System.TimeCreated.SystemTime
```

**Recorded lab results:** **73,591** network events; first UTC timestamp **2021-01-06 01:35:50.464**. These describe the sample file, not every system.

**XPath breakdown:** `System/EventID=3` selects network events; `Data[@Name="DestinationPort"]="4444"` matches one named field with the exact value. Prefer named-field equality over searching the whole XML for any `4444`.

## 4️⃣ Task 5 — Hunting Metasploit

**Hypothesis:** a suspicious process connects to a listener on port **4444** (or other configured callback ports). Sysmon **Event ID 3** can identify the connection and owning process.

```powershell
$log = 'C:\Users\THM-Analyst\Desktop\Scenarios\Practice\Hunting_Metasploit.evtx'
Get-WinEvent -Path $log -FilterXPath '*[System[EventID=3] and EventData[Data[@Name="DestinationPort"]="4444"]]'
```

**Interpretation:** examine `Image`, `ProcessGuid`, `DestinationIp`, and time; pivot to ID **1** for the executable's command line and parent. **Do not infer Metasploit merely from port 4444.**

## 5️⃣ Task 6 — Detecting Mimikatz

**Hypothesis:** an unexpected process accesses `lsass.exe` (credential-access behavior). Hunt **Event ID 10**.

```powershell
$log = 'C:\Users\THM-Analyst\Desktop\Scenarios\Practice\Hunting_Mimikatz.evtx'
Get-WinEvent -Path $log -FilterXPath '*[System[EventID=10] and EventData[Data[@Name="TargetImage"]="C:\Windows\system32\lsass.exe"]]'
```

**Lab example:** `C:\Users\THM-Threat\Downloads\mimikatz.exe` → `C:\Windows\system32\lsass.exe`; `SourceProcessId=3604`; `GrantedAccess=0x1010`. This is suspicious on a domain controller. Correlate source execution, account, binary hash, and other telemetry before declaring credential theft.

**Gotcha:** excluding `svchost.exe` may reduce noise but may also remove useful evidence. Treat exclusions as reviewed detection engineering decisions, not universal rules.

## 6️⃣ Task 7 — Hunting Malware / RATs

**Hypothesis:** RAT/backdoor activity creates repeated C2 connections, for example to **TCP 8080**. Investigate **ID 3** and connection frequency.

```powershell
$log = 'C:\Users\THM-Analyst\Desktop\Scenarios\Practice\Hunting_Rats.evtx'
Get-WinEvent -Path $log -FilterXPath '*[System[EventID=3] and EventData[Data[@Name="DestinationPort"]="8080"]]'
```

**Example:** an unknown binary in a user-writable directory repeatedly contacting the same remote endpoint on 8080 is a hunting lead. Investigate owner, binary, destination reputation, and beacon periodicity.

## 7️⃣ Task 8 — Hunting Persistence

**Goal:** find unexpected Startup-folder files (**ID 11**) and Registry Run-key changes (**ID 13**).

| Type | OS | Priv | Command | What | Example |
|---|---|---|---|---|---|
| File | Windows | User | `Get-ChildItem "$env:APPDATA\Microsoft\Windows\Start Menu\Programs\Startup"` | Inspect current user's startup files | Unexpected `persist.exe` |
| Filter | Windows | User | `Get-WinEvent -Path $log -FilterXPath '*[System[EventID=11]]'` | Find created files | `T1023.evtx` lab |
| Filter | Windows | User | `Get-WinEvent -Path $log -FilterXPath '*[System[EventID=13]]'` | Find registry value changes | Autorun value created |
| Registry | Windows | User | `Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Run'` | Read Run-key entries | Suspicious executable path |

```powershell
$log = 'C:\Users\THM-Analyst\Desktop\Scenarios\Practice\T1023.evtx'
Get-WinEvent -Path $log -FilterXPath '*[System[EventID=11]]'
Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Run'
Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Run'
```

**Example:** `persist.exe` created under `...\Start Menu\Programs\Startup`, or `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run\Persistence` pointing to an unknown executable. Verify who wrote it, what it executes, and whether it is authorized. Current ATT&CK: **T1547.001** (Run Keys / Startup Folder).

## 8️⃣ Task 9 — Detecting Evasion Techniques

**ADS:** ID **15** monitors named streams; `dir /r` or PowerShell `-Stream` lists NTFS streams. **Remote thread:** ID **8** can reveal code execution attempted inside another process.

| Type | OS | Priv | Command | What | Example |
|---|---|---|---|---|---|
| ADS | Windows | User | `cmd /c "dir /r C:\Sample"` | Display alternate data streams | `file.txt:hidden:$DATA` |
| ADS | Windows | User | `Get-Item -Path 'C:\Sample\file.txt' -Stream *` | List streams via PowerShell | `Zone.Identifier` |
| Filter | Windows | User | `Get-WinEvent -Path $log -FilterXPath '*[System[EventID=8]]'` | Hunt remote-thread creation | `powershell.exe` → `notepad.exe` |
| Filter | Windows | User | `Get-WinEvent -Path $log -FilterXPath '*[System[EventID=15]]'` | Hunt named streams | Hidden stream written |

```powershell
$log = 'C:\Users\THM-Analyst\Desktop\Scenarios\Practice\Detecting_RemoteThreads.evtx'
Get-WinEvent -Path $log -FilterXPath '*[System[EventID=8]]'
# Substitute the actual source file when hunting ADS:
Get-WinEvent -Path 'C:\Users\Administrator\Desktop\Sysmon.evtx' -FilterXPath '*[System[EventID=15]]'
```

**Example:** `powershell.exe` creating a thread in `notepad.exe` warrants investigation. **Neither ADS nor an ID 8 event alone proves malicious injection.**

## 9️⃣ Task 10 — Practical Investigations

| Scenario | Event IDs | Evidence | Example lab finding | Interpretation | Next pivot |
|---|---|---|---|---|---|
| **1 — Malicious USB** | 13, 9, 1 | USB registry / raw device / process | `\Device\HarddiskVolume3`; `rundll32.exe` | Suspicious removable-media execution | Process parent and binary |
| **2 — HTML masquerade** | 1, 3 | Executed HTA, connection | `update.html` → `update.hta`, `mshta.exe`, `10.0.2.18:4443` | Scripted code execution | Process tree and network |
| **3.1 — Registry persistence** | 13, 3 | Registry value, C2 hostname | `HKLM\SOFTWARE\Microsoft\Network\debug`; `empirec2` | Encoded payload / Empire lab scenario | Script command and ProcessGuid |
| **3.2 — Scheduled task + ADS** | 1, 10, 3 | Autorun, stream, LSASS access | `Updater`; `C:\users\q\AppData:blah.txt`; `172.168.103.188` | Persistence and credential-access lead | Task action and process |
| **4 — Botnet C2** | 3 | Network destination | `172.30.1.253:80`; lab attribution `Empire` | C2 blending into web traffic | Executable and repeated traffic |

**Investigation workflow:** identify hypothesis → retrieve matching `.evtx` → filter relevant Event ID → pivot via ProcessGuid and key fields → normalize timestamps → corroborate with other telemetry → distinguish observation from conclusion.

```powershell
# Adjust to the scenario's actual file location.
$log = 'C:\Users\THM-Analyst\Desktop\Scenarios\Investigations\Investigation-3.1.evtx'
Get-WinEvent -Path $log -FilterXPath '*[System[EventID=1 or EventID=3 or EventID=13]]' |
    Select-Object TimeCreated, Id, ProviderName, Message
```

## 🎯 Key Takeaways

- Learn which **Event ID provides which evidence**, then combine different event types into the full attack story.
- Prioritize **ProcessGuid + parent/child process + UTC timeline** rather than PID, filename, or port alone.
- Configuration quality determines the evidence you can collect. Review include/exclude rules before production deployment.
- Successful SOC work means **corroboration**, context, and repeatable queries—not merely spotting a red flag.
