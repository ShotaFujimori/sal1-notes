# 🕵️ Invite Only — Reference Sheet

> **TL;DR:** A malware-pivoting exercise. Start from a flagged hash/IP in a VirusTotal-style tool (TryDetectThis2.0), pivot through **Relations** (execution parents, dropped/bundled/communicating files) to map the malware chain, then read **Community comments** for attribution — landing on **AsyncRAT C2** and the Check Point *"From Trust to Threat"* hijacked-Discord-invite campaign.

## ⚠️ Gotchas

| Gotcha | Detail |
|---|---|
| Community tab = the gold | Attribution (family, campaign, MITRE, C2 port, references) usually lives in the **unstructured Community comments**, not the AV detection names. |
| "AsyncRAT C2" ≠ IP is malware | The IP is the **C2 server** infected hosts call back to, not malware itself. The distinction drives how you action it (block, hunt callbacks). |
| Block IP **+ port** | The actionable IOC is `101[.]99[.]76[.]120:7707` — SOC rules should match IP+port callbacks, not just the IP. |
| Geo ≠ hosting | The IP geolocates to the **Netherlands** but ASN **AS45839 (Shinjiru, Malaysia)** is "abusable hosting" — the ASN tells you more than the country. |
| Parents vs drops | **Execution parents** = what launched the file; **dropped files** = what it writes. Don't confuse the two pivot directions. |
| Pivot by hash, not name | Filenames (`syshelpers.exe`, etc.) get reused across samples; the **SHA256** is the reliable pivot key. Note hashes as you go. |
| OSINT the report | A Community comment referenced the Check Point report — pivoting to the published research gives campaign context the tool alone won't. |
| ClickFix relies on the user | It tricks the victim into pasting PowerShell into the Run dialog — no exploit or attachment, so AV/attachment defenses miss it. Aka **Pastejacking**. |
| ChromeKatz beats ABE | Modern cookie theft bypasses Chrome's **App-Bound Encryption** — "cookies are safe now" is false. |
| Hijacked Discord invites | Expired/vanity invite codes can be re-registered by attackers, so a once-legit invite can now redirect to a malicious server. |
| Don't give up on failed reports | Individual file reports may fail to load — check every tab and relation before concluding. |

## 🔗 Pivoting in a VirusTotal-style Tool

### Relations types
| Relation | Meaning |
|---|---|
| Execution Parents | Files/processes that **launched** this sample |
| Dropped Files | Files this sample **writes** to disk |
| Bundled Files | Files **packaged inside** this sample |
| Communicating Files | Files that **contact** a given IP/domain |
| Community | Human-curated attribution (family, campaign, MITRE, C2, references) |

### Report tabs
| Tab | What's there |
|---|---|
| Detection | Vendor flags, popular threat label, family labels |
| Details | File type, hashes (MD5/SHA1/SHA256), TrID, size, timestamps |
| Relations | Parents / dropped / bundled / communicating files |
| Behavior | Sandbox execution behavior |
| Community | Analyst comments — attribution & context |

## 🖱️ ClickFix Technique

| Step | Action |
|---|---|
| 1 | Victim lured via phishing email, malvertising, or compromised site |
| 2 | Fake error / CAPTCHA pop-up appears |
| 3 | A "Fix" button copies malicious code to the clipboard |
| 4 | User opens the Run dialog (`Win + R`) |
| 5 | User pastes the PowerShell (`Ctrl + V`) |
| 6 | User presses Enter → script runs with their privileges |
| 7 | RAT / infostealer downloaded and installed |

| Characteristic | Detail |
|---|---|
| Also called | Pastejacking |
| Emerged | First reported 2024, prevalent 2025 |
| Core mechanism | Clipboard hijacking + social engineering |
| Why it works | Relies on **user execution**, bypassing exploit/attachment defenses |
| Variants | FileFix, TerminalFix, DownloadFix |
