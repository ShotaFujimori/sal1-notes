# 🛡️ Intro to Cyber Threat Intel — Reference Sheet

> **TL;DR:** Cyber Threat Intelligence (CTI) gives SOC L1 analysts the *context* to decide which alerts are real threats. It turns raw **data → information → intelligence** through **enrichment**, follows a **six-phase lifecycle** (Direction → Collection → Processing → Analysis → Dissemination → Feedback), and is shared responsibly using **TLP** labels and machine-readable formats like **STIX/TAXII**. Frameworks (MITRE ATT&CK, D3FEND, Cyber Kill Chain, CVE/CVSS/NVD) give everyone a common language for adversary behaviour.

---

## ⚠️ Gotchas

| Gotcha | Detail |
|---|---|
| Data ≠ Intelligence | Data is a raw observable; intelligence is *analysed* info that answers "so what?" and drives an action (block/escalate/suppress). Don't confuse the layers. |
| IOC vs IOA | **IOC** = evidence a breach *already happened* (e.g. C2 IP in logs). **IOA** = a malicious action *in progress* (e.g. PowerShell spawning an unknown service). Different timing, different meaning. |
| Stricter TLP always wins | If the same IOC arrives as TLP:AMBER from one source and TLP:CLEAR from another, the record inherits **TLP:AMBER**. Combining never loosens the label. |
| TLP label must travel with the IOC | The label follows the indicator into every platform/ticket. Violating it can breach contracts and destroy partner trust. |
| Feeds vs Platforms are not the same | A **feed** is a scheduled *stream* of indicators. A **platform** (MISP, OpenCTI) is a *repository* that stores, enriches, maps, and enforces sharing. |
| Over-ingesting feeds is harmful | Dumping raw feeds without curation floods analysts with false positives and erodes trust in the whole programme. |
| OSINT must be cross-confirmed | Open-source indicators (AbuseIPDB, URLhaus, blogs) need verification against another source before you act on them. |
| Classification ≠ Lifecycle phase | *Strategic/Tactical/Operational/Technical* are **classifications** of intel. *Direction/Collection/Processing…* are **lifecycle phases**. Exam mixes these up. |
| "Processing" vs "Analysis" | **Processing** = normalise, correlate, deduplicate, format. **Analysis** = judge relevance/confidence and decide the action. Easy to swap on the exam. |
| ATT&CK vs D3FEND | ATT&CK = how adversaries **attack**. D3FEND = how defenders **respond**. |
| Kill Chain "Actions on Objectives" | Data exfiltration / encryption happens at the **final** phase — *Actions on Objectives*, not Command & Control. |
| Not all intel should be shared | Privacy laws, NDAs, and tipping off an active adversary are all reasons to withhold IOCs. |

## 🧠 Task 2 — Cyber Threat Intelligence

### The 3 essential questions CTI answers
| # | Question |
|---|---|
| 1 | Who/what is on the other end of this alert indicator? |
| 2 | What was their behaviour in the past? |
| 3 | How does my org respond, and what do I do *right now*? |

### Data → Information → Intelligence
| Layer | Definition | Alert-queue example | SOC L1 action |
|---|---|---|---|
| **Data** | Unprocessed observable | `45.155.205.3:443` | Capture the artefact |
| **Information** | Data + factual annotation | IP registered to Hetzner, first seen 2023-07-14 | Record attributes |
| **Intelligence** | Analysed info that answers *so-what* | IP belongs to current BumbleBee C2 — block now | Escalate or suppress |

### IOC vs IOA vs TTP
| Label | Meaning | Example |
|---|---|---|
| **IOC** (Indicator of Compromise) | Evidence of a breach | C2 address in the logs |
| **IOA** (Indicator of Attack) | A malicious action underway | PowerShell launching an unknown service |
| **TTP** (Tactics, Techniques, Procedures) | Adversary's detailed methodology | Expressed as MITRE ATT&CK IDs |

### Indicator types & first-line enrichment
| Indicator | Example | First resources | Associated IOA / TTP |
|---|---|---|---|
| **IPv4/IPv6** | `45.155.205.3` | WHOIS (ASN, allocation date), VirusTotal Relations, Shodan | IOA: repeated SSH failures · TTP: **T1110.003** Password Guessing |
| **Domain/FQDN** | `malicious-updates[.]net` | WHOIS age, RiskIQ/SecurityTrails passive-DNS, urlscan.io | IOA: surge of DNS queries to a 24-hour-old domain |
| **URL** | `hxxp://malicious-updates[.]net/login` | URLhaus, urlscan.io, Any.Run (network off) | IOA: browser POST to `/gateway.php` with payload |
| **File hash** | `e99a18c428cb38d5…` | VirusTotal, Hybrid-Analysis, MalShare | TTP: **T1055** Process Injection into `regsvr32.exe` |
| **E-mail address** | `billing@evil-corp.com` | MXToolbox header analysis, Have I Been Pwned | IOA: SPF failure + recent domain registration |
| **Local artefact** | `HKCU\Software\Run\updater.exe` | Sigma rules, EDR prevalence query, vendor KB | TTP: **T1060.001** Registry Run Keys |

> **Actionable tip:** Keep a bookmark folder / SIEM launcher that pre-populates your look-ups with the highlighted indicator. ~30s saved per alert = hours per month.

### Feeds vs Platforms
| Term | Definition |
|---|---|
| **Feed** | Scheduled *stream* of indicators (CSV, JSON, STIX, TAXII). Over-ingesting without curation drowns analysts in false positives. |
| **Platform** | Structured *repository* that stores indicators, tracks enrichment, maps relationships, enforces sharing permissions. **MISP** and **OpenCTI** are leading open-source examples — the single source of truth. |

### Sources of CTI
| Source | Notes |
|---|---|
| **Internal telemetry** | SIEM logs, EDR detections, phishing submissions — highest immediate relevance |
| **Commercial services** | Vendor premium feeds, paid sandboxes — high fidelity, but export/sharing limits |
| **OSINT** | AbuseIPDB, URLhaus, blogs, academic research — must be cross-confirmed |
| **Communities & ISACs** | Sector-specific, labelled, rich context (e.g. FS-ISAC) |

### Threat Intelligence Classifications
| Classification | Focus | Example |
|---|---|---|
| **Strategic** | High-level threat landscape, trends, business decisions | Annual ransomware trends report predicting data-wiping extortion in healthcare |
| **Tactical** | Adversary behaviours via TTP analysis | Advisory on new T1059.005 (Visual Basic) abuse in malspam |
| **Operational** | Campaign-specific motives/intent, targeted assets | Understanding which people/processes/tech may be targeted |
| **Technical** | Atomic indicators & artefacts | IPs and hashes tied to an attack |

## 🔄 Task 3 — CTI Lifecycle

### The Traffic Light Protocol (TLP) — defined by FIRST.org
| TLP label | Sharing boundary | Typical SOC L1 behaviour |
|---|---|---|
| **TLP:CLEAR** | No restriction | Post to internal wiki or platform |
| **TLP:GREEN** | Peer community, not public | Upload to MISP / partner-SOC Slack |
| **TLP:AMBER** | Org-wide + need-to-know clients only | Keep in company CTI platform; reference (don't copy) in tickets |
| **TLP:RED** | Named recipients only | Store in encrypted note; no ticketing without clearance |

### The Six Phases (scenario: Alex protecting TryHatMe's PostgreSQL DB)
| # | Phase | What happens | Key idea |
|---|---|---|---|
| 1 | **Direction** | Define the mission & intelligence requirements | Analysts **define the questions** to investigate |
| 2 | **Collection** | Gather raw material from feeds/OSINT/MISP/reports | Store dated copies for reproducibility |
| 3 | **Processing** | Normalise, correlate, deduplicate, tag, convert to action files | **Data converted into usable formats** |
| 4 | **Analysis** | Judge relevance & confidence; decide the action | Turns information into judgement |
| 5 | **Dissemination** | Deliver tailored output to each consumer | Unused intel = shelfware |
| 6 | **Feedback** | Measure KPIs, refine, re-iterate | Closes the loop |

### Analysis confidence grading (from the scenario)
| Confidence | Source agreement | Local sightings | Action |
|---|---|---|---|
| **High** | Same IOC in ≥2 sources | ≥1 local attempt | Immediate block |
| **Medium** | Single trusted source | No local hits | Alert-only |
| **Low** | OSINT only | No context | Monitor for 14 days |

### Intel format — STIX
**Structured Threat Information Expression (STIX)** = a **JSON schema** describing threat indicators, relationships, and context in a **machine-readable** form.

## 📚 Task 4 — CTI Standards & Frameworks

### MITRE ATT&CK — how adversaries attack
Common language ("Rosetta Stone") for adversary behaviour. Each technique has an ID (e.g. **T1059.001** PowerShell, **T1048.003** DNS tunnel).

**L1 workflow with the matrix:**
| Step | Action |
|---|---|
| 1 | Match alert behaviour to a tactic/technique pair |
| 2 | Write the ID in the triage note: *"Observed T1071.001 (web-based C2) against FINANCE-TRYHATME-00"* |
| 3 | Hand to L2/IR — they instantly know mitigations & threat-actor profiles |

### MITRE D3FEND — how defenders respond
Catalogues **defensive** techniques (e.g. Credential Hardening, Data Obfuscation).
- Example: proxy raises **T1048.003 DNS tunnel** → search D3FEND for **D3-NTDN (DNS request analysis)** → add controls (block large TXT records, alert on uncommon query entropy) to your "next actions".

### Cyber Kill Chain (Lockheed Martin)
| Phase | Purpose | Examples |
|---|---|---|
| **Reconnaissance** | Gather info on the victim | Harvesting emails, OSINT, social media, network scans |
| **Weaponisation** | Engineer malware for the attack | Exploit with a backdoor, malicious Office document |
| **Delivery** | Get malware to the victim | Email, weblinks, USB |
| **Exploitation** | Breach vulnerabilities, execute code, establish persistence | EternalBlue, Zero-Logon |
| **Installation** | Install malware/tools for access | Password dumping, backdoors, RATs |
| **Command & Control** | Remotely control, deliver more malware, move laterally, escalate | Empire, Cobalt Strike |
| **Actions on Objectives** | Fulfil goals: financial gain, espionage, exfiltration | Data encryption, ransomware, defacement |

> Extended by ATT&CK and the newer **Unified Kill Chain**.

### CVE / CVSS / NVD
| Term | Meaning |
|---|---|
| **CVE** (Common Vulnerabilities and Exposures) | Catalogue number for a vulnerability, e.g. `CVE-2023-4863` |
| **CVSS** (Common Vulnerability Scoring System) | 0–10 severity scale with temporal & environmental modifiers |
| **NVD** (National Vulnerability Database) | Canonical repo linking CVE → CVSS scores, exploits, affected products |

### Sharing standards — STIX vs TAXII
| Standard | Role |
|---|---|
| **STIX** | Structured **JSON schema** describing threat info (the *what*) |
| **TAXII** (Trusted Automated eXchange of Indicator Information) | Set of **secure APIs** to exchange intel in near real-time (the *how*) |

**TAXII sharing models:**
| Model | Behaviour |
|---|---|
| **Collection** | Intel is collected and *hosted by a producer* (consumers pull) |
| **Channel** | Intel is *published to users from a central server* (push) |

**Sharing trade-offs:** near-real-time feeds shorten the gap between another org's incident and your prevention, and contributions earn reciprocal trust — **but** privacy laws, NDAs, competitive info, and tipping off active adversaries are reasons *not* to share.
