# 🔬 File and Hash Threat Intel — Reference Sheet

> **TL;DR:** Alert triage is **verify → enrich → decide**, and file/hash intelligence lives in *enrich*. Start with cheap heuristics (filepath + filename), pivot to an immutable identifier (SHA256/MD5), enrich the hash on VirusTotal + MalwareBazaar, then confirm intent with sandbox behaviour (Hybrid Analysis / Joe Sandbox) and map it to MITRE ATT&CK. Core commands: `Get-FileHash -Algorithm SHA256 <file>`, `certutil -hashfile <file> SHA256`, `sha256sum <file>`.

---

## ⚠️ Gotchas

| Gotcha | Detail |
|---|---|
| A suspicious path/name proves nothing alone | Heuristics are *leads*, not verdicts. Attackers rename freely — always pivot to the hash. |
| Windows hides known extensions by default | `payroll.pdf.exe` displays as `payroll.pdf`. Check the **Type** column: a real PDF is never "Application". |
| Hash the file you actually have | On disk the file is `payroll.pdf.exe` — hashing `payroll.pdf` fails. Also hash **both** the archive and the extracted binary. |
| `Get-FileHash` returns UPPERCASE | Store hashes in **lowercase** to avoid needless diffs when comparing/searching. |
| Parameter is `-Algorithm`, not `-Algrithm` | Typo throws `ParameterBindingException: NamedParameterNotFound`. |
| One byte changes the whole hash | Recompiles, packing, or config edits break hash-based detection — that's why family labels/YARA matter. |
| Low detection score ≠ benign | New malware starts with few detections; vendors need 48–72h. Recheck after 24h and cross-reference MalwareBazaar tags. |
| A single "clean" vendor doesn't clear a file | CyberFortress marked Morse-Code-Analyzer non-malicious while Kaspersky, ESET, Microsoft and Sophos flagged DLL side-loading. **Conflicting verdicts = escalate to sandbox**, not "benign". |
| "First Seen In The Wild" ≠ "First Submission" | On VirusTotal these are separate History rows and can differ by hours/months. Read the exact row the question asks for. |
| Valid code signing is not trust | Certificates get stolen/abused. Check issuer, chain and expiry, not just "signed = OK". |
| High entropy isn't automatically malicious | Legit packers (e.g. UPX) raise entropy; >7.5 in a non-media file is a flag, not proof. |
| Sandboxes lie by omission | Evasion checks, 2–5 min execution windows, encrypted C2 and fileless/LotL malware all produce false negatives. |
| Trusted Windows binaries are attack tools | `regsvr32 ... /s` and PowerShell/WMI are LotL techniques — the binary being signed by Microsoft means nothing. |
| Defang URLs/IPs in notes | Write `hxxp://` so nobody clicks a live C2 link from your report. |
| Detonate in isolation only | Never hash/execute suspect binaries on a production or personal host. |

## 🗂️ Task 2 — Filenames and Paths

### Suspicious staging locations

| Path | Why attackers use it |
|---|---|
| `C:\` (system drive root) | Common target for persistence mechanisms |
| `C:\Users\Public` | Cross-user access to detonated adversary tools |
| `C:\Users\Public\Public Downloads` | High-traffic directory that often evades strict monitoring |
| `C:\Windows\Temp\` | Temporary directory for ephemeral payloads |
| `C:\ProgramData\` | Writable system path used for stealth persistence |

### Filename heuristic indicators

| Indicator | Example | What it abuses |
|---|---|---|
| **Double extensions** | `invoice.pdf.exe`, `payroll.pdf.exe` | Windows hides known extensions by default |
| **System binary impersonation** | `scvhost.exe` (vs `svchost.exe`) | User familiarity with core processes — allowlist *legitimate paths*, not names |
| **High-entropy strings** | `jh8F21.exe` | Automated packing / polymorphic generation in high-churn phishing |
| **Masquerading** | `backup-2300.exe`, single-character substitutions | Blends with routine files; visually legitimate |

## #️⃣ Task 3 — File Hash Lookup

### Why hashes

| Property | Meaning for the analyst |
|---|---|
| Immutable identity | Renaming the file does not change the hash |
| Pivot key | Search VT, MalwareBazaar, sandboxes, SIEM, EDR with one string |
| Fragile by design | Any byte change → new hash (attackers recompile to break IOC lists) |

**Hash hygiene rules:** store lowercase · hash everything relevant (archive **and** extracted binary) · never record a hash without where/when it was seen · assume one byte flips the value.

### Navigate to the sample folder (PowerShell)

**Purpose:** Get into the case-file directory before hashing.

```powershell
cd $env:USERPROFILE\Desktop
cd "CTI Files"
ls
# Directory: C:\Users\matthew.collins\Desktop\CTI Files
# -a----  5/18/2026  2:34 AM  2695990  bl0gger.exe
# -a----  7/29/2025  7:56 AM  1074688  Challenge.bin.sample
# -a----  7/21/2025 12:19 PM   181248  Morse-Code-Analyzer.exe
# -a----  7/29/2025  7:07 AM    65536  payroll.pdf.exe
# ls reveals the TRUE extensions that Explorer hides
```

> Tip: typing `powershell.exe` in the Explorer address bar opens a shell already in that folder.

### Generate a SHA256 hash

**Purpose:** Produce the pivot value for threat-intel lookups.

```powershell
Get-FileHash -Algorithm SHA256 bl0gger.exe
# Algorithm  Hash                                                              Path
# SHA256     2672B6688D7B32A90F9153D2FF607D6801E6CBDE61F509ED36D0450745998D58  ...\bl0gger.exe
# Output is uppercase -> lowercase it before storing/searching
```

```cmd
certutil -hashfile bl0gger.exe SHA256
:: cmd.exe equivalent when PowerShell is unavailable
```

```bash
sha256sum bl0gger.exe
# Linux equivalent; use md5sum / sha1sum for other algorithms
```

### VirusTotal report — what to read

| Section | Key question | Red flags | Analyst considerations |
|---|---|---|---|
| **Detection score & threat labels** | How many vendors call it malicious? | ≥5 solid vendors flag it; conflicting classes (Trojan vs PUA); no consensus among top 3 | New malware detects low; recheck after 24h; read the family/capability name |
| **Upload time** | When was it first submitted? | Uploaded 7 days ago with >10 detections; sudden detection spike | Vendors need 48–72h; detection growth = malware ageing |
| **Signatures** | Is it properly signed? | Missing/invalid cert; cert issued to unrelated entity | Valid certs can be stolen; check chain + expiry |
| **Properties** | Anomalies in file metadata? | Compile timestamp at odd hours (e.g. 3 AM); entropy >7.5 in non-media file | Packers (UPX) raise entropy; compare with known-good build |
| **Relations** | What infrastructure does it touch? | Known-bad IPs in the VT graph; DGA-like domains (`xk8f92.xyz`) | Legit CDNs can host malware; check IPs in Shodan |
| **Behaviour** | What happens post-execution? | Critical registry key changes; process injection | Some admin tools edit the registry legitimately; correlate with endpoint logs |

Also note: **contained domains/IPs** (network infrastructure) and **contained files** (embedded/dropped payloads).

### MalwareBazaar cross-reference

| Feature | Analyst use |
|---|---|
| Sample upload (web/API) | Contribute samples, build the intel database |
| **Malware family tagging** | `#IcedID` tag + only 5/70 on VT → still treat as malicious |
| **YARA rule integration** | Copy submitted rules into EDR/SIEM for hunting |
| **Campaign attribution** | Tags like `#TA551` link the incident to a known actor |
| **Sample availability** | Download and re-detonate in your own sandbox (best practice) |

**Search syntax:** `sha256:<file_hash>` — in this room, TryDetectThis (`http://TryDetectThis.thm:8080`) already ingests both VT and MalwareBazaar data offline.

## 🧪 Task 4 — Sandbox Analysis

### Why detonate

| Goal | What it gives you |
|---|---|
| Confirm execution | If nothing happens, the alert may be a decoy |
| Extract runtime IOCs | Domains, mutexes, dropped payloads → feed hunts and detections |
| Map to ATT&CK | Most sandboxes auto-label behaviour with technique IDs |

**Static vs dynamic:** static properties (hashes, strings, sections) tell you **identity**; dynamic detonation tells you **impact**.

### Sandbox comparison

| Tool | Strength | Best for |
|---|---|---|
| **Hybrid Analysis (HA)** | Behaviour trees + clean MITRE ATT&CK heatmap | Fast executive summary (L1 triage) |
| **Joe Sandbox (JS)** | System calls, strings, memory dumps | Reverse engineers / detection engineers |

L1 role: use the **lookup** features on a known hash. L2+ handle full detonation and deep analysis.

### Sandboxing limitations

| Limitation | Detail |
|---|---|
| **Evasion techniques** | Environment awareness checks (is this a VM?); anti-debugging and unique hardware ID checks |
| **Limited execution time & coverage** | Analysis stops after 2–5 min → multi-stage and time-delayed payloads never fire |
| **Encrypted / obfuscated traffic** | SSL/TLS often undecryptable → HTTPS C2 with no payload visibility; DNS tunnelling hides data in queries |
| **Fileless & LotL malware** | PowerShell attacks and WMI persistence never touch disk, bypassing file-based sandboxing |

**Mitigation:** cross-reference multiple intel sources; never treat a clean sandbox run as proof of benign.

|---|---|
| HA tags | **BlackMoon, Discovery, windows-server-utility** |
| Verdict | Malicious · 85/100 · Windows 10 64-bit · analysis duration 120 s |
| Parent process | `bl0gger.exe` (PID 2148) |
| Child 1 | `regsvr32.exe` (PID 3012) — ActiveX component registration |

## 🧭 Triage workflow (condensed)

| Step | Action | Output |
|---|---|---|
| 1 | Validate evidence — confirm you have the exact binary | Correct file + real extension |
| 2 | Inspect path & filename heuristics | Suspicion level, indicator type |
| 3 | Generate SHA256 (isolated host) | Pivot key (lowercase) |
| 4 | Enrich on VirusTotal | Detection ratio, labels, properties, relations |
| 5 | Cross-reference MalwareBazaar | Family tags, YARA rules, campaign attribution |
| 6 | Review sandbox behaviour | Commands, process tree, dropped files, network IOCs |
| 7 | Map to ATT&CK and report | IOC list by type + proportionate recommendations |

## 🔑 Key Takeaways

| Takeaway | Detail |
|---|---|
| Validate before analysing | Confirm you have the exact binary and hash |
| Read paths and names first | Unusual locations, trusted-software directories, naming tricks flag items for deeper review |
| Hash early | Generate hashes to pivot into external and internal knowledge bases |
| Observe runtime behaviour | Confirm intent, extract network/persistence indicators, map to ATT&CK |
| Report proportionately | List indicators by type, summarise behaviour, recommend actions backed by evidence |
